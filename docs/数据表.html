已知的读取事实（实测）

  • 文件已全局按 _symbol 排序，且 min/max statistics 完好。单股票查一天只需碰 680 个 row group 里的 2 个（2.6 MB / 792 MB，字节 338×）。
  • date=YYYYMMDD.parquet 是普通文件名，不是 hive 分区目录——标准分区推断认不出，只能 glob + 字符串切片。
  • column_4（时间）是字符串，statistics 按字典序：rg0 的 min/max 是 ('100000040','95959440')，min > max ⇒ 时间窗谓词无法下推。
  • pre_buffer=True：单列全文件扫描 231.9 s → 5.3 s（43.8×）——这是盘被 V1 作业抢时测的。2026-09-02 作业停后无争用复测：pre_buffer=False 冷读同样只要 3.3 s，收益只在争用时出现；仍保持 pre_buffer=True（无争用不亏）。单股 row group 裁剪复测 68.7×（0.09 s vs 全天 7 列 6.0 s）。全天单字段读 13.6 s 里 IO 只占一半，其余是 dtype 还原的 CPU——已改为 strip 物化一次、去正则、present 集合先 unique。
  • pl.read_parquet(use_pyarrow=True) 实测 350 s，比现状慢 13 倍。pq.read_table 9.4 s，跑满盘带宽。

五 · 事件层

空

目前没有任何事件被定义——事件注册表为空。这是全项目最大的一项待定。定义落在注册表（纯逻辑核、进 CI），不落在本表的文字里；本表只记录候选种子与不变量。

事件层的作用：把 5,300 万行/天的逐笔数据坍缩成几万条反常观测，让日常研究彻底脱离 4 IOPS 的外置盘。预估 5–8 GB 常驻内置 SSD——这个数字是估算，尚未实测。

定义事件时必须守的一条

事件只回答「这是不是统计上反常」，绝不回答「这是不是庄」。

提取一次要扫 2.585 TB（约 15 小时），判断一旦写进去就被锁死在一个极难重跑的位置。所以记录统计量，不记录语义标签。语义判断留在因子层，那一层改起来是秒级的。

事件流的不变量（属于接口，因子的合成夹具与真实流都必须满足）

① 按 (标的, 时间) 有序。② 每个 (标的, 交易日) 至少一条日界事件——不含反常统计，只标记该标的该日结束；没有任何反常的安静日也让因子状态机前进一步，因子在日界事件上产出该 (标的, 日) 的值。③ 安静 ≠ 缺口：安静 = 有数据、无反常（有日界事件）；缺口 = 数据不存在（无日界事件，必带归因码，是下游纯核入口的必需参数）。

三类参数，各有唯一住所：切割规则所用的提取参数（分位点、窗长、最小持续时长）→ 事件注册表，进证据指纹，假设不得修改；判断阈值与因子参数 → 预注册；白名单字面量 0 / 1 / −1。事件流版本 = 注册表版本 + 提取参数集 + 数据清单摘要，每个假设必须声明。

V1 最大的信息回收空间：事件本身从未被持久化

window_factors.py 里每一行 (symbol, win) 就是一个 30 秒时刻，is_buildup / is_spoof_seq / is_spoof_sweep 是该时刻的布尔——但它们在内存里算完就被 count / sum / mean 掉了，只有聚合落库。window_state.py:16-17 注释明说「每天只保留 per-(symbol) 聚合（小），不留全窗口帧」。V1 恰恰把事件全部聚合掉之后才存，事件本身没有任何一份持久化。

A · Build-Up → Cancel → Sweep 三段式（产出 sweep10，庄板池的定义）

真正的链条：window_factors.py → window_state.py → conditional_scan_full.py:199。SZ-only，只取连续竞价，30 秒窗（WIN_MS=30000）。去重 unique(subset=[_symbol, OB_TIME], keep="first")——供应商在 09:30/13:00 每股各发两帧重复开盘帧，不去重会双计。

# 每快照（factor_primitives.py:29-47）
ob_valid = bid1>0 and ask1>0 and bid1<ask1
depth_ok = 20 个 OB_BID_SZ / OB_ASK_SZ 全非 null
bv = Σ OB_BID_SZ[1..10];  av = Σ OB_ASK_SZ[1..10]
imb = (bv−av)/(bv+av)   if ob_valid & depth_ok & (bv+av)>0  else null
mid = (bid1+ask1)/2     if ob_valid else null

# 每 30s 窗（window_factors.py:58-90）
uq   = mean(imb)                                    # 深度失衡
mpc  = (last(mid) − first(mid)) / 100               # 中间价漂移，单位 tick
hqa  = count(orders rows: ORDER_SIDE∈{B,S}, 连续竞价, .SZ)   # 报单【笔数】，不加权量
ac   = Σ TRADE_VOL where TRADE_CODE=='C'            # 撤单【股数】
# 窗口集合由快照帧定义；hqa/ac left-join，缺窗填 0

# 三相位判定（window_state.py:96-141）
hi_hqa     = hqa >= quantile(hqa, 0.90) over _symbol    # 本股当日窗口分布 p90
hi_ac      = ac  >= quantile(ac,  0.90) over _symbol
extreme_uq = |uq| > 0.5                                 # :99 硬编码字面量
分组 g = [_symbol, sess]，sess = am if win < 1560 else pm  # 不跨午休

BuildUp   = hi_hqa AND extreme_uq
cancel_n1 = hi_ac[+1] AND win[+1]==win+1               # 下一窗必须连续
cancel_n2 = hi_ac[+2] AND win[+2]==win+2
rev(x)    = sign(uq)≠sign(x) OR |x| < 0.5·|uq|          # 失衡翻转或腰斩
sweep(m)  = sign(m) == sign(uq)                        # 漂移与失衡【同号】
use_n1 = cancel_n1;  use_n2 = (¬cancel_n1) AND cancel_n2

is_spoof_seq   = BuildUp AND ((use_n1 ∧ rev(uq[+1])) ∨ (use_n2 ∧ rev(uq[+2])))
is_spoof_sweep = BuildUp AND ((use_n1 ∧ rev(uq[+1]) ∧ sweep(mpc[+1]))
                          ∨ (use_n2 ∧ rev(uq[+2]) ∧ sweep(mpc[+2])))

# 日级聚合（window_state.py:143-157）→ state.parquet
spoof_sweep_count = Σ is_spoof_sweep;  spoof_state = spoof_seq_count ≥ 1
默认剔除当日涨跌停股整行（FTB_KEEP_LOCKED=0）   ← F182 的伤口

# sweep10（conditional_scan_full.py:199）
sweep10 = spoof_sweep_count.rolling_sum(10).over("symbol")   # 按行不按日历
庄板池  = sweep10 ≥ 2                                          # :255
四个词的真实含义，与 README 的印象出入很大
  • Build-Up 不是挂单量阈值——是报单笔数 ≥ 本股当日 p90，且十档失衡 |uq| > 0.5。单个 30 秒窗，无持续时间要求，不区分档位。
  • Cancel 不是撤单比例——是撤单股数 ≥ p90，且失衡相对 Build-Up 窗反向或腰斩。必须在后 1 或 2 个连续窗内，不跨午休。
  • Sweep 不是扫单事件——没有吃穿档数、没有主动成交量阈值。仅仅是「中间价漂移与 Build-Up 窗的失衡同号」，一个方向一致性判据。
  • spoof_sweep_count 在 join 前 fill_null(0) ⇒ 涨跌停日在 sweep10 里等于 0，机械拉低。前 9 行 sweep10 = null 不进池。

C · 冰山单（iceberg_detect.py → ice.parquet）

输入 orders：.SZ + ORDER_SIDE∈{B,S} + 连续竞价 + ORDER_PRICE>0 + ORDER_VOL>0
REP_MIN=10（:58）同 (price, vol) 递交 ≥10 次 = 算法切片证据；MIN_ORDERS=200（:59）
grp = count over (symbol, side, ORDER_PRICE, ORDER_VOL);  rep = grp where cnt≥10
ice_buy_repeat_max   = max(cnt)                        fill_null(0)
ice_buy_repeat_share = Σ(cnt·vol) / Σ ORDER_VOL
ice_buy_nlevels      = 组的个数
ice_buy_unif         = max over ORDER_VOL of count / n_orders

已证伪清单 §C 记：REP_MIN=10 的检测器 96% 的票都触发——不够稀有的错代理；论文里「隐藏量」的定义从未实现。

D · 日级派生（accum_dist.py → ad.parquet）

输入 trades：.SZ + TRADE_CODE=='0' + 连续竞价 + price>0 + vol>0 + ASK_REF>0 + BID_REF>0
is_buy = TRADE_BID_REF > TRADE_ASK_REF        # :164 序号大 = 后到 = 主动方
成交量时钟：V = vol20 / 50，vol20 = daily vol 的 rolling_mean(20, min_samples=5).shift(1)   # PIT
跨桶成交逐段拆分，整数切点，硬校验 Σ拆分 == 原量（:264-265）
MIN_TRADES=200 · MIN_BARS=5 · 默认剔除涨跌停股

ref_net_ratio = Σ svol / Σ vol                            # :230
oi            = 2·Σ is_buy − n_trades                     # :231
amihud        = median_bars(|r| / (Vtau·close/10000))     # 分母换算成元
rv            = sqrt(Σ_bars r²)                           # :300 是开方后的
vpin          = Σ Vtau·|2Φ(dP/sdP)−1| / Σ Vtau            # BVC，只给幅度不给方向

wmsp.parquet（info_trade / net_q / noise_ac）不是 Kalman / VAR 分解，尽管引用了 Brogaard et al. (RFS 2022)——代码只在成交量时钟 bar 上算 Pearson 相关：info_trade = corr(r, q)²，noise_ac = −corr(r, r_lag)。它不做跨桶拆分、无 seq tie-break、完全没有锁盘门，与 accum_dist 切出的 bar 边界不同。从未 wired 进策略。

V1 自己总结的 8 个反复出现的否定模式

① 活跃度混淆（主导）② subsumption ③ lift ≠ 可交易 P&L ④ OOS 不复现 ⑤ 不够稀有 / 错代理 ⑥ 方向相反 = 派发 ⑦ 同步非提前（lead=0）⑧ 数据稀疏测不动。

该文件自陈：「被活跃度混淆」这个标签不可当作定义复用——操作含义是「净偏 ≈ 0、无方向」，任何复活都必须用涨/跌偏向 + 双段 P&L 重测。
