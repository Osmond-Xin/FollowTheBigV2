一 · 领域

庄家

在个股上进行人为操纵的资金方。本项目的全部价值主张建立在一个前提上：庄家的操纵行为会在最细的盘口数据里留下痕迹，而这些痕迹被日级聚合统计当作噪声丢弃。

吸筹 → 拉抬 → 派发

庄家操盘的三个阶段。本项目的目标是识别处于吸筹末期、即将进入拉抬的标的。识别派发（出场信号）不是本项目的目标。

跟庄识别

本项目的任务定义。不是普适量化选股，不是交易机器人。产物预期是一个信号稀少、需长期等待、靠右尾不对称获利的模型。

信号稀少是设计目标，不是缺陷。

Level-2 数据

交易所提供的细颗粒度行情，含十档快照 / 逐笔成交 / 逐笔委托三个流。本项目唯一的信息优势来源。

二 · 研究流程

假设Hypothesis

一个关于市场的、可被数据裁决的陈述。本项目统一使用「假设」，不使用「命题」。来源可以是论文、观察、或 V1 的历史工作。假设独立于任何一次验证的结果而存在。

分三个层级，层级不同，判据类型也根本不同：

层级问的是判据形态
因子假设单个因子是否携带信息经验置换检验
组合假设多个因子合起来是否更强多重检验校正 / 共线性 / 增量信息
策略假设一套完整的进出场与仓位规则是否赚钱路径依赖 / 滑点 / 资金约束下的分布

假设不是一张平表，是一个 DAG：策略假设的验证以其依赖的组合假设已确证为前提。

假设的必填声明（缺一不得验证）：样本宇宙 · 研究 episode · correction_family_id · 污染级别 · 所依赖的事件流版本。

不得使用 L1 / L2 / L3 指代这三个层级

V1 中 L2 已经表示 Level-2 行情数据（本项目数据源本身的名字），L1 表示日级因子确认层，L3 表示「可证伪的赚钱解释」，且 L0 比 L1 更靠近交易——编号方向与层级高低不对应。复用必然造成歧义。

预注册Pre-registration

在接触数据之前，把一个假设的判据完整写死：检验方法、阈值、样本区间、多重检验校正、判定规则。完成后判据不可修改；要改，只能作废并重新预注册。

预注册目录 append-only——CI 用 git diff 硬拒对已有预注册文件的任何修改，只允许新增（新增必须声明 supersedes 旧 id 并写理由）。判据的哈希在执行前固定并写入证据指纹——改判据不被禁止，而是被检测到。

预注册必须声明样本宇宙。

预注册防的是事故，不是过拟合

它锁不住：预处理流水线、因子构造的中间选择、样本宇宙的选取本身、交叉验证的切分、执行参数中那些被称作「技术细节」的东西——每一个都是策略。

已知规避路径：本地网格搜索找到最优参数 → 事后填进预注册 → 声明「接触数据前提出」→ 系统机械判定确证。这会让系统给过拟合颁发一张不可篡改的确定性收据，比没有系统更糟。

对策不在工具里，在 episode 预算与污染级别声明里。

研究 episode

多重检验校正的作用域单位 = 一个研究问题 + 一个因子空间 + 一个样本宇宙空间。

episode 开始时声明假设预算，用完即冻结。每个假设必须声明 correction_family_id；family 的新增、关闭、分裂必须留审计痕迹。

episode 账本 append-only，与预注册目录同一纪律；预算计数是纯函数，验证开始前先查，预算用尽即拒绝，没有加预算的入口——要继续，只能开新 episode 并留痕。

校正的作用域不能定义在「一次裁决包含多少假设」上

① 周一确证的假设，会因周二新增假设收紧阈值而被机械降级为推翻，导致下游级联断裂——研究员被迫在「停止提出新假设」与「接受历史结论被不可逆摧毁」之间二选一。

② 换测试窗口、换样本宇宙同样是多重检验，而工具完全看不见。

验证Validation

按预注册的判据，在 V2 的数据上执行检验，得到一个裁决。验证只在 V2 的数据上进行。V1 的数据与 V1 的结论都不是验证的输入。

盲验Blind validation

验证过程不得读取、不得引用 V1 对同一假设的历史结论。V1 只作为假设的灵感来源。

盲验不可能被机械保证，不得宣称物理隔离

三方异构红队一致判定：

  • V1 的失败教训一旦被写下来，就已经成为每个 agent 的先验——写出的代码天然避开 V1 的失败模式，这不是盲验在工作，是教训已被吸收成「什么是显然正确的」。不满足「不知道有 V1 存在」的盲验不是盲验，是延迟读取。
  • Python 里进程污染标记一行即可消除，子进程完全不可见；真正的污染是认知污染经 prompt 在 agent 之间传递。把认知层防作弊寄托于 IO 标志位是安全错觉。
  • 字段命名、样本区间、因子选择本身就泄露 V1 偏好。
因此盲验降级为两件可执行的事

对照——每个 sprint 引入一个不知道项目历史的异构 agent（不同模型、不同上下文）独立出裁决；结果不与项目内裁决合并，单独报告一致性差异。

声明——每个假设必须声明其污染级别。记录污染，而不是假装消除污染。

污染级别Contamination level

一个假设的来源在多大程度上已经知道 V1 对同一问题的结论。假设的必填声明之一；记录，不消除。

分级标度见第六节【待定】；标度未定前只允许自由文本声明，不得用于任何机械判定。

对照裁决Contrast verdict

由不知道项目历史的异构 agent 对同一预注册独立产出的裁决。不与项目内裁决合并，存 .lineage/<假设 id>/contrast.json，只报告与 receipt.json 的一致性差异。

裁决Verdict

一次验证的输出，由工具机械计算得出（预注册判据 + 数据），三态之一：

状态含义
确证判据满足
推翻判据明确不满足，且证据足以支持这个否定
无定论尚不能回答。必须带附加标签：abandoned_for_cost / underpowered_but_negative / not_worth_more_data

「无定论」与「推翻」是不同的信息，不得合并。V1 把二者混为一谈是已知的失效模式。裁决不可解读、不可争辩——预注册的全部意义就在于此。

判定用经验置换检验，不用参数化功效

本项目目标就是「信号稀少、靠右尾不对称获利」：一年 5–10 次开仓 ⇒ 1122 天总样本 N ≤ 40、偏度 > 3。参数化功效几乎永远落在 0.1–0.3，有效与无效策略会被一律判成「无定论」，三态裁决沦为只输出「数据不足」的摆件。

做法：在保持真实波动率与流动性约束下，把信号在时间轴上随机打散 1000 次算经验 p 值；实测效应落在置换分布前 1% 且绝对样本 ≥15 即确证；证据不足时输出置换分布重叠度，不只给一个状态码。

「无定论」必须带标签的原因是反向的：否则它会被滥用成永不失败，队列堆满无定论尸体。

解读Interpretation

对一次裁决「意味着什么、值不值得继续、下一个假设是什么」的判断。

必须由未参与该实现的异构 agent 产出，以避免设计者对自己的结果做有偏解读。解读明确标注为非权威，与裁决分开存放：存 .lineage/<假设 id>/interpretation.json，与 receipt.json 并列。裁决进证据指纹，解读不进。

证据指纹

一次裁决所依赖的全部输入的可校验摘要。裁决离开证据指纹即无效。

绑定范围：源码树 + 依赖 lock + 数据清单 + 缺陷账本 + 参数集 + runner 镜像摘要 + 命令规格。

只绑 tree_sha("src") 太窄——改 lockfile、账本、夹具都会改变结果。

证据包Evidence Bundle

裁决结论的唯一落点：内容寻址，存 .lineage/<假设 id>/receipt.json。代码里只保留稳定的假设 id 或预注册哈希；CI 校验「当前代码声明的哈希是否存在对应证据包」。

结论绝不写回代码注释

代码保持只读，严禁运行时反向修改源码。写回会立刻改变 tree_sha，与收据机制死锁（收据里的 sha 是执行前的 ⇒ CI 必然硬拒）。

此外还会造成：合并冲突 · 无意义 diff 淹没 review · rerun 后源码变脏 · cherry-pick 困难 · 同一假设的多区间/多 runner/多版本结果塞不下 · 格式化即指纹失配。

三 · 观测与因子

事件Event

从原始层抽取的一条反常观测记录：假墙撤单、激进扫盘、冰山补单、对倒等。字段描述「发生了什么反常」——分位数、持续时长、吃穿档数、撤单前离最优价的距离等。

事件不含判断

事件提取器绝不回答「这是不是庄」，只回答「这是不是统计上反常」。

理由：事件提取是一次扫过 2.585 TB 的重活（约 15 小时），判断一旦写进去就被锁死在一个极难重跑的位置。判断要留在因子层，那一层改起来是秒级的。

事件流的不变量（属于接口，调用者必须知道）
  • 按 (标的, 时间) 有序；
  • 每个 (标的, 交易日) 至少一条日界事件——没有任何反常的安静日也让因子状态机前进一步；
  • 「安静」与「缺口」是两种信息：安静 = 有数据、无反常；缺口 = 数据不存在。不得合并。
日界事件Day-boundary event

事件流中标记某 (标的, 交易日) 结束的记录。不含反常统计。是因子输出该 (标的, 日) 值的触发点，也是跨日累积与衰减的时钟。

缺口Gap

某 (标的, 交易日, stream) 在派生层没有数据的事实，必须携带归因码（缺陷账本条目、未摄取、停牌等）。缺口是下游纯逻辑核入口的必需参数；「查不到 = 没有」被禁止。缺口不是事件，不进事件流。

事件注册表Event registry

全部事件定义的唯一来源：每种事件的字段、统计量定义、切割规则（把逐笔行坍缩为事件的判据）、版本号。属纯逻辑核，进 CI。事件提取与因子都只从它取定义，不得各自持有一份。

「事件的具体定义」这项待定的落点就是这张表，不是数据表里的文字。

提取参数Extraction parameter

事件注册表中切割规则所用的参数（分位点、窗长、最小持续时长等）。与预注册参数不同的第三类参数：不来自预注册（事件提取在任何预注册之前运行）；假设不得修改它；每个假设必须声明所依赖的事件流版本；进证据指纹。

三类参数，各有唯一住所：提取参数 → 事件注册表 · 判断阈值与因子参数 → 预注册 · 白名单字面量 0 / 1 / −1。

事件流版本Event stream version

事件注册表版本 + 提取参数集 + 原始层数据清单的内容寻址摘要。同一版本 ⇒ 同一事件流。预注册必须声明它；证据指纹绑定它。

因子Factor

由事件流计算得出的、可对（标的, 交易日）给出数值的量。因子含判断——它是「庄」这个语义的载体。

因子以状态机形式表达：

step(状态, 事件) -> (新状态, 值?)

这个形状同时解决两件事：跨日累积不需要回看原始数据（O(30T) 降回 O(T)）；且它仍是纯函数，留在 CI 硬门禁内。

样本宇宙Universe

一个假设所覆盖的标的集合与时间区间。样本宇宙属于预注册，不是数据管道的参数。

任何产物不得在未声明样本宇宙前删除行；参与样本池定义或标签定义的产物一律不得过滤行。（纯因子抽取可以且应当降维——事件提取本身就是降维。）

这条规则的伤口来源

V1 的 builder 在生成 sweep10 时删掉涨跌停日，而 sweep10 ≥ 2 就是庄板池的定义 ⇒ 池的定义本身带盲区，而要找的正是「准备拉升的庄」。

把宇宙定义关进 append-only 的预注册，这类事故在结构上不可能。

唯一的显式例外：原始层摄取只存主板前缀（000/001/002/003/600/601/603/605），与 V1 一致（Q15；2026-09-02 用户裁定）。被筛掉的标的按前缀计数进摄取收据。除此之外原始层不删任何行。

停牌心跳不是残缺归档：归档里每天约有 6 只主板标的的目录只有行情 CSV（每分钟一条、价格与十档全 0 的心跳快照），没有委托与成交（2026-09-02 实测 20220104 / 20220105，与 V1 manifest 的 xinqing 3134 / orders 3128 吻合）。摄取把它登记为合法形状：三 stream 分别计标的，这些标的记入收据 quote_only_symbols；只缺委托、成交之一，或缺行情，仍是残缺归档硬失败。「停牌」的判定属于日级参考层，摄取不猜。

业内叫「特征」的东西，在本项目一律叫因子。业内「特征 vs 因子」的区分（中间计算列 vs 候选 alpha）说的是意图，而意图已由「有没有为它预注册一个因子假设」表达。多一个词只多一处漂移。

本表曾在「因子假设」的定义里误用「特征」，2026-09-01 由用户当场纠正。词汇纪律的执行方式见第八节——不是禁用词，没有豁免名单。

四 · 数据

具体存了什么、每列怎么算 → 见数据表。这里只定义词。

原始层

交易所原始数据的副本。只读，永不修改。是全项目唯一的事实基础。

不得声称「逐行无损」——那是伪承诺

2023-01 → 2026-07 的原始 7z 已永久删除，对约 77% 的交易日既无法逐字节 round-trip，也无法与源 CSV 做真行数比对。

可验证性必须分档标注：verified_byte_exact 仅对幸存 7z 覆盖的约 23%（2022 全年 + 202608）成立；其余只能验证 preserve 层自洽。

任何裁决都应能回答「它依赖的天里有多少是真验过的」。

两类存储

接口不同，不是一个模块的两个后端——不变量相反、访问模式相反、性能特征差三个数量级。

原始层存储事件与因子存储
不变量只读，永不修改永远可删可重算
介质外置 exFAT 机械盘，4 IOPS内置 NVMe
访问模式顺序扫描，秒到分钟随机、反复，毫秒
附带缺陷账本、可验证性标签血缘、内容寻址
派生层

由原始层经确定性计算得到的一切数据。派生层永远可以被删除并重算；任何不可重算的派生数据都是缺陷。

日级参考层Daily reference layer

派生层的一个数据产品：每个 (标的, 交易日) 的日级事实——开高低收、涨跌停状态、停牌、成交量与成交额、样本宇宙成员资格（主板前缀、ST、上市天数）等 PIT 事实。

由事件提取的同一趟扫描顺带产出，不另起一趟。可重算、带血缘、常驻内置盘。是执行模拟、经验置换检验（保持真实波动率与流动性约束）、样本宇宙声明的输入。涨跌停与停牌在此是标记列，不是删行依据。

血缘Lineage

一份派生数据与它的全部输入（源数据 + 生成代码 + 参数）之间的可校验对应关系。无血缘的派生数据视同不存在。

事实单源

任何一个事实在系统中只有一处定义。

判据：一个事实如果能被代码执行出来，就不得被文档声明。

此原则继承自 V1，是 V1 唯一值得继承的治理原则。

五 · 代码结构

模块 / 接口 / 实现 / 深度 / 缝 / 适配器 —— 采用 Ousterhout + Feathers 的定义，不另立术语。特别注意：接口指调用者必须知道的一切，不只是类型签名，还包括不变量、顺序约束、错误模式、必需配置、性能特征。

纯逻辑核

不触碰 IO 的代码。可确定性测试，快。

质量标准：抽象复用、可解释性。受 CI 硬门禁约束。

IO 层

读写数据的代码。慢，依赖外部存储。逻辑应当简单，主要职责是异常处理。

质量标准：速度、异常覆盖。受本地门禁（契约测试、金标准回归、血缘校验）约束。

二者必须分属不同模块。这不是风格偏好：

门禁必须不可绕过 ⇒ 门禁要跑在 CI ⇒ CI 跑不了 TB 级数据 ⇒ 能进 CI 硬门禁的只有不碰数据的那部分。

任何既碰数据又含判断的代码，两套门禁都进不去，必须拆开。

六 · 待定

以下条目不得在代码中使用。

01

假设作为形式对象的确切结构——验证体系吃什么、吐什么。

02

存储引擎、格式与压缩方案。方向已定：先改读取代码（零迁移拿到 row group 裁剪 68.7×；pre_buffer 只在争用时救命，2026-09-02 复测）；重编码若做，必须含 DELTA_BINARY_PACKED——只改 dtype 不加 delta 会让文件变大 7–25%。

03

事件的具体定义——事件注册表目前是空的。这是最大的一项待定。候选种子见数据表第五节。

04

三个必须实测的数字：事件流实际体积 / 一次全量提取实际耗时 / 「宽而中性」能宽到什么程度。该次扫描须同时产出日级参考层，否则要补第二趟。

05

八 · 易混淆词表（词汇门禁的数据源）

没有禁用词，没有豁免名单。2026-09-01 用户裁定：硬拒加豁免会让人忙于豁免而不是语义。门禁检查的是「同一个概念有没有被别的说法指代」以及「有没有引入与已有定义重叠或冲突的新定义」。

执行分两级（tools/check_vocab.py）：① grep 右列找候选，只找不裁决；② 便宜的模型逐条判定语义——候选处若在指代左列的概念即冲突；数学与固定搭配（特征值、性能特征）、引用或描述 V1 与第三方原文、讨论本表自身、泛指他义，皆合法。另对改动的文件检查是否新定义了与左列重叠的概念。任一冲突或判定不可用即门禁失败。
