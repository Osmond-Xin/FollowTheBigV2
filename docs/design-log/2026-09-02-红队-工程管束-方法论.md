## 致命

**F1. append-only 纪律没接住 supersedes，R6 把预注册与账本并入同一门禁却没带过 supersedes 规则**
证据：R3「账本 append-only：已存在条目的 id / code / days 只能增不能删改（与预注册同一纪律，`git diff` 门禁）」；R6「预注册目录与账本共用 append-only 门禁，现在就建」。
攻击路径：研究员发现某形状登记其实是误判（例如 `empty_file` 是 `stream_symbol_mismatch` 的子集），用 supersedes 替换为新条目 + 理由；`git diff` 看不出异常，与 R3 门禁正交绕过。预注册侧同一路径：用"措辞更精确"的 supersede 把不显著的旧假设静默替换。这正是 CONTEXT.md §二预注册显式点名的失败模式。
修正：明文继承 CONTEXT.md 的 supersedes 规则——supersedes 必须显式记录被替换条目 id、替换理由、替换时间；supersedes 链本身也 append-only；CI 校验"曾经存在但现在找不到"的条目必须有显式 supersede 出处（`git log -S` 即可回溯）。

**F2. 活文档被定位为"唯一裁决"——STATE.md 又是模型起草——裁决/解读/事实的边界被抹平**
证据：R4「活文档（三份 HTML + CONTEXT.md + docs/STATE.md，唯一裁决）」；R4「用 MiniMax 读新日志，产出 STATE.md 草案与归档移动……模型只起草，不裁决」。
攻击路径：CONTEXT.md §二 裁决是工具的机械输出（三态），解读是异构 agent 产出、非权威、单独存放。把"现在在哪/卡在哪/下一步"叫作"唯一裁决"，等于把解读（"卡在哪"）的权威性套到事实层；又用模型起草 STATE.md，模型会平滑掉 推翻 vs 无定论、抹掉无定论 4 个附加标签（abandoned_for_cost / underpowered_but_negative / not_worth_more_data）、把"待裁决"写成"在审"。「模型只起草，不裁决」是承诺，不是门禁——人合并时倾向通过"读起来通顺"的版本，无人反向核对每条 STATE.md 陈述的源头日志。
修正：把"唯一裁决"这词从 STATE.md/活文档移除（"唯一导航"可以，"唯一裁决"不行）；STATE.md 改为模板化结构（每条都是固定 schema 的列表项），字段直接来自 `.lineage/<id>/{receipt,contrast,interpretation}.json` 与 ledger 条目，禁止模型改写/合并/推断；模型只做"挑出本周新条目并按 schema 填进去"。

**F3. `empty_file` 还是待裁决状态就已经写进 ledger**
证据：R3「今天四个形状入账本：`quote_only`……`empty_file`（待裁决：推荐登记进收据）」。
攻击路径：CONTEXT.md §二、§三 都明确"待定"项不得作为数据或门禁依据。`empty_file` 一旦入 ledger，下游 DefectCode 枚举就可以"自然延伸"把它写进代码；CI 门禁「账本 code 集合 ⊆ 代码枚举」立刻把它锁成 enum 一员。届时再 supersede 拆，已经污染了若干证据指纹。这是 R3 的 supersedes 缺口（F1）的具体引爆点。
修正：ledger 拆 `formal.toml` 与 `pending.toml`；待裁决项只能入 pending；入 formal 必须声明 裁决 id（即便裁决是"暂作 X 处理，待 N 复审"），并落到 R1–R6 的预注册纪律下。

**F4. 工具可先于预注册存在，R6 的禁令没覆盖到今天的工具化动作**

**F5. R1 `audit_preserve.py` 把 V1 preserve 当 V2 校准基准——V1 偏见通过字节比对被反向固化**
证据：R1「tools/audit_preserve.py：V2 产物 vs V1 preserve 逐 row group 比对 → JSON」；CONTEXT.md §四「2023-01 → 2026-07 的原始 7z 已永久删除，对约 77% 的交易日既无法逐字节 round-trip，也无法与源 CSV 做真行数比对」。

**S1. 整套方案没有 contrast verdict 的落点**
证据：R1–R6 通篇未提"对照裁决"；CONTEXT.md §二 明确「存 `.lineage/<假设 id>/contrast.json`，只报告与 receipt.json 的一致性差异，不合并」。

**S3. 污染级别 (contamination level) 在整个文档/账本系统中无落点**

攻击路径：污染级别若不落到 ledger 条目/预注册文件/工具 run 元数据，"记录污染"就只是承诺；事后想审"这条裁决的判据有没有被 V1 结论污染"无处可查。
修正：ledger 每条、预注册每份、工具每次 run 的元数据都加 `contamination_level` 字段；标度未定前先放自由文本。

**S4. 证据指纹的"绑定范围"未与 R1–R6 的工程产物对齐**
证据：CONTEXT.md §二 证据指纹绑定"源码树 + 依赖 lock + 数据清单 + 缺陷账本 + 参数集 + runner 镜像摘要 + 命令规格"；R3 ledger 入版本控制但未声明 hash；R1 tools/README 不记录参数集；R4 STATE.md 不写命令规格。
攻击路径：研究员把某次裁决的"绑定范围"凑不齐——ledger hash 没记、工具参数没记、runner 镜像没记——证据指纹降级为 `tree_sha("src")`，CONTEXT.md §二 已警告这是过窄的伪绑定。
修正：R3 ledger、R1 tools/README、R4 STATE.md 各加"绑定锚点"字段（事件流版本、参数集 hash、runner 镜像摘要、命令规格），所有锚点进 evidence fingerprint；锚点缺失即 verdict 无效。

**S5. 事件流版本 (event stream version) 无承载点，事件注册表 R1–R6 全程未提**
证据：CONTEXT.md §三「事件注册表是全部事件定义的唯一来源」「预注册必须声明它；证据指纹绑定它」；R1–R6 无事件注册表与事件流版本字段。
攻击路径：预注册要声明"我依赖哪个版本的事件流"，但事件流版本如何从事件注册表 → 提取参数 → 原始层清单 hash 链上拼出来，本方案没说；若没这条链路，预注册就声明了一个没有可校验来源的版本号。
修正：R3 ledger 的"形状"条目须显式绑定到"事件流版本 id"；事件流版本由（事件注册表 hash + 提取参数集 hash + 原始层清单 hash）内容寻址；新增事件定义时事件流版本自动 bump；R1 `tools/scan_shapes.py` 必须在产出中给出事件流版本 hash。

**S6. 经验置换检验的执行器判据形态未落进 R6**

攻击路径：研究员实现执行器时若走参数化 t-test，N≤40、偏度>3 的场景被一律判成无定论——CONTEXT.md 已点出这是 V1 失效模式；R6 不锁这个形状，门户大开。
修正：R6 增补"执行器 v1 必须实现经验置换检验（≥1000 次、时间轴随机打散、保持波动率与流动性约束）"；CI 跑一次金标准回归（已知数据集上输出已知 p 值）。

## 建议

**s1.** R4 `design-log 顶层文件数 ≤ 30 即红`——文件数不是健康指标；某次关键调查天然跨 30 文件。建议改"超过 30 时必须归档的是已落地项，未落地的不计入"。

**s2.** R4 `docs/ 总词数 ≤ 5 万即红`——词数也不是；50k 字维护良好 > 5k 字过时。建议删掉这条或换成"死链数 ≤ N"。

**s3.** R4 24 小时落地——落地 ≠ 正确；事实被错误归档等于错事两次发生。建议加"对账（self-check）"步骤：落地前对照 ledger / 预注册 / 代码的最新 hash 校验一遍。

**s4.** R2 `CI 重新生成后与仓库 HTML 逐字节 diff，非空即红`——若生成器有 bug，错 HTML 被锁死。建议加语义抽样（关键区块做属性级断言，如"词汇表行数 == CONTEXT.md 词条数"）。

**s5.** R5 `单文件 > 400 行由 crapkit ratchet 拦`——因子状态机可能天然超 400 行（CONTEXT.md §三 因子是状态机）。建议对状态机文件给豁免，但要求"单状态机一文件"且 ratchet 在状态机字段上做（如"单 step 函数 ≤ 50 行"）。

**s6.** R1 scratchpad 探针位置没说清——若在仓库树内，存在被无意 promote 的风险。建议明确放在仓库外（`~/.scratchpad` 或独立 `git worktree`），不入 `git ls-files`。

**s7.** R6 没显式禁止"先写代码再写预注册"——F4 已致命化，此处留作流程提醒：R6 增补一条"先 `.preregistration/` 后 `src/`"的拓扑序门禁。

**s8.** 整套方案没提 gap (缺口) 在派生层的传播——日级参考层里 gap 是否被记入血缘、是否被因子状态机消费、是否影响样本宇宙成员资格判断。建议在 R3 后单独立一条 R3.5「gap 传播规则」。

**s9.** R5 `types.py 杂物箱按所属概念归位`——"所属概念"未定义；建议删除或引用 CONTEXT.md §四「事实单源」原则（一个概念只一处定义）。

**s10.** R3 `quote_only (structural, none)` 的 action = `none` 不清楚下游是否保留这些 (标的, 日)——若保留，行为正确；若默认丢弃，等于在摄取层静默缩样本宇宙。建议 R3 明确 `none` = "保留并打标，下游由样本宇宙消费"。
