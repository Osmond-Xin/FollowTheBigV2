# 红队原文 · 对象：红队工具链自身（tools/redteam, 建仓提交后的工作区）· 攻击面：方法论

> 归档过程文档。fail-open、REDTEAM_ONLY 可清空、crapkit 失败被吞、文件名拆分、输出目录串扰、manifest 缺失均已按此修正；Lens×Runner 矩阵解耦与对 LLM 评审做多重检验校正未采纳。

总判：本次提交只搭起研究纪律的脚手架，但纪律本身（预注册、样本宇宙、证据指纹、对照裁决、污染级别）一件都没落到代码——门禁清单里看不到它们，CI 也跑不了它们；连禁用词门禁本身都红着。距"可下第一个假设"还差一截研究纪律的执行机制。

---

【致命】

**F1: 预注册目录与 CI 硬拒机制不存在**
- 证据：CONTEXT.md「预注册目录 append-only——CI 用 `git diff` 硬拒对已有预注册文件的任何修改，只允许新增」+「判据的哈希在执行前被固定并写入证据指纹」；README + `.claude/settings.json` + `tools/redteam/redteam.sh` 全无预注册目录、无 hash 钩子。
- 攻击路径：第一个假设来时，研究员发现没有落点 ⇒ 写在 `docs/` 或临时笔记 ⇒ 「append-only」沦为口头承诺 ⇒ V1 的过拟合规避路径（先看数据后写判据）直接打开。
- 修正：建 `pre-registrations/` 与 `episodes/` 两目录；文件名必须含 `sha256(criterion)`；CI 加 `git diff --diff-filter=M pre-registrations/` 必须为空（仅允许新增）；新预注册必须 `supersedes` 旧 id 并写理由。

**F2: 样本宇宙未在 append-only 预注册中固定**
- 证据：CONTEXT.md 「样本宇宙属于预注册，不是数据管道的参数」+「任何产物不得在未声明样本宇宙前删除行」+「池的定义本身带盲区」；README 仅口头说沿用主板 `000/001/002/003/600/601/603/605`。
- 攻击路径：日级参考层生成时先于任何预注册过滤行（停牌、上市天数、ST、涨跌停）⇒「庄板池」之类的定义在数据层先定 ⇒ 等同于在策略层定 ⇒ 假设的真实样本宇宙被悄悄偷换。
- 修正：在 `pre-registrations/00-universe.md` 固化主板 PIT 声明（含 ST 判定口径、上市天数门槛、停牌日处理、涨跌停状态列为标记不删行）；filter 函数接口只接受「预注册哈希」作为参数。

【严重】

**S1: 盲验降级承诺的「对照裁决 + 污染级别」机制未实现**
- 证据：CONTEXT.md 「盲验降级为两件可执行的事：对照 … 声明污染级别」+「假设的必填声明」含污染级别；diff 中 `tools/redteam/redteam.sh` 只处理 `design`/`review` 两种模式，没有 `hypothesis` 模式；`.claude/skills/redteam/SKILL.md` 同理。
- 攻击路径：第一次验证时无对照工具 ⇒ 研究员跳步直接写 `receipt.json`，事后声称"对照过"但对照未发生；污染级别必填项没人收集 ⇒ 必填沦为"可不填"。
- 修正：扩 `redteam.sh` 加 `hypothesis` 子命令（输入：预注册 + 数据子集；输出：`.lineage/<id>/contrast.json`）；`.claude/skills/redteam/SKILL.md` 补假设模式；预注册模板增加 `contamination_level` 必填字段（分级标度未定前用自由文本，但必须非空）。

**S2: 禁用词门禁当前红 5 处，词汇纪律执行基础动摇**
- 证据：README 「**禁用词门禁当前红**：命中 5 处（V1 原文引用 + 词汇表渲染物），待裁决改文还是改豁免」；CONTEXT.md 「词汇纪律靠机器，不靠自觉」+ 给出可机械判定命令。
- 攻击路径：CI 整体已红 ⇒ 后续 commit 门禁形同虚设（"反正已经红了"）⇒ 或有人把整条 grep 加 `--exclude=*` 废掉 ⇒ 「事件不含判断」这条规则在词法层就失守。
- 修正：在 `tools/gate.sh` 中把豁免白名单明确化（`docs/design-log/` 全目录 + `docs/词汇表.html` 渲染产物 + 复合词「性能特征」），README 同步说明范围；本周内必须改到绿，否则"门禁"二字是空话。

**S3: 证据指纹 7 类绑定输入没有任何采集入口**
- 证据：CONTEXT.md 「绑定范围：源码树 + 依赖 lock + 数据清单 + 缺陷账本 + 参数集 + runner 镜像摘要 + 命令规格」；diff 中无 `receipt.py`、无缺陷账本结构、无数据清单机制。
- 攻击路径：第一次裁决时，研究员手写 `receipt.json`，漏绑 lockfile/参数集 ⇒ 后续 lockfile 更新或参数微调后 receipt 仍判"通过"⇒ 结论失效但签名有效。
- 修正：建 `tools/receipt.py`，固化 7 类输入采集（`uv.lock` sha256、缺陷账本路径、`pre-registrations/<id>.json` sha、参数集 JSON、runner 镜像如 `minimax-cn-coding-plan/MiniMax-M3`、命令规格如 `mmx text chat --messages-file ...` 的字面哈希）；CI 校验 receipt 的 `inputs` 字段非空且每项 hash 可重算。

**S4: 事件流版本机制缺位**
- 证据：CONTEXT.md 「预注册必须声明所依赖的事件流版本」+「同一版本 ⇒ 同一事件流」；diff 中无事件注册表、无版本号、无内容寻址。
- 攻击路径：研究员写预注册时事件注册表还是空的（CONTEXT.md 自承「最大的一项待定」）⇒ 他要么跳过这一字段（必填变可选）⇒ 要么手填一个虚假版本号 ⇒ 多重检验的「family」边界立刻模糊。
- 修正：建空事件注册表 `events/registry.json` 带版本号字段（schema 已定、数据为空），CI 校验预注册的 `event_stream_version` 必须存在于该文件。

【建议】

**W1: 「宽而中性」的窗宽必须在跑 20 个交易日之前固定**
- 证据：README 卡点第三项；CONTEXT.md 「本地网格搜索找到最优参数 → 事后填进预注册」是已知规避路径。
- 攻击路径：研究员本能调到「看起来最舒服」的窗宽再写预注册 ⇒ 同样的 V1 失败模式又来一遍。
- 修正：在 `pre-registrations/00-experimental-calibration.md` 先固定窗宽候选集合 [N1, N2, N3, N4] + 选用规则（纯函数），之后才允许跑数据。

**W2: 三方红队的「方法论」面恒为 MiniMax-M3**
- 证据：`tools/redteam/redteam.sh` 中 `lens_of()` 把 `mmx|opencode` 都映到「方法论」+ 二者二选一；SKILL.md 「三方独立命中的要害最可信」。
- 攻击路径：实际跑出来永远是「方法论 MiniMax-M3 · 架构 Gemini · 工程 OpenAI」，三方中方法论只有一家 ⇒ 「三方独立」实际上是「两方独立 + 一方同源」。SKILL.md 描述与执行结构不符。
- 修正：要么把 SKILL.md 改为「二方红队 · 两面独立」；要么给方法论面引入第三个异构模型（如 Claude / Qwen）替换 mmx，让三方真正异构。

**W3: crapkit ratchet baseline 在零业务代码时即冻结**
- 证据：`crapkit-ratchet.tsv` 仅有 header + 注释；`crapkit.toml` target=30；`coverage_optional` 给 io/tools。
- 攻击路径：baseline 为 0 ⇒ 任何 crap 都不算变差 ⇒ 第一批业务代码无论多烂 ratchet 都不会拦 ⇒ CRAP 从「事前约束」沦为「事后统计」。
- 修正：ratchet 在 baseline 至少 5 个非零条目后才激活；冻结 baseline 前必须先有 ≥N 行通过 coverage 的核心代码。

**W4: 「无定论」附加标签无强制入口**
- 证据：CONTEXT.md 「`abandoned_for_cost` / `underpowered_but_negative` / `not_worth_more_data`」三标签；diff 中无裁决生成器。
- 攻击路径：研究人员拿到「无定论」时倾向写"证据不足"四个字完事 ⇒ 队列堆满无定论尸体（V1 已知失效模式）。
- 修正：裁决生成器（`tools/receipt.py` 一并）的 schema 中"无定论"必须枚举三标签之一；缺 label 直接拒绝写 receipt。
