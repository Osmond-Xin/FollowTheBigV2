## 【致命】

### 1. 「10–30 条/(标的·日)」是未经预注册的假设，却被当成机械门禁的验收基线
- **证据**：`seeds.py:9` 明文「四条的 density 全是 None」；`types.py:243-251` `require_density()` 抛错信息「没在真实数据上测过密度」；对象简报第 36 行「目标密度 5300 万行/天坍缩成几万条/天，即约 10–30 条 / (标的·日)」。
- **攻击路径**：目标密度是「注册表的密度门禁拒收什么」这件事的判据本身——但它写在一句项目背景里，不在任何 hypothesis 的判据位。逻辑链是：先在样本日上跑一遍四条 → 量到 X → 若 X 落在 10–30 之间则接受，否则改设计。**问题**：① 区间 10–30 是从哪来的？ ② 落在区间外时改设计是「校准」还是「重判」？ ③ 测量本身的样本日、样本宇宙、episode 都没有声明。任何人只要在样本日上跑出 X∈[10,30]、写一段 `density=...`、门禁就绿。这是用户已经警告过的「把结构问题降级成申报字段」的同构复发——只是申报字段从字符串变成了浮点数。
- **修正**：把「目标密度 10–30 条/(标的·日)」本身写成一条预注册的因子假设（H-density）——它的判据是经验置换检验（参见 CONTEXT.md「裁决」），预注册的判据形态应包括：样本宇宙的板块分布、样本日的选取规则、判定的「高于目标两个数量级以上即拒」门限、与「不显著不意味无定论而是采集更多日」的退出条件。H-density 必须先于四条事件提取器进入预注册目录。

### 2. `Relation.invariant` 是纯字符串门禁，方法论上等于「我不知道这段不变量在判什么」
- **证据**：`types.py:166-173` `Relation.invariant` 仅做 `if not self.invariant: raise`；对象简报 108 行明确「机器只查非空」。这与上一版被拆掉的「查 docstring 里有没有某句话」同构——门禁可绕过性已被审计承认，但还没修。
- **攻击路径**：研究员 A 写 `invariant="委托与撤单在同一档位"`，研究员 B 写 `invariant="委托后撤单"，这二者在字面上都满足「非空」，门禁放行，但前者其实把「成交耗尽时这档位仍活着」这种关键约束漏掉了。下游的契约测试只能查「invariant 非空」，看不到 invariant 与实际切割代码的关系。**这等于把「跨行结构关系」这条核心防线的判据权交给作者命名**——契约名（"建墙的本方委托"）会自我合理化一切错误写法。
- **修正**：方法论层的最低要求是把 invariant 升级为**可被代码机械断言的谓词**——可以是 dataclass 化的约束列表（如 `tuple[Invariant, ...]` 其中 `Invariant` 是带枚举类型标签的断言），或者一段可执行的 polars expression（结构化查询串而非自由文本）。即便改不动这一版，也必须把 invariant 写成**单一的字面量枚举**（`Invariant.NO_TRADES_IN_LIFE` / `Invariant.REFILL_AFTER_FILL` 等），每条枚举对应一条**可单测**的 polars 表达式，注册表只挂枚举名、不挂自由文本——这样至少能把「这条 invariant 实际能不能跑」降到单测层。

### 3. 四条条目的 `contamination=KNOWS_VERDICT` 加起来，等于盲验物理破产
- **证据**：`seeds.py:68 / 112 / 149 / 198` 全部 `Contamination.KNOWS_VERDICT`；对象简报已声明「污染级别是参考值不是判据」（CONTEXT.md「污染级别」条）。本批事件种子的来源按上下文均来自 V1 失效模式审计（`v1_audit` 字段已写明：V1 §F / §C / §D / accum_dist），即全部命中「知道 V1 结论」一档。
- **攻击路径**：CONTEXT 第二节明文「盲验不可能被机械保证，不得宣称物理隔离」，并把盲验降级为「对照裁决 + 污染级别声明」两条可执行的事。**本批条目没有任何一条安排了对照裁决**：四条种子由同一人在同一上下文内写完，未引入异构 agent 出独立裁决。**这不是个体失败，是流程未装**：架构设计里就没有「每个新条目触发对照裁决」这一步。后果是：四条结构隐含地继承了 V1 对「什么结构有意义」的判断——例如「补单必须在成交之后」（冰山 v1 §C 的核心结论）很可能不是来自数据，而是来自 V1 失败后的修正方向。一旦这四条进入生产，下游因子层与裁决层的污染是结构性的、不可逆的（事件流版本绑定进了证据指纹）。
- **修正**：在 `EventSpec` 接口或事件流注册规范里**强制绑定** `contrast_verdict_ref: str | None`，每条条目进预注册前必须至少有 1 份对照裁决（独立 agent / 独立上下文 / 独立判据）。`contrast_verdict_ref is None` 的条目与 `density is None` 应当同类处理：`require_density()` 同级新增 `require_contrast()`，全量提取前两道门禁一起过。

## 【严重】

### 4. `Density` 测量协议本身没有预注册——这是过拟合的下一处入口
- **证据**：`types.py:177-197` `Density` dataclass 字段 `rows_per_symbol_day` / `collapse_ratio` / `receipt`；`seeds.py` 末段注明「`io.events` 全量提取前必须 `require_density()`」；对象简报 116 行「预算是拍的必须在花掉 15 小时之前暴露」。
- **攻击路径**：研究员在样本日上跑 `io.events` 拿到数字 → 填进 `density=...` → 门禁放行 → 跑全量。**问题**：①「样本日」是几天？哪几天？②「在样本日上跑」用的样本宇宙是什么？会不会专门挑活跃股？③「坍缩比」的「原始行数」怎么计——是 `orders + trades + xinqing` 的总行数，还是 `orders` 一流的行数，还是只在 orders 内与本事件相关的行数？④测量本身算不算一次「接触数据」？若是，按 CONTEXT.md「预注册」的定义，测量前的样本选取、参数选取都属于策略——**预注册防的是事故，测量协议若不预注册，density 字段就成为 V1 失败模式「本地网格搜索找到最优参数 → 事后填进预注册」的镜像**。
- **修正**：把 `Density` 的填入本身写成预注册的产物——预注册的判据形态应包括：① 测量样本日（≥ 5 个，覆盖涨/跌/震荡/集合竞价封板/停牌日）；② 测量样本宇宙（按板块分层随机抽样，N ≥ 200 标的）；③ 坍缩比的原始行集定义（必须写明取哪几流的哪些列）；④ 测量本身的 episode 边界（一次密度测量 = 一次独立 episode，不与因子 episode 共享预算）；⑤ 测量结果的「意外高密度」必须有结构解释并触发「回退到设计」而非「把数字调成可接受」。

### 5. 多重检验作用域未定义——四条条目 × ~9 几何度量 = ~36 个备选变量，组合空间爆炸
- **证据**：四条 seed 每条声明 5-9 个 Measure；`seeds.py:53-66 / 103-110 / 141-147 / 174-179` 完整列出；CONTEXT.md 第二节明文「episode 是多重检验校正的作用域单位」。
- **攻击路径**：每条事件记录都会带 ~9 个几何度量，这些度量**本身是未来因子的备选变量**：例如 `RefillAfterFill.span_ms` 可以是「等待耐心」因子，`LevelBuildThenVanish.n_orders / life_ms` 可以是「建墙效率」因子，`VolClockBar.volume / vwap / n_trades` 可以衍生出十几种时间结构因子。**当前没有任何 episode 视角指出：这 4×9 = 36 个备选变量将分别走因子假设流程，进而消耗 episode 预算**。若每条几何度量都直接走因子假设（按 V1 的流水线），则 36 个因子 + 任意非线性组合 = 单批次上百次检验——episode 预算瞬间耗尽。
- **修正**：在条目文档里强制声明每条 Measure 的「对应假设路径」——一个 Measure 必须挂在至少一个因子假设的预注册条目上才能存在，否则视为死字段。这是「事实单源」的延伸：几何度量若没有假设方向就不应留在接口里（没有消费者）。CI 校验 `measure.name ∈ ∀pre_register.factor_hypotheses.factors`。

### 6. `bars_per_day=48` 是「采样分辨率」伪装的拓扑量，方法论上是判断
- **证据**：`types.py:49-50` `SAMPLING_RESOLUTION` 定义「调它只改变段的粗细，不改变段是什么」；`seeds.py:181-197` VolClockBar 用 `bars_per_day=48`，`why` 字段写「48 对应连续竞价 4 小时里平均每 5 分钟一根，是个起点值，第一片实测后按每日 bar 数分布重定」。
- **攻击路径**：48 这个数字本身不含样本排名 / 分位 / 偏差——技术上确实通过三条拓扑量检查。但**为什么是 48 而不是 32 或 96**？作者已自陈「起点值、第一片实测后重定」——这就是预注册应锁死但没有锁死的事。把 48 改成 96 会让每根 bar 变细、揭示出更多微观结构（潜在的「庄家分笔模式」），改成 24 会变粗、把更多结构压平。**这是一个隐藏的过拟合旋钮**：研究员跑第一遍拿到 N 条 → 改 48 到 X 再跑 → 若信号更强则「找到了更合适的分辨率」→ 把 X 填进预注册 → 一次性确证。这是 V1 accum_dist 「阈值焊在生成期」的同构复发，搬到 bar 切分粒度上。
- **修正**：把 `bars_per_day` 的取值集合作为预注册的判据（候选集合 = {24, 48, 96, 144} 等离散刻度），不允许在 pre-flight profiler 之外调整；或者退一步：把 48 锁死，注明「任何调整都是新预注册」，CI 校验 `bars_per_day` 修改必须伴随 `pre_registration_id` 出现。

### 7. `VolClockBar.tick_volume` 把「20 日均量」当作现成事实读取——这是统计量伪装成的拓扑量
- **证据**：`seeds.py:185-194` `tick_volume = daily_ref.volume 的 20 日均值 ÷ bars_per_day`，「日均值取自 T−1 及以前，绝不含当日自身」；架构红队第 7 条已指出除权除息会破坏此假设（cite）。
- **攻击路径**：20 日均量是统计量——它的稳定性建立在「标的成交量行为在 20 天内平稳」这一未被声明的假设上。高送转 / 配股 / 板块风格切换（农业 → 题材）/ 大宗解禁日都会让该均值严重失真。**更糟的是**：作者用「T−1 及以前、绝不含当日自身」把这一处理标榜为「避免未来信息」，但**这条规矩在方法论上只防了一半**——它防了 09:35 的 bar 边界取决于 14:55，没防 09:35 的 bar 边界取决于过去 20 天的总量分布。**20 日窗口本身是研究者选择的，不是市场结构决定的**。该窗口对应一次特定的「最近期偏好」选择，研究员完全可以选 5 日 / 60 日 / 250 日得到不同的 bar 结构。
- **修正**：把 `lookback_days` 从硬编码的 20 升级为 `ParamRole.SAMPLING_RESOLUTION` 风格的预注册参数——候选集合 = {5, 10, 20, 60}，每次测量时强制声明所用的 lookback_days 与所测的样本日组合。或者在 `core.raw.types` 里增加 `lookback_robustness` 检验：要求同一事件流在 lookback_days ∈ {10, 20, 60} 上的产出条数变异系数 < 阈值，否则视为样本敏感性过高、写进事件流的「不稳定」标签（与覆盖状态并列）。

### 8. `Param.why` 与 `EventSpec.v1_audit` 是「署名字段」但实际承担判据职责
- **证据**：`types.py:124-130` `Param.why` 仅 `if not self.why: raise`；`types.py:240-241` `v1_audit` 仅 `if not self.v1_audit: raise`；对象简报明确这些是「署名字段（机器只查非空，拦不住写错的人）」。
- **攻击路径**：`v1_audit` 被声明为「V1 失效模式审计是进注册表的前置条件」——这是研究纪律层级的硬约束，但机械实现只看非空。研究员可以写 `v1_audit="V1 没做过"`、`v1_audit="N/A"`、`v1_audit="略"` 而不触犯任何 CI 检查。**这等同于预注册「预注册目录 append-only」机制的镜像漏洞**：预注册目录受 git diff 保护，事件注册表的 v1_audit 不受任何保护。两者在「研究纪律层硬约束」这件事上形式相似，但防护强度差一个数量级。
- **修正**：要么把 `v1_audit` 升级为枚举（`V1AuditOutcome.NOT_APPLICABLE` / `V1AuditOutcome.AUDITED_AND_DISMISSED` 等，每条枚举对应一段固定引用 V1 失效模式的条款）；要么在 CI 里增加对 v1_audit 字数 / 关键词的最低硬性下限（虽不优雅但有效）。**最低限度**：要求 v1_audit 必须显式引用至少一个 V1 章节号（§F / §C / §D / accum_dist 等），CI 用正则匹配章节号格式，不通过则拒。

## 【建议】

### 9. 时段边界缺位：集合竞价（09:15–09:25）、涨跌停封板、停牌心跳在四条条目里都没出现
- **证据**：四条 seed 的 `lookback` 均为 `INTRA_DAY` / `CROSS_DAY`，无任何 `applicable_phases` 字段；架构红队第 6 条已指出三条反常结构在集合竞价期间会爆量。对象简报 122-123 行问「集合竞价、涨跌停封板、停牌心跳这些形态会不会让某条结构退化成噪声或爆量」。
- **攻击路径**：集合竞价阶段允许撤单、撮合未开始——「建档、撤回零、期间 0 成交」的假墙会大量出现；涨停板买一封单 30 万手、排队者撤单再挂单，假墙事件密度可达平时 50 倍；停牌心跳日（每天约 6 只主板）orders 与 trades 双双为空，提取器在「等成交到达」上死锁或超时。**任何不含时段过滤的日内型提取器在样本日上得到的 density 数字都不可外推到全量**——这是用户在 2026-09-03 已裁定「边界由结构触发不由时间触发」时的另一种情形：集合竞价不是「时间触发」，但它是「时段前置条件」，属于接口该有的另一个维度。
- **修正**：在 `EventSpec` 增加 `applicable_phases: tuple[TradingPhase, ...]`（默认排除 `CALL_AUCTION` 与 `PRE_CLOSE_AUCTION`），同时增加「时段内数据缺失则产出 `DayBoundary.gap_codes ⊇ {DefectCode.OUTSIDE_TRADING_PHASE}`」规则。停牌心跳日条目直接短路返回空事件流，由日界事件兜底。

### 10. SSE / SZSE 数据源能力不对称在注册表层未声明
- **证据**：`schema.py:69-78` trades 流字段 `ask_ref` / `bid_ref` 是 SZSE 委托-成交关联号；架构红队第 1 条指出 SSE trades 不携带买方/卖方原始订单号。`seeds.py:80-117` RefillAfterFill 的不变量「被成交耗尽的本方委托 → 耗尽它的成交 → 同价同量的补单」在 SSE 上无法机械判定。
- **攻击路径**：主板标的 ~50% 为 SSE（`600/601/603/605`）。若 RefillAfterFill 在 SSE 上跑，要么退化为「订单簿重建」（违反纯逻辑核不碰 IO 的约束，因为它要在每个事件上维护订单簿状态），要么退化为「以 trades 自身回放」（这等于把 trades 当 orders 用，密度归零或可信度归零）。**当前条目没有声明 supported_exchanges，下游因子的样本宇宙声明无法对齐**——一个因子假设若声明「在 RefillAfterFill 上验证」，但注册表条目无 exchange 约束，则样本宇宙实际被悄悄砍半。
- **修正**：在 `EventSpec` 增加 `supported_exchanges: tuple[Literal["SZSE", "SSE"], ...]`，所有 SZSE-only 的条目必须在样本宇宙声明里把 SSE 标的排除（通过 `MAIN_PREFIXES - SSE_PREFIXES`），并由日界事件产出 `gap_codes ⊇ {DefectCode.UNSUPPORTED_ON_THIS_EXCHANGE}`。

### 11. `FillExceedsDisplayed` 的「幸存即隐藏」假设在 3 秒穿档场景下结构性失效
- **证据**：`seeds.py:124-154` 不变量「成交量 ≥ 前一帧的展示量，而该档位在后一帧仍然活着」；`schema.py:32-35` 连续竞价时段 4 小时，架构红队第 4 条已详述穿档再回档路径。
- **攻击路径**：3 秒一帧的快照间隔内，激进市价单可以打穿价位再被反弹回来的新挂单重新撑住——后一帧快照看到的「该档位活着」是 **新挂单** 而不是原挂单。方法论层这是「幸存≠同一批订单幸存」的语义漂移：用户裁定说「幸存本身就是隐藏的证据」，但幸存者可以是新加入者，证据并不指向隐藏深度。架构红队的修正建议（要求两帧之间该 (side, price) 上 orders 新增笔数 = 0）是结构性收窄，但**这是从 orders 流找补，是用 orders + trades + xinqing 三流重建出「无新增挂单时段内成交量 ≥ displayed_vol」这一新不变量**——单 xinqing + trades 物理上做不到，强制三流对齐后该条目的日内 / 多流对齐属性才会被正确反映。
- **修正**：把 streams 从 `(xinqing, trades)` 扩到 `(xinqing, trades, orders)`，并在不变量里加 `orders_in_window == 0`；同步把 `lookback` 重新审视是否仍是「日内」（orders 流与 xinqing 流的对齐水位窗口属日内范围，但 `max_alignment_skew_ms` 需声明）。

### 12. `ticks_from_touch_at_peak` 等几何度量定义在日内行情里依赖隐含的「盘口深度与快照同步」
- **证据**：`seeds.py:62-65` 几何度量 `ticks_from_touch_at_peak` 描述「peak 时刻该档位离本方最优价几个 tick」。事件提取过程中需要把 orders 流上的时刻与 xinqing 流上的最优价对齐。
- **攻击路径**：orders 与 xinqing 在毫秒级不同步（典型 100ms–3s 水位），peak 时刻的「最优价」取自最近一帧 xinqing（而不是真正的 peak 瞬时最优价）——这是一个**测量误差不被记录**的隐性方法论问题。研究员用 `ticks_from_touch_at_peak` 作因子时，看到的不是 peak 时的真实最优价位置，而是「peak 时刻所在快照区间的最近一帧快照里的最优价」——两者在剧烈行情下可差 5-10 个 tick。因子若依赖此度量的精细分位（1 tick / 2 ticks），会引入系统性偏差且无法被因子层自己检测到。
- **修正**：在事件流版本里增加 `alignment_skew_ms` 字段，记录 orders 时刻与最近 xinqing 帧之间的时间差（毫秒），进证据指纹；或者把度量重命名为 `ticks_from_touch_at_nearest_snapshot` 让语义真实反映测量对象。
