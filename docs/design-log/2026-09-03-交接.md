1. **工程只保五条硬约束**：深模块 · 结构化互相调用有约束 · 同一功能只有一个入口 · 单一职责 · 不重复造轮子（新功能必须调用已有功能）。每轮强制，红队重点查这五条 + 正确性。其余约束降为每周一次。

3. **工程管束四、五步暂缓**（文档生成、STATE.md + 周报）：HTML 是给人看的，用户看的是程序结构。
4. **因子按事件定义，不绑定交易日**：CONTEXT.md「因子」「日界事件」已改，词汇表 / 架构图同步。此前把因子定成 (标的, 交易日) 粒度是漂移，与 Level-2 逐笔数据为核心的目标矛盾。
5. 事件定义收敛到**结构切割**（`design-log/2026-09-02-事件定义.md`），并于当日第二次 session 收口
   （`design-log/2026-09-03-事件流设计收口.md`，已写进三份活文档）：事件三型（区间 / 组 / 时刻）·
   回看范围四档（段内 / 日内 / 跨日 / 周期）· 边界由结构触发不由时间触发 · 每类事件一张表 ·
   周期型落日级参考层的列 · 提取参数只能是拓扑量 · 不得用「反常」定义事件。
   「日级参考层先跑一趟」的建议已收回（副产品不能排在主产品前）；驱动层外层按日期升序、内层按标的并行，
   跨日依赖因此零成本。**第一批种子五条全留**，理由是每类提取器至少一条，否则分类没被验证。
   **仍待用户裁决**：污染级别的分级标度。

6. **按工程方便砍业务需求是错的**（用户当场纠正）：不同事件本来就该有不同的提取器，
   串行的活给串行提取器，并行的活给并行提取器，**按需选，不是按贵贱选**。
