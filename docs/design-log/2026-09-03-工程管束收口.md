# 工程管束收口（2026-09-03 用户裁定）

- 前三步值，保留；第四步（文档生成）与第五步（STATE.md + 周报）**暂缓**——HTML 是给人看的，程序结构足够好、反馈足够及时就不需要看它。
- 工程的硬约束收成五条，每轮强制、红队重点检查：**深模块 · 结构化互相调用有约束 · 同一功能只有一个入口 · 单一职责 · 不重复造轮子（新功能必须调用已有功能）**。
  其余约束（观测批次明细绑定、收据全集、门禁自身 ratchet 等）降级为每周一次的检查，不再当场修。
- 每个 PR 只跑一轮红队；红队攻击面改为五条硬约束 + 正确性；多轮红队会飘、会带着主思路走，这是今天最大的成本。
- 回到目标：找策略。下一步推进项目本体（事件注册表 / 事件提取 / 三个必测数字 / 第一个假设），不再为门禁开 PR。
