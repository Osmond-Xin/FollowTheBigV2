## 一、红队命中分类

| 类 | 条目 |
|---|---|
| **三方独立命中**（全部采纳） | ① append-only 用 `git diff` 可绕、需语义校验 + 生命周期状态 · ② 模型起草 STATE.md 会把未裁决写成事实，「唯一裁决」用词错 · ③ 全局数量门禁（≤30 文件 / ≤5 万词）会被关掉或诱发对抗压缩 · ④ `tools/` 边界：工具必须是薄适配器，判据下沉 src · ⑤ 「跑第二次即工具化」不可观测，改为落地事实必须带收据 · ⑥ HTML 逐字节 diff 脆弱且生成器可手改，需 provenance |
| **两方命中**（采纳） | ⑦ 目录名门禁挡不住入口泛化（`__main__`、argparse、`project.scripts`、workflow）· ⑧ 枚举方向反了：账本是单源，代码枚举 == 账本 · ⑨ 待裁决形状不得进正式账本 |
| **单方命中，核实成立**（采纳） | ⑩ 架构图从代码生成与「图上没有视为不存在」循环（agy）· ⑪ 非规范文件名跳过是隐式样本过滤（opencode）· ⑫ 「被测试引用」≠ 烟雾测试（codex）· ⑬ 扫描 / 摄取工具的 checkpoint、锁、原子输出（codex）· ⑭ 账本条目缺 created_at / receipt / 工具版本（codex、opencode）· ⑮ V1 preserve 不是真值，只是 sanity（opencode）· ⑯ 账本驱动的表驱动测试（agy）· ⑰ 状态机文件的行数豁免（opencode）· ⑱ 16 个脚本账目要逐个列（agy，实为 8 源脚本并成 4 工具 + 8 废弃，下表补齐） |
| **单方命中，不成立** | 「无尾逗号应记为 gap」（opencode S12）：数据在，枚举空值是值不是缺口；正确处理是读取层保持原值、下游把 `' '` / `''` / null 视为同一无值，已登记数据表 |
| **攻击面错套**（不采纳，理由：属研究执行器，本方案明确推迟到 R6 之后，规则已在 CONTEXT.md §二、§三） | 对照裁决落点 · 解读落点 · 污染级别字段 · 事件流版本链 · 置换检验形态 · episode 预算 · 三态裁决字段 · 「工具须先预注册」（audit / scan / bench 是工程工具，不含研究判据）· 「阈值方向写反」（措辞，且该门禁已废） |

## 二、规则（修订版）

**R1 工具与脚本**
- 仓库无 `scripts/`。`tools/` 只放**薄适配器**：argparse → 调 `src` 公开接口 → 格式化输出；≤ 120 行；不含任何判断逻辑。
- 判据下沉：文件名规范、磁盘余量、幂等判定、比对口径全部进 `src`（纯的进 `core`，碰盘的进 `io`），有契约测试。
- `tools/manifest.toml` 登记每个入口：目的 · 输入 / 输出 · 烟雾测试路径 · 最近一次收据。
- 门禁：(a) 全仓 AST 扫描 `if __name__ == "__main__"` / argparse·click·typer / shebang / `[project.scripts]` / workflow `run:`，不在 manifest 即红；(b) 每个入口有烟雾测试：用合成夹具真正调用入口，断言退出码、输出 schema、二次运行幂等；(c) `tools/` 禁止非入口 helper；(d) import-linter：`tools` 只能 import `ftbv2` 顶层导出。
- **收据规则**（替代「跑第二次」）：任何进入账本 / 数据表 / design-log 的数字必须带 `receipt_id`（命令、工具版本 hash、输入 hash、输出 hash、时间），且 PR 里有能复现它的 `tools/` 入口；无收据的事实不得落地。
- 16 个脚本处置（8 源 → 4 工具，8 废弃）：
  `compare_v1_v2 + compare2 → tools/audit_preserve.py`（口径进 `io.raw.audit`；V1 preserve 只作 sanity，byte-exact 判据来自摄取收据的 `sha256_csv`）·
  `time_shape_scan → tools/scan_shapes.py`（扫描逻辑进 `io.raw.audit`，带 checkpoint / 锁 / 原子写 / 事件流版本占位）·
  `ingest_20days + ingest_one_day + ingest_two → tools/ingest_days.py`（驱动逻辑进 `io.raw.ingest.ingest_days`；文件名规范是 `core.raw.schema` 的纯函数；**不跳过**非规范文件——列入收据 `skipped` 并非零退出，除非 skip code 已登记；磁盘余量绝对字节 + 百分比双阈值）·
  `extract_floor + bench_rawstore → tools/bench_read.py`。
  废弃 8：bench_decode / bench_decode2 / bench_time / profile_b / resident / disk_probe / time_len / bench_b2（结论已落数据表与实施记录，各自附一行收据）。
- scratchpad 在仓库树外（现状即如此），永不 `git ls-files`。

**R2 活文档：源是文本，HTML 是构建产物**
- 三份活文档的**源**改为文本：词汇表源 = `CONTEXT.md`；数据表第四节源 = `ledger/*.toml`；架构图模块表源 = `architecture.toml`（见 R5）+ 各模块 `__init__` 签名。手写段落留在 Markdown 源里，HTML 整体由 `tools/render_docs.py` 生成，**不再手改 HTML**。
- 生成物带 provenance 块：源路径、源 hash、生成器 hash；CI 重新生成后比对（先经格式化器标准化，再语义抽样：词汇表词条数 == CONTEXT 词条数、第四节行数 == 账本条目数），provenance 与实际源 hash 不符即红。
- 生成器改动走 CODEOWNERS 专门 review。
- artifact 重发由 CI 产物驱动（本地 = 线上）。

**R3 形状账本：单源、语义 append-only、有生命周期**
- `ledger/defects.toml` 收全部形状（缺陷与良性），条目：`id · code · kind · stream · days|structural · status(pending|active|superseded) · superseded_by · created_at · evidence(receipt_id) · read_layer_action(patch|gap|none)`；`none` 明确 = 保留并打标，下游由样本宇宙消费。
- 待裁决只能 `pending`，转 `active` 须写裁决出处；代码 `DefectCode` **从账本生成**（或 CI 校验集合相等）。
- 门禁：从 `origin/main` 读上一版账本，按 `id` 做结构化比较：禁删 id、禁改 `code/kind/stream/created_at/evidence`、`days` 只许并集、废弃只能 `superseded_by` 指向已存在 id 且原条目保留。**不用文本 diff。** supersedes 链本身 append-only。
- 表驱动测试：`action=none` 断言读取层透传，`patch` 断言修复契约，`gap` 断言归因码。
- `ledger/observed`（工具扫描观测集合）⊆ 登记集合的门禁一并建。

**R4 文档生命周期：写一次、带出处、机械归档；模型不裁决**
- 三类：活文档（三份源 + CONTEXT.md）· 设计日志（写一次不改）· 归档（`docs/archive/YYYY-MM/`）。
- `docs/STATE.md` 是**导航**不是裁决：结构化条目 `decision_id | status | source_ref | source_hash | decided_by | decided_at`，禁止自由事实句；CI 拒绝缺 hash / 缺状态 / 引用未落地日志的条目。
- 归档由确定性程序按「日志里的事实已落到活文档 / 账本 / 代码」（`landed_refs`）判定并随该落地 PR 联动移动；模型（MiniMax，CI cron 每周）只产 `docs/digest/YYYY-WW.md` 周报，无裁决效力，输入只给剥离代码块的纯文本、输出只许 JSON schema。
- 门禁改为增量式：单个 PR 顶层新增 design-log ≤ 1；单篇 ≤ 2000 词且必须有「问题 / 决策 / 落地点」三段；「未落地日志」计数 > 10 即红（已落地的不计）。废除总词数门禁。
- README 固定模板，只留入口链接。

**R5 架构声明先于代码**
- `architecture.toml` 声明模块拓扑（名字、归属纯核 / IO、允许依赖）；import-linter contracts 从它生成；CI 校验 `src` 下的包集合与依赖 ⊆ 声明。「图上没有视为不存在」的「图」= 这份声明，HTML 只是渲染。
- 模块公开接口 = `__init__.__all__`；AST 门禁禁止 `importlib` / `sys.path` 篡改 / 深路径与私有导入。
- 行数不做硬门禁；crapkit 复杂度 ratchet 管；状态机文件按「单状态机一文件、单 `step` ≤ 50 行」另计。

**R6 研究阶段**
- 验证执行器 + 预注册 + 证据包存在前，研究问题只允许产出经 review 的工具与收据；预注册目录与账本共用 R3 的语义 append-only 门禁，现在就建（含 supersedes 规则）。执行器的判据形态、三态裁决、episode 预算、对照裁决、污染级别按 CONTEXT.md §二、§三，不在此重述。

## 三、落地顺序（每步一个 PR，门禁先于迁移）

1. R3 账本结构 + 语义 append-only 门禁 + 枚举生成（今天四个形状：`quote_only` active，`no_trailing_comma` active，`stream_symbol_mismatch` active/gap，`empty_file` **pending 待裁决**）。
2. R1 入口门禁（AST 扫描 + manifest + 烟雾测试）；把 4 个工具落进 `tools/`，判据下沉 `src`；8 个废弃脚本各附一行收据。
3. R5 `architecture.toml` + import-linter 生成 + `__all__` 门禁。
4. R2 文档源文本化 + 生成器 + provenance 门禁（先词汇表，再数据表第四节，再架构图模块表）。
5. R4 STATE.md 结构 + 增量门禁 + 归档程序 + 周报 cron。

## 四、需要用户裁决的四件事

1. 是否接受本方案（含把三份活文档的源改为文本、HTML 变为构建产物——这改变你日常看图的工作流：看的还是同一个 artifact，但改动只能改源）。
2. `empty_file`（0 字节 CSV）：pending → 登记进收据（推荐）还是维持硬拒。
3. 周报由 CI cron + MiniMax 产 `docs/digest/`（推荐，无裁决权）还是 Claude Code 云端例程。
4. 落地顺序是否按上表（账本与门禁先行，迁移后行）。
