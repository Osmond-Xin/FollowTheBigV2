# 事件是什么：红队后的备选定义（待用户裁决）

> 草案 `2026-09-02-事件定义简报-草案.md` 把用户的起点模型（算式 + 阈值）列为 A，另给 B（分位候选）、C（结构切割段）、D（窗口帧）。
> 三方红队：agy（架构）需改 · opencode（方法论）需改 · codex（工程）不得合并。原文同目录。本文只收共识与分歧，最后给推荐。

## 一、三方共识（独立命中，全部采纳）

1. **淘汰 A 和 B：阈值与分位都是判断。** θ 决定事件存不存在；p95 与 p80 给出不同候选集，是判断强度换了个名字。写进提取器 = 锁进 17 小时。
   方法论一路给了可机械检查的三条线（见第三节）；工程一路要求给参数打角色标签并 lint。
2. **淘汰 D（窗口帧）及其组合。** 架构：17 亿行让因子状态机每天空转 480 步，O(T) 契约被击穿，CI 秒级回归瘫痪；逐笔结构（冰山递交序列、撤单距离）被 30 秒窗抹掉不可恢复；SSD 148 GB 撑不住 30–40 GB 加派生。
3. **封杀日内事后分布口径。** 「当日自身 p90」让 09:35 的事件存在与否取决于 14:55——事件流的存在性本身携带未来信息，任何置换检验都是伪检验，也永远对不上实盘。
   提取器判据只允许两类：无分布依赖的物理结构约束；或严格来自 T−1 日以前日级参考层的滚动量（冷启动记缺口，不进事件流）。
4. **收敛到 C：事件 = 结构切割段。** 一段有起止的时间区间，由拓扑规则切出（连续性、计数、档位相邻、时间上界），带自身的几何度量，不带任何「够不够显著」。
5. **日界事件是系统事件，由提取器驱动层产生**，来源是 交易日历 × 标的主表 × 摄取收据 的叉积，不是注册表条目的产物；缺口与覆盖状态（停牌心跳 / 无原始数据 / 单边缺失 / 救援日）编码在日界事件的属性里（`gap_codes` 与账本共用 DefectCode）。
6. **形状消歧层在事件提取之前**（IO 层）：开盘重复帧、停牌心跳、6 位时间、枚举空值三态，在进入切割规则前归一成 canonical tick schema；注册表不知道 D008 / D013 存在。
7. **事件流版本要绑全集**，并有 major / minor / patch 规则：改切割算法或参数 = major（全量重跑，隔离旧流）；新增独立事件类型 = minor（增量追加）；纯重构产物哈希不变 = patch。

## 二、单方命中、核实成立（采纳）

- **废止「伴随量清单」**（agy）：段后 K 窗的伴随量要求提取器等未来、破坏单向流式，而且是在猜因子层要什么——猜错就重跑 17 小时。事件只记内生几何；跨段的环境量由因子状态机在消费时自己累积。
- **种子事件先过 V1 八种失效模式审计**（opencode）：冰山「同 (price, vol) 递交 ≥ k」正是 V1 96% 触发的错代理，k 从 10 改 3 只是把同一段逻辑挪个位置。任何种子若在 V1 的 ①活跃度混淆 / ⑤不够稀有 / ⑥方向相反 / ⑦同步非提前 上中过招，条目必须写明「为何不继承该否定」。
- **种子按结构命名**（opencode）：`Seq_RepeatedSamePxVol` 而不是「冰山」，语义别名放旁字段——`event_type == "spoof"` 这一列本身就是对下游的语义污染。
- **目标事件率**（opencode）：信号稀少是设计目标。以「年 5–10 次开仓」反推每 (标的, 日) 事件数上限，注册表条目要声明期望条数；B 形态的 8400 万条候选与「几万条 / 天」差 1000 倍。
- **资源上限与两阶段提交**（codex）：注册表条目带 `max_rows_per_symbol_day` 等预算；输出先写临时目录、生成 output manifest 校验后原子发布；超预算硬失败不发布。
- **原始快照 id**（codex）：提取启动前冻结每个原始文件的 path / size / checksum，读时二次校验，任何变化立即失败。
- **分位与浮点定义固定**（codex）：凡进入注册表的滚动量都写明 quantile_method / nan_policy / empty_sample_policy / tie_policy / operator。
- **第一条种子 = V1 唯一存活几何**（opencode）：`net_hi_quiet ∧ max_abs_uq高` 是「持续安静 + 单点突变」的复合，结构上是日界事件上的窗口统计而不是反常时刻；注册表须让日界事件承载当日事件计数、跨度等 `window_stats`，因子层直接读。

## 三、「事件不含判断」的机械判据（方法论一路给出，采纳为注册表门禁）

一个提取参数要同时满足三条，否则它是判断阈值，只能进预注册：
1. **维度切分**：参数只定义切割边界的拓扑量——时间窗边、笔数边、价位连续性边、离最优价的离散刻度边；不接受任何关于「该量在样本中的排名 / 分位 / 偏差」的参数。
2. **单调同伦**：参数单调变化只能让段切得更细或更粗，不能把事件换成另一种东西（θ↑ 把 Build-Up 换成 Cancel 就违反）。
3. **不可调出空集**：参数在允许范围内怎么取，每个 (标的, 交易日) 都至少有一条日界事件。

工程一路的补充：注册表每个参数带 `parameter_role ∈ {structural_partition, sampling_resolution, candidate_recall_gate, decision_threshold}`；
`decision_threshold` 禁止进入提取器；`candidate_recall_gate`（调紧会单调减少候选数）必须登记召回覆盖率实测。

## 四、推荐给用户的定义

**事件 = 某标的 tape 上被拓扑规则切出的一段区间**，记录：`event_type_id`（结构名）· `symbol` · `start_time` · `end_time` · `side` · 该结构特有的几何度量（价、量、笔数、档位、时延）。
不记录：任何分位、排名、通过 / 不通过、以及段外的环境量。
**判断（多大算反常、几次算多、离最优价多近算近的显著性）全部是因子层的预注册参数**，秒级重跑。
**日界事件**是另一类事件，每 (标的, 交易日) 恰好一条，由驱动层从日历 × 标的主表 × 摄取收据产生，带覆盖状态、缺口码与当日 `window_stats`。

对照用户的起点模型：「某个计算量大于某个值」里，「计算量」保留（它是段的几何度量），「大于某个值」搬到因子层。提取器只回答「这里有一段结构」，不回答「这段够不够大」。

## 五、分歧与待裁决

1. **切割参数能否完全不含幅度**：agy 的种子写了「≥ 3 s」「≤ 2 ticks」「≥ 3 次」，opencode 说 k 本身就是判断。推荐：切割规则只保留**存在性**（相邻、连续、时间上界），计数与距离作为几何度量记录（n_slices、rest_ms、ticks_from_touch），不设最小值；由第三节三判据机械裁定。
2. **成交量时钟的刻度**来自 T−1 日级参考层 ⇒ 日级参考层要先于事件提取存在（架构图说两者同一趟产出）。推荐：日级参考层先跑一趟（只需 trades，1122 天约 7 小时），事件提取第二趟。这是对架构图「同一趟」的修正，须改图。
3. **种子数量与 family 预算**：方法论要求每批种子 ≤ episode family 上限的 25%。第一批 5 条（含日界）是否可接受。
4. **污染级别**三档（注册表作者 / 提取器作者 / 因子消费者 是否读过 V1 同源结论）作为条目必填字段。
