## 一、正确性

**CSV 解析（最严重）**
- `ingest._parse_body`物理行计数 = `body.splitlines()`，但 polars `read_csv` 对带引号字段是引号感知。**CSV 含跨行字段时，物理行数 ≠ 逻辑行数**，`n_rows_csv` 与 `frame.height` 校验会假阳性通过（行数短于实际），或下游报错。数据表第三节必须显式声明"CSV 不含跨行字段"才能成立，否则应改用 `csv.reader`/`csv.DictReader` 流式计数。
- 表头 `header.split(",")` 同样不处理引号 —— 表头若含 `"foo,bar"`，列数算错。
- 行计数 `if line` 忽略空行 + `n_rows=` 截断读取，两条线逻辑一致；但跨行字段下仍错。

**`_validate_entries` 死代码**
```python
if mode[:1] in ("l", "L") or "Link" in entry:
```
`entry` 是 dict，"Link" 不在 7zz `-slt` 的属性 key 中（属性键是 `Attributes`/`Path`/`Size`/...）。`"Link" in entry` 永远 False。注释只承认前者；要么删这条、要么修正语义。

**`_load_manifest` / `parse_ledger` 字段缺失**
字段缺失抛原生 `KeyError`，错误栈难排。建议在解析层包 try/except，给出"账本第 N 条缺 `id`" / "manifest 缺 `quality`"。

**`decode.to_int64` 边界**
2^53+1 → null 的判定 `exact_int.is_null() | (candidate != exact_int)` 对 null 输入 `candidate` 也是 null，`!=` 比较返回 null（polars 三态），`fill_null` 后才得到布尔。**当前表达式没 `fill_null`**，依赖 polars `when(...).then(None).otherwise(candidate)` 中 `loses_integer_precision` 求值为 null 时走 otherwise 分支 → 给 candidate（即 null）。语义正确但隐式 —— 行为依赖 polars `when` 对 null 谓词走 `then` 分支的处理。建议加注释或显式 `.fill_null(False)`。

**`to_time_ms` 五位 HMMSS**
`slice(0,1).cast(Int64, strict=False)` 取小时位 1 位；上限校验 `hour.is_between(0, 23)` 兜住。OK。但 `slice(2, 2)` 取 2 位分钟对五位串会越界 → null（polars 默认）。**"厂商省掉毫秒与前导零"是否同时省掉秒位？** docstring 没说清，需要语料验证。

**`plan.attribute_gaps` 语义**
文件存在但全空（row group 都在但 symbol 都缺）→ `_decode` 后 frame 高0，`present[fp.day] = frozenset()`，所有请求 symbols 都被算成 SYMBOL_ABSENT。**更准确的归因应是 `DAY_PRESENT_EMPTY`**（无现有枚举值）。需要契约层决定。

**`schema.FIELDS` 字段注释**
`type` 注释提到 SZ `0/1/U` 与 SH `A/D`，2025 起新增 `' '` `S`。但 `type` kind 是 `enum`，**store 不映射未知值原样保留**——注释与 `decode.decode_field` 的行为一致。✓

## 四、性能路径

**pre_buffer**：`_read_row_groups` 用 `pq.ParquetFile(fp.path, pre_buffer=True).read_row_groups(...)`；`inspect_raw` 用 `pq.read_table(..., pre_buffer=True)`。✓禁止 `pl.read_parquet` 在 docstring 显式声明。✓

**Row group 裁剪**：`_select_row_groups` 按 `[symbol_min, symbol_max]` 与 symbols 相交，`num_rows > 0` 必选；`pruned=True`。空 statistics（min/max=""）永不入选。✓ 单标的期望338× 削减可见于 `stats`。

**零拷贝写**：**未确认**（`_write_streams` 后半段被截断）。需要验证 ingest 走 `pa.Table` 直接 `pq.write_table` 而非 `polars → pyarrow → pq` 的多步复制。**关键确认点**。

**字符串保留**：所有 parquet 列 large_string + `_symbol`，dtype转换只在 execute 层做。**避免 ingest→store 双重转换**，✓。

**catalog 不缓存**：每次 `execute` 都重读所有文件 footer。若同一 RawStore 实例多次读（如探索性查询），热点。可作技术债，但当前实现已按文档承认是观测辅助接口、不进计划。

## 五、Docstring 一致性

**严格一致**：
- plan 全部断言（单趟、裁剪、空 rg 不入选、projection 最小、patch 按文件、ledger_sha256、未登记字段 KeyError）
- schema.SYMBOL_COL 唯一来源
- store 全部 IO入口与 docstring 行为一致
- "查不到 = 没有"禁令在 Catalog.missing_days / attribute_gaps / inspect_raw / quality.UNVERIFIED 全部兑现

**不一致 / 含糊**：
1. **`decode.to_time_ms` 五位 HMMSS**：docstring 说"厂商省掉了毫秒与前导零"，但 HMMSS 把秒位也省了还是只省毫秒+前导零？实现按 HMMSS 解析，文档需更明确。
2. **`_frame_segment` 内联三段**：sha256_csv 的规范帧规则散在 `_load_stream` 的 3 行里，没命名 `canonical_frame_bytes(symbol, header, body)`。**接收端必须按相同规则复算才能 verify**，但规则没在接口层声明。
3. **`store.execute` "time_6digit 只检查本次投影实际读到的列"**：这是性能 vs 安全取舍，已 docstring 声明，但等于「显式 request.fields 不含 time_ms 即可绕过登记检查」——若下游因性能考虑裁掉 time_ms 字段，会绕过 fail-loud。这是有意识的漏洞，应在预注册或调用方约定中要求"任何读取 orders/trades/xinqing 的请求必须含 time_ms"。
