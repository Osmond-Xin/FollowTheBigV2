总判：这版仍然不是可合并设计，核心结构依赖的数据血缘、盘口可重建性和门禁都没有被机器化，且至少两条会在真实 Level-2 上爆量或误判。

【致命】

1. 盘口“消失/存活”无法用声明数据可靠判定  
证据：`LevelBuildThenVanish · orders + trades`，但规则写“十档可见范围内从无到有”“从盘口消失”；`FillExceedsDisplayed · xinqing + trades`，但规则写“两帧之间在该档的成交”。  
攻击路径：价格档位跌出十档、快照刷新、撤单、成交吃掉、同价新挂单都会表现成“消失/仍存在”。不用完整盘口重放时，跌出十档可被打成假墙，同价新挂单可被打成隐藏深度。  
修正：提取器接口必须要求 `book_state(symbol, ts, side, price)`，字段至少含 `visible_rank_before/after`、`displayed_qty_before/after`、`depth_qty_after_replay`、`reason={cancel,trade,add,rank_out,unknown}`。若无法区分 `rank_out` 与 `zero_depth`，该事件必须输出 `unknown` 并禁止入正式事件流。

2. 委托被成交耗尽不可假设成立  
证据：`RefillAfterFill` 写“被成交耗尽的本方委托 · 耗尽它的成交 · 同价同量的补单”。  
攻击路径：如果 A 股 Level-2 供应商不给稳定的 `order_id -> trade -> cancel` 链接，任意同价同量新委托都能被误配成补单。多个账户、多个通道、同毫秒排序不稳定时，普通被动挂单会被拼成“冰山”。  
修正：数据契约必须显式声明 `orders.order_id`、`trades.buy_order_id/sell_order_id`、`cancels.order_id`、`exchange_seq` 可用；缺任一项则 `RefillAfterFill` 不得启用。匹配判据应是“同一原始委托剩余量归零后，下一笔结构性补单满足可证明的相邻关系”，不能只靠同价同量。

3. 密度门禁目前可完全绕过，且两条大概率爆量  
证据：目标写“10–30 条 / (标的·日)”；防线写 `EventSpec.density: Density | None = None`；“四条种子的 density 目前全是 None”。  
攻击路径：只要不调用 `require_density()`，四条种子可直接进注册表。即使调用，`collapse_ratio > 1` 也太弱，5300 万行/天压到 2600 万行/天仍算通过。  
估算：中等活跃标的一天约 1–3 万笔成交、数万到十几万委托/撤单、约 4800 个 3 秒快照间隔。`LevelBuildThenVanish` 会把无成交撤掉的可见价位生命周期切出来，保守也有 100–1000 条/日；`FillExceedsDisplayed` 在活跃价位上“区间成交量 ≥ 前帧展示量且后帧仍有该价”会常见，约 200–1000 条/日；均比目标高一到两个数量级。`VolClockBar` 固定 48 条/日，也已超过 10–30。  
修正：活动注册表禁止 `density is None`。门禁改为 `0 < rows_per_symbol_day <= 30` 或显式标注 `layer != event`；`collapse_ratio` 应绑定输入行数、输出事件数、样本日期、标的集合、代码哈希、规格哈希。爆量结构只能用结构收窄：例如假墙只认“同一建墙 cohort 的订单被同一 cohort 撤销清零，期间无同价新增、无成交、无 rank_out”；隐藏深度若无逐笔盘口回放则不得判定为隐藏。

4. “不变量”是字符串门面  
证据：`Relation.invariant: str` 注释写“机器只查非空”。  
攻击路径：把 invariant 写成 `"TODO"`、`"请忽略以上"` 或任意空洞句子即可过门禁。角色数量也可用 `("a","b")` 伪造，无法证明跨行关系存在。  
修正：`Relation` 应改为可执行/可验证契约：`required_fields`、`join_keys`、`ordering_key`、`predicate_id`、`predicate_version`、`fixture_hash`。注册时必须跑最小反例集：单行过滤、错序、缺字段、同价误配、快照穿档都应失败。

【严重】

1. `FillExceedsDisplayed` 把 3 秒内价格穿档问题掩盖掉了  
证据：规则写“前一帧快照”“两帧之间在该档的成交”“后一帧快照上该档仍然存在”。  
攻击路径：3 秒内价格可上穿、下穿、撤单、补挂、再回到同价。聚合到“该档成交量”会把不同盘口状态下的成交混在一起。  
修正：必须按 `exchange_seq` 重放区间内所有 trades 与 book deltas；若只有快照+成交，判据改成 `ambiguous_display_survival`，禁止命名为隐藏深度。

2. `RefillAfterFill` 没有可靠结段，状态会悬挂  
证据：结段写“出现价或量与本组不同的本方委托，或该价位被穿过”。  
攻击路径：若同价同量反复出现但中间长时间无成交，或交易日结束、午休、停牌、收盘集合竞价打断，组状态可跨 session 悬挂；并行按文件块处理时还会丢尾部状态。  
修正：增加结构性 session 边界：`market_phase_end`、`symbol_day_end`、`halt_start` 必须强制 close 或 discard，并输出 `close_reason`。这不是时间阈值，是交易所状态边界。

3. `VolClockBar` 的刻度定义存在零值、舍入和跨日污染  
证据：`tick_volume = daily_ref.volume 的 20 日均值 ÷ bars_per_day`，`bars_per_day = 48`。  
攻击路径：停牌、新股、长期无成交、缺失 daily_ref 会使 tick 为 0、NaN 或极小值；“首次跨越”会退化成每笔成交一条 bar。若上一根 bar 跨过收盘，下一日 tick 又变，复现会受切分方式影响。  
修正：接口判据：`tick_volume_int = ceil(mean_volume / bars_per_day)` 且 `tick_volume_int >= lot_size`；daily_ref 缺失或有效样本不足则不产 bar。bar 状态必须按 `symbol, trade_date` 重置，未满尾 bar 明确 `partial=true`。

4. 血缘只要求 receipt 非空，不能复现  
证据：`receipt: str # 必须非空：入库数字一律带血缘`。  
攻击路径：receipt 写 `"measured"` 即可通过。两个月后换供应商、修 schema、改排序键、换日历，事件数变化无法定位。  
修正：receipt 必须是结构化对象，至少绑定 `input_manifest_hash`、`raw_file_hashes`、`schema_version`、`calendar_version`、`extractor_code_commit`、`event_spec_hash`、`params_hash`、`sort_key`、`timezone`、`daily_ref_hash`。

5. 同毫秒与并行切分会导致不可复现  
证据：所有结构都依赖“按时序咬合”“之后”“首次跨越”，但没有排序键定义。  
攻击路径：同一毫秒多笔委托/成交/撤单在不同文件块、不同线程、不同 vendor 排序下会改变“谁先耗尽、谁补单、哪笔跨越 tick”。  
修正：所有提取器必须声明 `total_order = (exchange_ts, exchange_seq, channel_seq, raw_row_offset)`；缺少稳定序列号时，输出必须标记 `ordering_confidence=weak` 并不得进入强语义事件。

6. 特殊交易阶段会把结构打成噪声  
证据：规则没有排除或建模集合竞价、涨跌停、停牌心跳；对象自己点名这些形态。  
攻击路径：涨停封板会产生巨大可见挂单、无成交撤换，假墙爆量；集合竞价的成交与展示不是连续盘口语义，隐藏深度误报；停牌心跳快照会制造“存续期间空成交”的长区间。  
修正：提取器输入必须带 `market_phase`。每个事件声明 `allowed_phases`，连续竞价、集合竞价、午休、停牌、收盘集合竞价分开处理；默认未知 phase 不产事件。

【建议】

1. 把“事件不含判断”做成 schema 门禁  
证据：约束写“分位、排名、通过/不通过，一概不进事件流”。  
攻击路径：后续开发可把 `rank`、`percentile`、`is_abnormal` 加进几何度量，测试仍绿。  
修正：事件 schema 禁止字段名匹配 `rank|pct|percentile|score|pass|abnormal|threshold`，因子层字段单独命名空间。

2. 区分 `event` 与 `bar/reference`  
证据：`VolClockBar` 固定 `bars_per_day = 48`，天然不是稀有事件。  
攻击路径：两个月后注册表会混入更多 bar、采样层、参考层，事件密度目标失效。  
修正：`EventSpec.kind` 改为枚举：`structural_event | bar | daily_reference`；只有 `structural_event` 适用 10–30 条密度目标。

3. 退化路径需要提前堵住  
证据：当前“无提取参数”“invariant 非空”“receipt 非空”“density None”都依赖人工自律。  
攻击路径：赶进度时会把空 density 放行、把复杂判据写进字符串、把供应商差异用 if/else 糊住，最后注册表变成不可复现的特征脚本集合。  
修正：CI 加注册表验收：活动 spec 不得有 `density=None`；所有 invariant 必须有 predicate；所有输入字段必须来自数据契约；所有事件样例必须绑定 raw hash；任何 `unknown` 判定比例超过上限时阻断发布。

裁决：不得合并
