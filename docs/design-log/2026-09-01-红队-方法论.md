# 攻击报告

我把这份简报当成一个真实的对手来打。下面每一节都直接对应简报里某个具体的模块、不变量、或数字。结尾给出三版的失败概率排序和第四种切法。

---

## 0. 顶层判断

三版都解决了一个真问题——**V1 不是死于没有架构，而是死于「重复 end-to-end 脚本」能让每个局部看起来都在工作**。但三版都把同一个隐含假设当作公理：

> **「只要裁决是机械的、判据是预注册的、产出是带指纹的，研究者就会被迫按规矩出牌。」**

这个假设在单兵研究里是错的，在多 agent / 多 sprint 的项目里是错的程度更深。下面所有攻击都指向它。

---

## 1. 「无定论」会吞掉一切：统计功效的通胀与隐性的样本外漂移

这是这套语义里**最致命的洞**，因为它不是 bug，是设计目标。

### 1.1 简报里悄悄做了一个等价替换

简报把「无定论」定义成"数据不足或功效不够"，又把"功效不够"的判定权完全交给工具（`power_precheck`）。问题在于：

**A 股"跟庄"是一个低信噪比 + 厚尾 + 结构性断裂的过程。**

- 真实的庄家拉升样本一年可能只有几百到几千次（取决于定义），远小于"假设数 × 时间窗 × 子群"展开后的检验空间。
- IC（信息系数）的真实值在 A 股横截面里通常在 0.01–0.03 级别，要打显著需要**百万级观测**；分层收益需要极长的 OOS 期。
- 而"做庄"信号的生命周期可能就是几周到几个月，**事件研究单元的 iid 假设根本不成立**——同一只票的多次"拉升"在样本里高度自相关（同一个庄、同一个周期、同一波筹码）。

后果：**`power_precheck` 在绝大多数假设上会判定为 "predetermined_inconclusive"**。这本身没错，但问题是：

### 1.2 工具的「无定论」是单次的，研究的「无定论」是累积的

工具只能在单假设、单判据、单数据集上算功效。但真实的量化研究是一个**序贯决策过程**：

- 看到「无定论」→ 调整窗口 → 再测 → 再「无定论」→ 加变量 → 再测 → 终于显著 → 但你不知道这是第 N 次数据接触之后的产物。
- 预注册的判据哈希**对单次接触有效**，对**序贯接触无效**。简报里没有"接触次数计数器"这种东西，也没有"对一个假设家族累计触达的数据集变体数"这种东西。

### 1.3 「三态裁决」对 A 股的结构性失败

A股有三种**非平稳性**会系统性地让"无定论"变成永远的状态：

1. **制度性断裂**：注册制（2023）、转融通、T+0 试点、印花税调整、北交所开市——每一次都让历史 IC 分布的 stationarity 假设破灭。一个 2022 年"无定论"的因子在 2024 年可能"确证"，反之亦然。预注册判据写死的"样本区间"在这种环境下是诅咒而不是保护。
2. **幸存者偏差**：要找的是"正在准备拉升的庄"，但样本里能被你识别出来的拉升，事后看都是成功的。**失败的拉升（建仓后没拉、庄被套、庄放弃）被你用的 Level-2 指标完全无法事后确认**。这是**标签问题**，不是判据问题，三态裁决救不了你。
3. **做庄形态演化**：监管在升级，散户在进化，量化对手盘在挤压传统庄家。"庄"的形态本身在漂移。预注册写下的"庄 = 吸筹期 X 天 + 量比 Y + 大单占比 Z"在 2022 年是有效的定义，在 2026 年可能是过时的定义。

**具体退化路径**：

> 第 1 个月：`power_precheck` 报 80% 假设是 `predetermined_inconclusive`。
> 第 3 个月：研究 agent 发现"扩大时间窗能让某些无定论变成确证"——这是合理的统计直觉，但**也是数据窥探**。简报里没有任何机制区分"合理的窗口扩展"和"为了 p-value 调窗口"。
> 第 6 个月：解读 agent 开始给"无定论"附加"弱信号"标签，写进 `.md` 注释。
> 第 12 个月：代码注释里到处都是"在 2024–2025 子区间上 IC=0.02（弱信号）"，CI 怎么拒？

### 1.4 替代方案

承认**预注册的判据是"分析计划"不是"判决书"**，并显式建模三件事：

- **功效预算的硬上限**：每个 sprint 最多 X 个`predetermined_inconclusive`→`confirmed`的转换数；超过则整个 sprint 冻结、写根因分析。这逼研究者承认"我的判断不是数据告诉我的"。
- **窗口调整日志**：每次调整样本区间/时间窗必须登记"假设性调整"（hypothetical adjustment）vs"观测性调整"（observed adjustment），后者强制按新发现处理。
- **跨制度区间的强制分段报告**：每个判据必须给出"在三个制度区间的子结果"，而不是合并 IC。跨制度"无定论"与单制度"无定论"是两种不同的信息。

## 2. 预注册防的是事故，不是过拟合

这是简报语义里**最被高估的工具**。

### 2.1 预注册在哪个变量空间里锁死？

预注册写死的是：**检验方法 + 阈值 + 样本区间 + 多重检验校正 + 功效**。

它**没有锁死**且**没办法锁死**的：

1. **预处理流水线**：缺失值填充、平滑、缩尾、对齐——这些是统计结果的隐性决定者，且高度依赖实现细节。同一份原始数据，过缺失值用"前一天收盘"还是"行业均值"，IC 可以差 30%。
2. **特征工程的中间选择**：构造"主力吸筹"指标时，是用 `volume × price_range`、还是 `order_imbalance × 笔数标准差`、还是 `大单撤单率 × 委托队列深度`？这些**因子构造选择**对最终 IC 的影响往往大于因子本身。
3. **Universe 定义**：简报里有"sweep10≥2 = 庄板池"，V1 里 builder 删涨跌停日——**标签/样本池本身就是数据窥探的产物**。预注册写死的 universe 定义本身可能就是在自证一个错误。
4. **Cross-fitting 的 fold 划分**：尤其是 rolling window CV 的窗口起点、步长、训练/测试比例——这些在 A 股这种 regime-heavy 数据上，**对 Sharpe 的影响可以达到因子本身的量级**。
5. **执行模拟里的"合理默认"**：`ExecutionSpec` 里那些被简报称为"唯一来源"的参数，**每一个都是策略**。滑点模型、冲击模型、是否允许撤单——这是策略假设，不是技术细节。

### 2.2 预注册锁死 ≠ 研究者可重复

预注册的判据哈希在执行前固定并写入证据指纹——这个机制**对单个假设有效，对假设族无效**。一个常见的规避路径：

> 研究者意识到"按因子族做 Bonferroni 太严"，于是把一个家族假设拆成 5 个独立假设分别检验，每个都单独校正——**`p × 5 = 5p`，名义上每假设都通过了预注册校准，实际膨胀了 5 倍**。工具没法检测这种拆解，因为它在语法上是合法的。

更阴的：

> 把一个连续型判据（"IC > 0.02"）拆成 3 个二值判据（"IC > 0.015" / "IC > 0.02" / "IC > 0.025"），只注册中间那一个，但分析时三个都报。

预注册**只能防"我在看到结果后改判据"这种粗糙事故**，防不了"我在判据空间里精心选择注册位置"这种细颗粒度的事故。

### 2.3 替代方案

- **预注册的是"分析计划"而不是"判据"**：写明"我会用 X 因子、在 Y 区间、按 Z 流程、产出三个统计量 W1/W2/W3，每个对应一个领域问题"。W1/W2/W3 可以后面增删，但**X/Y/Z 必须严格遵守**。
- **预注册必须有"备择假设的预注册"**：不只写"我会检验 IC > 0.02"，还要写"如果 IC ≤ 0.02 但 turnover-adjusted IC > 某个值，我会怎么做"。这强制研究者把决策树写死。
- **盲化样本区间的"探索段"和"确认段"**：把数据切成 [探索段][缓冲][确认段]，预注册时**只公布探索段结果，确认段必须一次性使用**。V1 的 1122 个交易日可以切成 [2022][6 个月缓冲][2023–2026]，确认段 800 天 + 800 天做 walk-forward。这是预注册真正能发挥作用的地方——但简报没这么做。

## 3. 多重检验校正的作用域：第三版做得对，但理由是错的

第三版说"裁决器必须一次看到整批假设，否则相当于没有校正"。**机制是对的**，但理由只对了一半。

### 3.1 第三版漏掉的最危险作用域

**校正作用域不只是"一次裁决里包含多少假设"，还有"一个因子被多少种方式检验过"。**

具体场景：

> 研究者注册了假设 H："因子 F 的 IC > 0.02"。测试，无定论。
> 研究者**没有改判据**，只是换了**测试窗口**：[2022-2023] / [2024-2025] / [2025-2026]，三个窗口分别报。
> Bonferroni 在"一次裁决包含 N 个假设"上做了 1 次校正。
> 但研究者实际做了 **N × 3 次检验**，校正系数应该是 3N 才对。

工具看不见"测试窗口换了"这件事，因为它是探索 agent 的自由。第三版的"一次看到整批"机制对此无能为力。

更阴的：

> 同一个因子 F，在 3 个 universe 上（沪深 300 / 中证 500 / 全 A）各做一次判据。每个 universe 一个独立的裁决，**每个裁决都"一次看到整批"，但三个裁决之间没有任何机制把它们视为一次多重检验**。

这是 Bonferroni / FDR / Holm 在**多步序贯研究**里的经典失败模式——简报里完全没处理。

### 3.2 替代方案

- **多重检验的作用域定义在"研究 episode"上，不在"一次裁决"上**。一个 episode = 一个研究问题（如"主力吸筹是否可被识别"）+ 一个因子空间 + 一个 universe 空间。episode 内的所有判据构成一个 family。
- **family 内的检验数必须在 episode 开始时声明**。每个 episode 有"假设预算"，用完即冻结。这是真正能防 Bonferroni 失效的工具。
- **Holm-Bonferroni 优于 Bonferroni**，且必须按**原始 p 值排序**校正，而不是排序后的 p 值——这是一个非常容易写错的细节，简报里没提。

## 4. 三层假设 DAG 的划分本身有问题

### 4.1 简报里的三层划分

> 因子假设 → IC/分层收益/置换检验
> 组合假设 → 多重检验/共线性
> 策略假设 → 路径依赖/滑点/资金约束

这个划分有一个隐含假设：**因子之间相互独立，可以组合；组合可以脱离因子单独检验；策略层只接收组合层的输出。**

### 4.2 真实的依赖结构

在 A 股跟庄这件事上，**假设的依赖不是树状的，是网的**：

- **因子假设依赖数据特征**：同一份 Level-2 数据，构造"主力吸筹"的 5 种算法之间高度相关（共享"大单"定义、共享"时间窗"假设），它们**不应该被当成独立假设做多重检验**。但 DAG 看不见这种相关。
- **组合假设依赖市场状态**：分散化效果在牛市/熊市/震荡市是三个不同的数。组合假设不能跨市场状态合并。
- **策略假设反向依赖因子**：滑点模型取决于因子信号的**集中度**——如果因子集中在小盘股，滑点是另一个量级。策略层不能等组合层做完再算。

更糟的是 **DAG 静态化的代价**：

> 假设 DAG 在研究开始时构建，运行时不变。但 A 股制度性断裂让 DAG 本身需要随时间演化——2023 年注册制改革后，"小盘股因子"和"壳价值因子"的依赖关系变了。
> 工具看不见这种 DAG 重构，因为它把 DAG 当成静态结构。

### 4.3 替代方案

- **承认 DAG 是研究产出的对象，不是研究的基础设施**。DAG 不应该是代码，而应该是数据——每次研究迭代产出一个 DAG 的变体，工具记录"假设 H 在 DAG 版本 v1 和 v2 上结果不同"，触发人工 review。
- **三层划分改成"两层 + 一个投影"**：信号层（因子 + 组合作为一个整体，因为它们的依赖不可拆）+ 策略层（执行 + 资金约束）+ 一个**显式的"信号到策略的投影函数"**作为单独的可裁决对象。

## 5. 盲验在"人的记忆"这条路径上不可能实现

这是简报整套机制里**最被高估、也最危险的一条**，因为它**声称能机械实现，但实际只能靠纪律**。

### 5.1 三版的盲验机制都在防什么？

- 第五节：角色切分。"给假设队列排优先级的角色" vs "编写预注册判据的角色"。
- 第七节：污染标记。任何读取 V1 历史结论的进程，其后续产出被打"已污染"标记。
- 第八节：同 7。

这些机制都在防**"一个 agent 看到 V1 的结论后照抄"**——这是最粗糙的事故。

### 5.2 这些机制防不住的真正事故

**V1 的失败教训已经被吸收进了 LLM 的训练数据 / 上下文缓存 / 项目记忆**。

具体场景：

> 研究者（人，或者 agent 的 prompt author）在 V1 跑了一年，看到 V1 报了 473 个未引用脚本、1235 处硬编码、V1 的 builder 删涨跌停日、V1 的 6 位时间戳问题——**这些教训在写 V2 时已经以"先验知识"的形式存在于每个 agent 的上下文里**。
> 当 agent 写一个新的因子计算模块时，它**不会显式 import V1 的代码**，但它写出来的代码天然就避免了 V1 的事故模式——**这不是因为盲验在工作，而是因为 V1 的教训已经被吸收成"什么是显然正确的"**。

第七节和第八节的污染标记对此**毫无作用**——标记能标记一个进程读没读过 V1 文件，但标记不了一个 agent 的"思维模式"是否已被 V1 污染。

### 5.3 真正能伤害研究的不是"知道 V1 失败了"，而是"知道 V1 为什么失败"

简报里把 V1 的失败教训详细列出来（第二章），然后要求"盲验"——这是自相矛盾的：

> 一旦把 V1 失败教训写入简报（即使是作为"反向案例"），这些教训就成了 V2 agent 的训练信号。V2 的每个决策都会**避开这些失败模式**，但避开的方式**和"看了 V1 代码"避开的失败模式是一样的**。
> 真正的盲验要求：研究 agent **不知道**有 V1 这个项目存在过，不知道 A 股 Level-2 数据有什么已知陷阱，不知道"涨跌停日数据有问题"这种事实。
> 任何一个不满足这个条件的"盲验"都不是盲验，是"延迟读取"。

### 5.4 "隔离只读区 + 污染标记"机制的物理缺陷

- **污染标记如何不可移除**？第八节说"任何进程读取该区，都会在其后续产出的证据上打上不可移除的标记"。但"进程"的边界在哪？
  - LLM agent 通常是**长期运行的进程**，agent A 读了 V1 区，然后被 agent B 接手继续工作——B 没读过 V1，但 B 看到的 prompt 里包含 A 的产出，**A 的污染通过 prompt 传到 B**。
  - 跨进程 IPC、文件缓存、shell history、~/.bash_history——这些都不在"进程"的定义里。
- **标记如何不可移除**？第八节没说技术机制。如果靠"代码层面的标记函数"，那研究 agent 写一个不调用标记函数的脚本就绕过了。如果靠"OS 层面的标记"（如 inotify + 写时打 tag），那所有 V1 数据要在写入磁盘时染色，但**已存在的 V1 数据怎么办**？迁移时染色 = 重算所有指纹，昂贵且易错。
- **"读取"的定义**：grep 一个文件名算不算读？`ls` 算不算读？IDE 索引文件内容算不算读？任何**让信息进入 agent 上下文**的操作都是读，第八节的定义太窄。

### 5.5 替代方案

- **承认盲验在 LLM 时代不可能纯机械实现**，把它降级为"审计对象"而不是"机制"。
- **真正的盲验是"fresh-eyes test"**：一个从未参与该项目、不知道项目历史的 agent（最好是不同 LLM、不同训练数据切片的），拿到一组预注册判据和一份数据，独立产出裁决。这个裁决**不与项目内部的裁决合并**，而是单独报告"fresh-eyes 组的判据与项目内判据的一致性"。
- **长期方案**：把 V2 的成功标准定义为"在不知道 V1 失败教训的前提下，新研究员/agent 是否能独立复现并改进现有结论"。这是一个**多代研究**的目标，不是 V2 能解决的。

## 6. 证据指纹：看起来很强，但有一个不可修复的洞

### 6.1 指纹能锁什么

指纹能锁：输入数据的哈希 + 代码版本的哈希 + 参数的哈希 + 输出的哈希。这是个**完整性证明**，不是**正确性证明**。

### 6.2 指纹不能锁什么

**指纹不能锁"输入数据本身是否有偏"**。

具体场景：

> 第三版说"未解释残差必须为空，非空 = 系统有 bug，硬失败"。这是对的，但只在**两个指纹之间的差异完全可解释**时有意义。
> 真实情况是：研究者注册了 800 个假设，每个假设一个指纹 + 残差报告。**残差报告本身也是研究产出**——研究者可以"调整残差计算方式"使残差变小，再生成新指纹。这是 GIGO：垃圾进、垃圾出、垃圾对齐。
> 指纹机制对此毫无防御能力。

### 6.3 指纹与"代码即文档"循环的退化

第三版有"代码执行完毕后，工具自动把执行结果写回该代码的注释"——这是一个**危险的循环**：

- 第一步：执行代码 → 得到结果 R → 写回注释 "结果 = R"
- 第二步：人类修改代码 → 注释里的 "结果 = R" 还在
- 第三步：CI 怎么判断"现在的代码产生 R 吗"？必须重跑。
- 但代码碰数据 ⇒ CI 不能跑 ⇒ 收据机制上场
- 收据机制：本地跑完写 HMAC 签名收据，CI 校验签名和 tree_sha 是否匹配。
- **攻击路径**：研究者改了 `src/` 里的某个函数，把代码注释里的"结果 = R"也更新为"结果 = R'"，然后本地跑重活、写新收据、提交。CI 校验：tree_sha 匹配 ✓，签名匹配 ✓。**CI 通过，但代码现在产生的是 R' 而不是 R，且注释说的是 R'**。
- 这个机制防的是"改了代码没跑重活"，但它**假设重活的输入/参数和上次一样**——而"改了代码"本身往往意味着"输入也变了"。

### 6.4 替代方案

- **指纹链必须有"参数清单"**：每个指纹包含输入数据的 byte-level hash + **所有调用参数的 hash + 依赖库的 hash**（不仅是 `src/` 的 tree_sha）。这增加规避难度但不能消除。
- **承认指纹是"审计工具"，不是"防御工具"**。任何一份指纹都可以被复算——指纹机制只在"复算结果与原始记录不同"时报警。这是个**事后检测**，不是事前防御。
- **代码即文档机制必须分开"被记录的"和"被执行的"**：注释里写的是"上次跑出的结果"，但 CI 必须独立验证"现在的代码 + 现在的数据 + 现在的参数 = 上次跑出的结果"。这三者的"现在的"都必须显式存在于 CI 校验里，不能只校验代码 + 签名。

## 7. 第八节第三版的逐条攻击

> "扫描器的谓词是封闭构造子集合，不接受任意 lambda"

对。但有个洞：**封闭构造子无法表达"主力吸筹"这个概念的核心**——它本质上是个**模式识别问题**，需要统计/ML 推理（异常检测、状态机）。把这些塞进封闭构造子 = 把你需要的 80% 业务逻辑排除在谓词下推之外。结果：要么下推得到（简单谓词，但信号不准），要么信号准但不下推（慢 25 倍）。**这是"性能 vs 表达力"的经典权衡**，第三版选了性能但牺牲了业务适配。

> "估算(同参) -> {预计读取字节, 预计 seek 次数, 命中 row group 数}"

这条很强，但有个缺陷：**估算本身必须能"在不打开数据文件的前提下"回答**。row group statistics 是文件 footer 里读的——打开 footer 是打开文件。pyarrow 的 `ParquetMetadata` 可以不读数据只读 metadata，但 footer 也是文件的一部分，IO 上的成本是**几个 KB 的随机读**，在 4 IOPS 的外置盘上是**几百毫秒**。每次 `估算()` 调用都付这个成本，且估算本身是频繁调用的（CI 断言里要调）。**估算的成本模型本身就要被估算**——递归问题。

> "缺陷补丁是登记数据（纯 Polars 表达式），默认处置是拒绝"

机制好。但**"必须登记"这件事没有强制点**——补丁表是手工维护的，研究者写新数据加载代码时忘了登记新发现的缺陷，怎么办？必须靠 lint/lint rule。**补丁登记表本身成为新的可绕过层**。

> "回测内核的签名里没有 `stop_loss` 参数，只有参数集句柄"

这条有个反讽：**它解决的是 V1 散装 kwargs 的问题，但它把策略假设的"参数选择"集中到了一个台账里**——这个台账是研究 agent 唯一可以"调整参数而不改代码"的地方。**台账成为新的、可被精心调整的隐藏层**。`stop_loss = -0.12` 从代码迁移到 YAML，台账里有一万个 -0.12 的变体，"散装 kwargs"换了皮。

> "裁决器必须一次看到整批假设"

第 3 节已攻击，这里补一条：**它无法检测"研究者把一个家族假设拆成 N 个独立假设，每个独立裁决都校准，但整体上 N 倍膨胀"**。这是 Bonferroni 的经典失败模式。

> "污染标记……不可移除"

第 5 节已攻击。

> "派生库与扫描器的环用目录打断"

机制优雅，但**目录本身需要 schema 演进**——派生层的列定义要随研究演进，schema 升级 + 内容寻址的代价是**旧产物的驱逐 + 重算**。在 100 GB SSD 预算下，频繁的 schema 演进会导致驱逐风暴。

> "CI 断言读取字节数（用 pyarrow 的 IO 计数器）"

这条**依赖 pyarrow 的 IO 计数器是否对外暴露**。查 API：`pyarrow` 的 `Scanner` 有 `scan_options` 但**没有标准的 IO byte 计数器**。需要 monkey-patch 或 fork。这是"看起来聪明但实际做不到"的候选之一——除非用 `strace` 或 LD_PRELOAD，但那是另一套基础设施。

> "拒绝建立『质量门禁』模块 / 『配置』模块 / 引擎的 port"

"配置"模块的拒绝我同意。"质量门禁"模块的拒绝——但**第三版自己列了一堆门禁（ruff, import-linter, 自带 AST, diff-cover, 契约测试, 血缘校验）**——这些不是"门禁模块"是什么？第三版在拒绝"门禁模块"的同时**默认存在一打门禁**，这是术语游戏。

> "接口窄了但没变简单"

第三版最诚实的一句话。**窄 ≠ 可维护**，**窄的接口可能只是把复杂度从一处推到另一处**。在 IO 层，"窄"意味着研究员要理解一整套 12 模块的协同才能加一个新因子——这比"1,123 个调用点各自端到端"在**单次改动的认知成本**上更贵。

## 8. 三版各自的致命伤

### 第五节（信息隐藏切法）

**致命伤**：纯逻辑核模块 5/7 和 IO 层模块 2/4 之间**没有定义"什么样的假设算"**。`Hypothesis` 是"类型化 Python 对象"——但**类型化对象本身可以表达任意业务逻辑**，研究 agent 可以用任意复杂的 Python 代码构造一个 Hypothesis 对象，预注册机制对此毫无约束。**"类型化 Python 对象"是必要的，但远非充分的**。

更深的问题：**第五节完全没有处理"研究者怎么产生假设候选"这个问题**。假设队列从哪里来？如果从 LLM agent 来，那 agent 的 prompt 就是新的隐藏层；如果从人来，那 V1 的教训就在人的脑子里。

### 第七节（横向 6 模块切法）

**致命伤**：**夹具语料的"故意注入全部五种已知缺陷 + 一个未知模式版本"**——这是**自找麻烦的逆向选择**。

- 已知缺陷的注入是合理的（确保修复代码生效）。
- **但"未知模式版本"被注入后**，测试只能验证"代码在未知模式上抛错"——抛错之后怎么办？没有数据可用，没有判据可执行。
- 更糟的是：研究者为了"通过"未知模式的测试，会**主动让代码"识别未知模式并打标记"**——这就把"识别未知的未知"这种 AI 难题硬塞进 IO 层。
- **第五节和第八节都有这个问题，但第七节明确写了它**。

第二致命伤：**`power_precheck` 报 `predetermined_inconclusive` 是 C1 成本等级（只读账本），但实际的多重检验功效计算需要看真实样本分布**——C1 不够。需要 C3（定向扫描原始层）才能算真正的功效。第七节把功效预算划到 C1 是个**资源规划错误**，会让大量假设被错判为"无定论"或被错判为"功效足够"。

### 第八节（细粒度 12 模块切法）

**致命伤**：**自陈的弱点 #1（跨日窗口因子 → 流式 → 掉出 CI 硬门禁）就是它的死刑判决**。

跟庄信号几乎必然需要跨日建仓观察（吸筹期 5–30 天）。如果因子核必须流式才能算，那因子核的 80% 业务逻辑都不在 CI 硬门禁里——**CI 硬门禁的全部价值（确定性测试、PR 级反馈、合并门禁）就消失了**。

第三版对此的应对没说，但**承认了**。这等于说"我的核心业务逻辑不在我的最强保障范围内"。

**自陈弱点 #2（CI 验证不了性能契约）**也不小——但可以通过金样本扩容缓解，不算死刑。

## 9. 三版的失败概率排序与致命原因

| 排序 | 版本 | 致命原因 | 短期可见失败 |
|---|---|---|---|
| 1（最先失败） | 第八节 | 跨日窗口因子 = 流式 = 掉出 CI 硬门禁 | 第 2 个 sprint，写第一个跨日因子时 |
| 2 | 第五节 | `Hypothesis` 是 Python 对象，没有"假设候选的产生机制"约束 | 第 4–6 个 sprint，研究者发现"产生新假设比验证旧假设快 10 倍" |
| 3 | 第七节 | 已知缺陷夹具 + 未知模式注入 = 自找麻烦；功效预算算错 | 第 6–9 个 sprint，`predetermined_inconclusive` 比例超 60% 时 |

**最可能失败的是第八节**，因为它的核心业务逻辑必然掉出门禁。**第二可能的是第五节**，因为它对研究行为的约束力最弱。

## 10. 第四种切法

三版的共同问题是：**它们把"研究纪律"包装成"代码机制"，但研究纪律的本质——研究者何时停止探索、何时承认无定论、何时不偷看 V1——是人的判断，不是代码能锁的**。

第四种切法的组织原则：

### 10.1 不要"门禁"，要"代价"

三版都默认"门禁越严越好"。但简报里**exFAT 4 IOPS 是项目最大的物理约束**——这个约束比任何代码层面的门禁都更强。**第四种切法把 IO 代价当作门禁**：让"违规走旁路"的物理成本高到不可承受。

具体地：

- **强制 IO 集中**：所有 IO 必须经过**一个**带计划的 reader（第七节的 H1 是对的）。但**不让它有"私有路径"**——`read_parquet` 不出现在任何代码里，**包括 src/**。reader 是一个**独立的可执行文件**（subprocess），接受 stdin 上的请求，stdout 上输出数据。**`src/` 里没有 IO 函数，连类型签名都没有**。
- **代价模型进请求**：每个 IO 请求必须带 `expected_cost_class`（C0–C4），reader 拒绝任何 `expected_cost_class` 与请求内容不符的请求——比如声明 C2 但请求里包含未下推的谓词，**reader 直接拒**。
- **IO 收据 = IO 请求的字节级日志**：每个读操作都被记录到不可变的 append-only 日志，包括"谁请求的、请求了什么、实际读了什么、为什么"。这个日志不是"审计"——它是**唯一可重放研究结果的方式**。

### 10.2 不要"假设 DAG"，要"研究 episode"

- **每次研究启动 = 一个 episode**。episode 有：固定预算的假设数（N=10–30），固定预算的功效预算（N 次 power_precheck），固定预算的样本接触次数（每个假设最多 2 次：探索 + 确认）。
- **episode 结束 = 强制 write-up**：所有 episode 必须产出一份结构化的 markdown 报告，包括"我们看到了什么 / 我们没看到什么 / 我们错了什么"。**报告本身的完整性是 CI 校验的对象**（字数、章节、必须包含的元数据）。
- **跨 episode 的假设传递是受限的**：episode A 的"无定论"假设不能直接进入 episode B 重新检验，必须**显式标注"假设来自前 episode"**——这给"研究者循环检测同一假设直到显著"行为一个可审计的痕迹。

### 10.3 不要"角色切分"，要"代际隔离"

- **每个 sprint 至少包含一个"新人 agent"**：prompt 里**不知道 V1 的任何失败教训**，只有"项目当前状态 + 任务"。新人 agent 的产出**与老人 agent 的产出对比**，差异报告作为项目产出的一部分。
- **不试图阻止老人知道 V1**——**承认这是不可阻挡的**——而是确保**新人的视角被保留**。

### 10.4 不要"代码即文档"，要"代码 + 失败博物馆"

- 代码 + 注释（执行结果写回）是有用的，但**只记录成功不记录失败**。
- 第四种切法强制每个失败的假设 / 失败的因子 / 失败的策略**也写一份"失败报告"**，存入 `museum/` 目录。CI 不要求失败报告写回代码注释（避免 GIGO），但要求它存在且未被篡改。
- **失败博物馆让"无定论"有具体内容**——"无定论"不只是状态码，是"曾经试过 N 种方法，都没成功，原因是 X/Y/Z"。这从结构上对抗"无定论吞噬一切"的退化。

### 10.5 不要"指纹链"，要"可重放研究记录"

- 每个 episode 的所有 IO 请求、所有裁决、所有 write-up、所有参数变更 = 一个**可重放的研究记录**。
- **CI 跑的不是"代码的单元测试"**，而是"重放上一个 episode 的研究记录，验证结果一致"。
- 这把"代码质量门禁"换成"研究可重放性门禁"——后者**直接对应研究有效性**，前者只对应代码正确性。

## 11. 总结：哪些机制看起来聪明但实际做不到或有害

| 机制 | 来自 | 判断 |
|---|---|---|
| 角色切分（给优先级 vs 写判据） | 第五节 | **做不到**——优先级排序本身依赖业务判断，写判据的人会被优先级反过来影响选择 |
| 污染标记不可移除 | 第七、八节 | **做不到**——LLM agent 的"进程"边界不清晰，污染通过 prompt 传递 |
| 封闭构造子谓词 | 第八节 | **有害**——把核心业务逻辑排除在外，IO 性能与业务适配二选一 |
| `估算()` 不打开文件 | 第八节 | **部分有害**——footer 读取本身是 IO，估算成本本身要被估算 |
| 缺陷补丁默认拒绝 | 第八节 | **有用但容易绕过**——补丁登记表成为新的可绕过层 |
| 参数集句柄代替 kwargs | 第八节 | **换皮**——把可调参数集中到一个新台账，问题迁移不解决 |
| `Hypothesis` 是 Python 对象 | 第五节 | **必要但不充分**——类型化对象可以表达任意业务逻辑，无约束力 |
| `plan()→execute()→reduce()` 强制分层 | 第七节 | **强约束**——但 IO 段不允许基于数据内容分支会让"动态加载"不可行 |
| 实测功效优先于推翻 | 第七节 | **有用**——但功效预算算到 C1 是不够的，需要 C3 |
| 缺陷账本进 CI | 第七节 | **有用**——但账本本身的完整性靠谁保证？ |
| 100 GB SSD 派生层硬上限 | 第七节 | **致命**——tick 级派生数据不压缩，3–4% 预算不够 |
| 不透明句柄代替路径 | 第八节 | **有用但代价高**——所有调试/日志都需要从句柄恢复路径，复杂度换地方 |
| CI 断言读取字节数 | 第八节 | **依赖未确认的 API**——pyarrow 没有标准 IO 计数器 |
| fresh-eyes 平行研究 | （我建议） | **长期方案**——不是 V2 能解决的 |

## 12. 一句话总结

**预注册防的是事故，盲验在 LLM 时代做不到，"无定论"会吞噬一切除非显式限制假设族预算和接触次数；三版都解决了工程问题但都没解决研究行为问题；真正的防线是 IO 物理代价 + episode 预算 + 失败博物馆 + 代际隔离，而不是更聪明的门禁。**

第八节最先失败（跨日因子 = 流式 = 掉出门禁），第七节次之（夹具自找麻烦 + 功效预算算错），第五节再次（假设产生机制无约束）。第四种切法应该放弃"门禁"思维，改为"代价 + episode + 代际隔离"。
