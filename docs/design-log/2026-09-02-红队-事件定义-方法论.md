总判：简报把"事件定义"框成「算式 vs 分位 vs 段 vs 帧」的选型题，但方法论真正要裁决的问题是**这套事件定义如何避免重演 V1 已证伪的八种失效模式**——而简报四选型与全部种子均未通过这一审计，故必须重构选型标准而非在 A–D 之间挑一个。

### 【致命】

**1. 选型轴心错位：四备选都在切"事件是什么"，没人切"事件流为下游承担什么不变量"**
- **证据**：简报 §2 给出 A / B / C / D 四个「事件是什么」的定义并要求排序；§4.1 直接问「A–D 哪个进注册表」。CONTEXT.md 把事件流的接口不变量写死为「按 (标的, 时间) 有序；每个 (标的, 交易日) ≥ 1 条日界事件；安静 ≠ 缺口；纯函数；判断留在因子层」，但简报从未把任一备选与这五项不变量做矩阵对账（例如：A 在安静日是否真能产 ≥1 条日界事件；D 在 quote-only 标的能否产；B 的"分位候选"在 (标的, 交易日) 没有任何候选时如何产日界）。
- **攻击路径**：红队一旦问"哪个备选让因子状态机能在 PIT 下唯一确定地读完一日并走出一步"，A 因为 θ=0 时静默丢弃、当日缺日界事件；B 在 PIT 冷启动窗口（2022-01 头 20 个交易日，参考分布不到 20 个样本，p95 不可估）下整日无候选、但日界事件必须产——备选与不变量的冲突被回避成"工程问题"，方法论上等于把不变量降级为可选项。
- **修正**：把简报 §2 重写为一张不变量矩阵。每一备选 × 每一不变量给一行，写明「满足 / 违反 / 在何种声明下满足」；矩阵里出现"在何种声明下满足"的格子必须有可机械检查的声明入口。判定方法不再是 A/B/C/D 排序，而是"不变量全绿"才算候选。

**2. 第一批种子事件里至少两条已经在 V1 证伪，被当种子是直接踩 V1 的雷**
- **证据**：数据表 §六 C「冰山 REP_MIN=10 的检测器 96% 的票都触发……错代理」；§六 F「spoof_seq≥3 残差真但稀有闸版不显著；max_abs_uq 82% 股票饱和」；§六 L「§F 假墙 / 极端失衡"被证伪"。**唯一 🟢 存活**：`net_hi_quiet ∧ max_abs_uq高`」；简报 §4.7 把"假墙 / 冰山 / 隐藏深度 / 成交量时钟"列为种子，其中冰山与假墙正是 V1 的两个"残差真但工程上做了 wrong proxy"的代表。
- **攻击路径**：注册表的第一批种子决定第一批假设。如果种子写「同 (price, vol)递交 ≥ k 次」（数据表 §六 C 原文 REP_MIN=10），那么任何 k 取 3 / 4 / 5 / 10 都在机械地复制 V1 的失败——只是把96% 触发降到 88% / 75% / 52% / 12%，再在因子层加判断，等于把同一段逻辑从提取器挪到因子层，而 V1 已经把同样的逻辑在因子层否过一次。**盲验的根本失效就在这里**：种子复用 V1 的几何（而不是 V1 的判断），factor 层会自然用上 V1 的判断绕路。
- **修正**：种子列表必须先回答"它在 V1 八种失效模式中的哪几个上中过招"。任何在 V1 命中过① 活跃度混淆 / ⑤ 不够稀有 / ⑥ 方向相反 / ⑦ 同步非提前任意一项的种子，注册表条目必须显式声明「该几何被 V1 在某因子假设上否过，本注册表的语义为何不继承该否定」；否则视为不合格种子。这就是简报 §4.7 缺的「污染级别」落地。

**3. 「事件不含判断」在 B / C 里没有可机械检查的边界，提取参数与判断阈值的切分线是该简报最大的逻辑漏洞**
- **证据**：简报 §0.4「提取参数（分位点、窗长、最小持续时长）属于事件注册表，进证据指纹，假设不得改；判断阈值只属于预注册」；§2 B 把"松分位 p95"列为注册表参数；§2 C 把"持续 ≥ N 窗 / 连续递交 ≥ k 次 / 连续吃穿 ≥ m 档"列为切割规则；§4.2 直接问"分位、N、k、m 是不是变相阈值"。该问句被简报丢回给红队，等于把 CONTEXT.md 写的"提取参数 vs 预注册阈值"这条铁律的可机械判定推给下游。
- **攻击路径**：B 的"松分位 p95"是判断——p95 越大越稀有，p95=80 与 p95=99 给出完全不同的候选集，正是判断强度。简报承认"参照分布若是『当日自身』= 日内前视"，但用"前 N 日滚动"绕过后仍要把"该股过去 N 日 p95"算到本帧上，这一计算本身就是判断（自适应的"宽"）。C 的 k=3 与 k=10给出完全不同的"冰山事件"集——这与 A 的 θ=0.5 vs θ=0.9 是同一类判断，只是藏在拓扑结构里。**没有机械检查的线，V1 的局部网格搜索会以另一种形式回来**：`k=3..7` 网格 → "k=5 在 2024Q1–Q2 上事件数对齐 V1 旧冰山" → 写进注册表 → 声称"接触数据前定"。
- **修正**：必须给"事件不含判断"画一条机器可验的界线，建议在简报里加以下三判据，**任一不满足即升级为预注册参数**（写在注册表条目上但 §4.5 必须 bump 事件流版本 major）：
  1. **维度切分**：参数只定义"切割边界"的拓扑量（时间窗边、笔数边、价位连续性边、撤单与最优价的离散刻度边），不接受任何关于"该量本身在样本中的排名 / 分位 / 偏差"的参数；
  2. **单调同伦**：参数的单调变化（k↑、N↑、m↑、窗长↑）只允许让"事件被切得更细"，不得让"事件被替换成另一种东西"；A 的 θ 与 B 的分位均违反（θ↑ 把 Build-Up 换成 Cancel，分位↑ 把候选集整体换掉）；
  3. **不可调出空集**：参数无论取何值（允许值范围内）都必须保证每个 (标的, 交易日) 至少产生一条日界事件；当前 B、C 均不满足（C 的 k 大到 11 即在大多数日空集）。

### 【严重】

**4. 信号稀少是设计目标，但四个备选都默认产海量候选；这本身就是把判断写到提取器**
- **证据**：CONTEXT.md 第一节「**信号稀少是设计目标，不是缺陷**」；简报 §2 D「3128 标的 × 480 窗 × 1122 天 ≈ 17 亿行」；§2 B 虽未给数，但 3128 标的 × 480 窗 × 1122 天 ×候选量分布超过 p95 的概率 5% ≈ **8400 万事件**（高于 CONTEXT.md "5–8 GB" 估算的两个数量级，与 §五"几万条反常观测"差 1000 倍）。
- **攻击路径**：事件流的体积决定因子层算 L1 假设的成本。当事件密度高到与日 K 线同量级，因子层任何"统计反常的聚合"都自动退化为日级因子重算——把判断搬到事件层预筛一遍。这是 V1 §六 E「**U→1 闸版反而成了过滤主力**」的结构同构。CONTEXT.md 把这写为"事件注册表目前为空"并标注为最大待定，但简报用同样的预算估算给出四选型却没回答"哪一个能让事件流达到一年5–10 次开仓的稀少度"。
- **修正**：简报必须补一节「目标事件率」：以"年度每标的 5–10 次开仓 ⇒ 1122 天每标的 ≤ 0.05 条事件 / 天"为锚，反推注册表条目的"单事件期望条数 / (标的 · 日)"上限；任何候选备选必须能在该上限内选出有判别力的子集，否则视为工程自残。

**5. 日界事件与缺口的不变量在 quote-only 与救援日上落不了地**
- **证据**：CONTEXT.md「每 (标的, 交易日) ≥ 1 条日界事件；安静 ≠ 缺口」；ledger D008（quote-only 每日 6 只、仅行情心跳）；D004（救援日 orders / trades 标的集合不一致）；D011（非救援日标的级单边缺失5 天 × 1–3 只）；D009（0 字节 CSV）。简报 §0.3 仅复述不变量，§4.6 把"日界事件与缺口在各备选里怎么产生"列为给红队的问题。
- **攻击路径**：D008 标的在 orders / trades 没有行；提取器若按 orders / trades 的最后行生成日界事件，quote-only 当日无日界事件，**因子状态机在当日不走一步**，跨日累积状态被冻在一周前那个值上，与真实世界脱节；这等于把"是否停牌"这个判断塞进了提取器（提取器必须能识别这是停牌而非数据缺失）。D004 / D011 是另一种缺口：标的在两流里符号集合不一致，提取器按何者发日界事件？按多者按少者？多者有 orders 无 trades 的日子，对 iceberg 提取来说缺一半源数据——缺口在事件流中如何编码？CONTEXT.md 说"缺口必须携带归因码……是下游纯核入口的必需参数"，但事件流怎么携缺口？**简报给不出答案 = 不变量不可执行**。
- **修正**：日界事件的生成权必须收归提取器驱动层（不是事件注册表的产物），由交易日历 × 标的主表 × 摄取收据三者的叉积给出；事件流按日界事件为锚产出，缺口在日界事件的旁路属性里编码（`gap_codes: tuple[DefectCode]`，与 ledger共享 DefectCode 枚举）。**这意味着事件流 schema 必须把日界事件当作一类特殊事件，与反常事件并列，注册表上单独列一节 `DayBoundaryDefinition`；而不是把日界事件当每条反常事件的"日界头"。** 这一点是把 §4.6 从开放问题升格为接口规范的最低限度。

**6. 参照分布口径是预注册参数还是事件注册表参数，简报没有给出归属规则，会让事件流版本与预注册版本双向污染**
- **证据**：简报 §3列出三种口径（当日自身 / 前 N 日滚动 / 全市场当日横截面），承认"当日自身=日内前视"，但仍说"注册表必须把口径写成参数，因子层不得混用"；未指明口径**本身**是哪一类参数。
- **攻击路径**：若口径属事件注册表（提取参数），则同一预注册在不同 N / 横截面口径下不能复用——同一假设重做时口径微调 = bump事件流版本 major = 历史证据包全废；若口径属预注册（判断参数），则同一事件流在不同口径下要重算百分位——意味着**事件流不该含百分位字段**，B 的"分位候选"形态就直接违反这条铁律。简报让 B 与这条铁律正面冲突。
- **修正**：简报必须明确写出**口径的归属规则**：归预注册 →提取器只产原始度量（值与必要伴随几何量），不产任何分位排名 → B形态不成立；归事件注册表 → 提取器冻结口径，事件流里写明每条记录用的是哪种口径、参数 N 是几 → B 形态成立但必须 bump 事件流版本规则被绑定。**两者必选其一**，不能默认滑过；建议**默认归预注册**（理由：分位排名是判断而非结构，与第 3 条修订一致）。

**7. Episode 预算与多重检验作用域完全没进入视野，这是直接踩 V1 §七 第⑤、第⑧条**
- **证据**：CONTEXT.md「episode 账本 append-only」「每个假设必须声明 correction_family_id；family 的新增、关闭、分裂必须留审计痕迹」；数据表 §七 「V1 自己总结的 8 个反复出现的否定模式：① 活跃度混淆 ② subsumption ③ lift ≠ 可交易 P&L ④ OOS 不复现 ⑤ 不够稀有 / 错代理 ⑥ 方向相反 = 派发 ⑦ 同步非提前 ⑧ 数据稀疏测不动」；简报全文未提 episode 预算、未提 family、未提 correction。
- **攻击路径**：注册表第一条种子条目就是一条**新 family 的诞生**。若注册表条目是 N 条，episode 启动时 family 数量被一次性 +N，研究预算被一次消耗 N / K（K 为家族上限）；V1 的 §七 第⑤「不够稀有 / 错代理」就是从这里开始的——种子几何看起来都对，但 family 太宽，每族给的样本独立性低、检验势不够，结果全部"无定论"。简报没让红队看这层，方法论上等于鼓励一次性产出 50 条种子事件。
- **修正**：简报必须加一节「种子预算与 family 配额」：每批种子数 ≤ episode family 上限的 25%（让研究过程还有 space to discover）；种子优先级按"在 V1 八种失效模式上的覆盖"排序而非按"直觉上有意思"排序；第一条种子必须显式对应 V1 §L 唯一存活的 `net_hi_quiet ∧ max_abs_uq高` 几何，先证"反例不会复活"再添新种。

### 【建议】

**8. 种子事件的几何命名应当是结构性的而非语义性的，否则会复制 V1 的语义污染**
- **证据**：数据表 §六 把 V1 的 is_buildup / is_spoof_seq / is_spoof_sweep 等命名拆出来，并明确"spoof / iceberg / hidden depth"是含判断的语义标签（"Sweep 不是扫单事件……仅仅是方向一致性判据"）。简报 §4.7 沿用"假墙 / 冰山 / 隐藏深度 / 成交量时钟"为种子名。
- **攻击路径**：把"假墙撤单"写进注册表条目名等于在 schema 层签发"我们打算识别庄家操纵"的语义许可。后续无论提取器多中性、因子层多纯净，事件流被读成 Parquet 喂给 pandas 时，`event_type == "spoof_cancel"` 这列就已经在污染下游——盲验降级为"延迟读取"是 CONTEXT.md 已定的现实，命名选错就把延迟读取直接变成了必读。
- **修正**：种子条目改名——结构在前、语义备注在后：`Seq_RepeatedSamePxVol`（冰山的几何）/ `QuoteThenWithdrawWithinT`（假墙的几何）/ `SnapshotRestGeqKDisp`（隐藏深度的几何）/ `VolClockBar`（成交量时钟的几何）。语义别名放 `semantic_aliases`字段，证据指纹只对结构名寻址。

**9. 必须在事件流版本中绑定证据指纹所需的全集而非子集**
- **证据**：CONTEXT.md「事件流版本 = 注册表版本 + 提取参数集 + 原始层数据清单 的内容寻址」；简报 §4.5 把"改一个统计量定义 / 改一个参数 / 加一个字段"作为版本 bump 的待决问题。
- **修正**：事件流版本的哈希输入应至少含八项：(a) 注册表条目源文件 SHA256；(b) 每条目的切割规则字典序列化 SHA256；(c) 每条目的 schema 字典序列化 SHA256；(d) 提取参数集字典序列化 SHA256；(e) 数据清单 manifest SHA256；(f) 提取器镜像（image 或 wheel路径 + SHA256）；(g) 提取命令规格（含 IO 参数）；(h) 缺陷账本 active 条目集合的 SHA256。**任何字段变化必须 bump major**（规则见后）。注册表条目内嵌字段的新增若不影响其他事件则允许 minor；纯实现重构允许 patch（产物哈希不变）。

**10. D013 开盘重复帧与停牌心跳必须在事件注册表之前先由提取器驱动层消歧**
- **证据**：ledger D013「供应商在 09:30 / 13:00 每股各发两帧重复开盘快照。preserve 不删行；事件提取的切割规则必须处理」；D008 停牌心跳每日 6 只；V1 §六 A 用 `unique(subset=[_symbol, OB_TIME], keep="first")` 去重——这是一个隐藏判断写进了提取器（选择 keep="first" 而非 "last"，无依据）。
- **修正**：在事件注册表之外先建一个**形状消歧层**（IO 层，与纯核事件注册表隔开）：(1) 09:30 / 13:00重复帧聚合为单一开盘快照，按"两帧价量一致"判同源，否则记入 ledger；(2) quote-only 标的的逐笔流空集 = 期望形态；(3) 救援日与非救援日的标的级单边缺失登记为日界事件旁的 gap_codes。该层产物是不可改的"shape-stable parquet"，是事件提取的唯一入口；事件注册表不知道也不需要知道 D013 / D008 / D011存在。

**11. V1 §L 唯一存活信号是因子而不是事件——注册表必须显式支持"事件缺位"作为一阶信号**
- **证据**：数据表 §六 L「**唯一 🟢 存活**：`net_hi_quiet ∧ max_abs_uq高`，early +2.79%/胜 71%，oos +0.58%/胜 51%」——这是一个跨多日的"安静 + 单点突变"复合，结构上是因子而非事件；简报 §2 四备选均假设事件是"反常时刻"，没有"持续无事件本身作为信号"的位置。
- **修正**：注册表须显式定义"事件缺位事件"或"日界事件属性"承载一段时期的统计描述，例如 `window_stats`字段记录该标的当日事件总数、跨度、稀有事件有无，让因子层能从日界事件上直接读到 V1 §L 的几何，而不是反过来要求因子层维护一份事件流索引。

**12. (元层面) 简报没有把"事件注册表的污染级别"机制纳入**
- **证据**：CONTEXT.md「**对照裁决**：每个 sprint 引入一个**不知道项目历史的异构 agent**独立出裁决……结果**不与项目内裁决合并**……只报告一致性差异」；CONTEXT.md「每个假设必须声明污染级别」。简报 §4 没有出现"污染级别"四字。
- **修正**：注册表的每一条种子条目必须带三个污染级别字段：(i) 注册表作者是否读过 V1 该几何的同源结论；(ii) 提取器代码作者是否读过；(iii) 因子层最可能的消费者是否读过。三档全空 = 真正盲；任一有读 = 写明读过什么、决定如何避免被污染。证据指纹绑这三档声明。
