总判：不得合并；当前设计的“fail-loud / 原子写 / 可复现”有可直接打穿的路径，且会产生静默错误结果。

【致命】

1. 证据：`src/ftbv2/core/raw/plan.py:27-28` 写明有 `symbols` 时只选 statistics 相交的 row group，且“无 statistics 永不入选”；`src/ftbv2/io/raw/store.py:133-135` 对非空但无 stats 的 row group 返回 `("", "")`。
攻击路径：构造或迁移一个 `_symbol` 无 statistics 的非空 parquet。请求 `symbols={"000001.SZ"}` 时 `_select_row_groups` 不会选中该 row group，随后 `attribute_gaps` 会报 `SYMBOL_ABSENT`，真实数据被静默裁掉。
修正：`catalog()` 遇到非空 row group 缺 `_symbol` stats 必须 `RuntimeError(day, stream, row_group)`；或计划退化为全 row group 读取并设置 `pruned=False`。门禁加“非空无 stats parquet + symbol 查询不得返回 absent”的夹具。

2. 证据：`src/ftbv2/io/raw/ingest.py:10-11` 承诺违规时“root 无任何改动”；但 `src/ftbv2/io/raw/ingest.py:82-89` 先写三个 stream 再写 manifest，`src/ftbv2/io/raw/ingest.py:278-286` 每个 stream 单独 `os.replace`。
攻击路径：让第三个 stream 写入或 manifest 写入时磁盘满、权限变更或进程崩溃。root 中会留下 1-3 个新 parquet、无 manifest 或旧 manifest，读路径可能把半成品当天纳入 `days()` 或读取到混合状态。
修正：引入 day 级 ingest lock；所有输出写入同一 staging 目录，校验三 stream 和 manifest 后一次性发布 commit marker；`days()` 只承认有效 manifest + 三个文件哈希匹配的天。失败清理 staging，绝不发布部分 parquet。

3. 证据：`src/ftbv2/io/raw/ingest.py:62-68` 幂等返回只比 `archive_sha256` 和 `prefixes`；`src/ftbv2/io/raw/ingest.py:110-114` manifest 记录 `parquet_bytes`，但没有 parquet sha256、schema 版本、writer 版本哈希。
攻击路径：manifest 写好后替换某个 parquet 内容，或用不同 pyarrow/polars/ROW_GROUP_ROWS 重写同样 archive。再次 ingest 会直接返回旧 receipt，读取层也不会发现数据产物已漂移。
修正：manifest 每个 stream 记录 `parquet_sha256`、`num_rows`、`row_group_rows`、物理列列表、writer 版本、schema/FIELDS 哈希；幂等返回前必须校验目标文件存在且哈希一致。读结果证据指纹至少绑定 parquet sha + ledger sha + schema hash。

【严重】

1. 证据：`src/ftbv2/io/raw/ingest.py:136-140` 调 `7zz` 无 timeout；`src/ftbv2/io/raw/ingest.py:183-184` 整包解压；`src/ftbv2/io/raw/ingest.py:242` 每个 CSV `read_bytes()`，`src/ftbv2/io/raw/ingest.py:256` 再整体 concat。
攻击路径：归档炸弹、超多小文件、超大 CSV 或挂起的 `7zz` 可耗尽磁盘、内存或进程池，导致失败级联到同机其他任务。
修正：读取 `7zz l -slt` 的 `Size/Packed Size` 做上限判定；限制文件数、总解压字节、单 CSV 字节、符号数；`subprocess.run(..., timeout=...)`；CSV 分块写 parquet，禁止全量 concat。

2. 证据：`src/ftbv2/io/raw/ingest.py:217` 只用 `symbol.startswith(prefixes)`。
攻击路径：目录名 `000BAD`、`000001.SH.bak`、`000001` 都可通过前缀筛选并写进 `_symbol`，污染 row group stats 与下游 `SYMBOL_RE` 契约。
修正：摄取入口用同一判据 `^\d{6}\.(SZ|SH)$` 校验 symbol；再用 `symbol[:3] in prefixes` 判断样本宇宙；非法 symbol 直接 `RuntimeError`。

3. 证据：`src/ftbv2/io/raw/ingest.py:247` 只保留第一个 header；`src/ftbv2/io/raw/ingest.py:252` 每个文件按自己的 `len(header.split(","))` 解析。
攻击路径：同一 stream 中某个标的 header 字段顺序变化但列数相同，会被统一改名为 `column_N` 后 concat，语义列静默错位。
修正：同一 stream 内所有 `header_bytes` 必须逐字节一致；不一致时报 `RuntimeError(stream, symbol, expected_header_sha, actual_header_sha)`。如允许漂移，manifest 必须按 symbol 记录 header 并禁止合并为同一语义表。

4. 证据：`src/ftbv2/io/raw/ingest.py:266` 使用 `encoding="utf8-lossy"`；对象 docstring 却写 `CSV：GBK 表头一行 + 纯 ASCII 数据行`。
攻击路径：数据体出现非法字节会被替换字符吞掉，行数仍可能匹配，`sha256_csv` 绑定的是原始 body，但 parquet 已经是损坏后的 lossy 结果。
修正：body 先按 ASCII strict 校验，或按明确编码 strict 解析；任何替换字符路径都必须硬失败。门禁加非法字节 CSV 应失败的测试。

5. 证据：`src/ftbv2/core/raw/decode.py:33-38` 只对 `^[+-]?\d+$` 做精度丢失检查。
攻击路径：科学计数法或小数字符串的大整数值可经 Float64 舍入后 cast 成错误 Int64，而不会触发 `loses_integer_precision`。
修正：对所有可接受数值文本用 `Decimal` 或 Arrow decimal 做精确整数判定；指数/小数形式必须满足 `Decimal(raw) == Decimal(candidate)`，否则 null 或硬失败，接口判据固定下来。

6. 证据：`src/ftbv2/core/raw/plan.py:38-45` 没有校验 `catalog.stream == request.stream`。
攻击路径：调用方把 trades 的 catalog 传给 orders request，计划会按 orders schema 解 trades 文件；列号重叠时不会立刻失败，只会产生语义错误。
修正：`plan()` 开头增加 `if catalog.stream != request.stream: raise ValueError(...)`；门禁加跨 stream catalog 误用测试。

7. 证据：`src/ftbv2/io/raw/store.py:97-98` 写明 `inspect_raw` “不经 schema、不经账本、不经计划”，且“import-linter 契约待加”。
攻击路径：两个月后因子/事件代码直接调用 `inspect_raw` 绕过 time_6digit、字段登记、Gap 归因和质量分档；门禁尚未存在，绕过只能靠事后数据异常发现。
修正：把 `inspect_raw` 移到 debug/tools 专用模块，生产包不导出；立即加 import-linter 规则禁止 `ftbv2.features/events/core` 依赖 `ftbv2.io.raw.store.RawStore.inspect_raw`，CI 失败信息列出违规 import。

【建议】

1. 证据：`src/ftbv2/io/raw/ingest.py:206` 只遍历 `scratch.rglob("*.csv")`。
攻击路径：归档中夹带非 CSV 文件会通过摄取审计，既不入 manifest，也不入 `sha256_csv`，后续无法证明归档内容是否被完整解释。
修正：遍历全部 extracted files；除期望的三类 CSV 外一律 `RuntimeError`，或 manifest 记录 ignored files 的路径和哈希并要求为 0。

2. 证据：`src/ftbv2/io/raw/ingest.py:138` 直接执行 `["7zz", ...]`，manifest 只记录 `sevenzip_version`。
攻击路径：PATH 被污染时可执行伪造 `7zz`；同一版本字符串的不同二进制也不可区分。
修正：配置绝对 `sevenzip_path`，启动时 `resolve(strict=True)`；manifest 记录 `sevenzip_path` 与二进制 sha256；CI/运行时校验允许列表。

3. 证据：`src/ftbv2/io/raw/store.py:80` 未登记短时间只在 `time_column in raw.columns` 时检查；docstring 也承认“只对本次投影实际读到的时间列检查”。
攻击路径：请求不含 `time_ms` 且无 windows 时，可读取未登记 time 形状的同日其他字段，绕过 fail-loud 门禁。
修正：摄取或 catalog 产出 per-file shape summary，例如 `has_short_time`；execute 不依赖投影列，发现未登记即失败。若坚持投影内检查，接口文档必须把该门禁降级为“条件检查”，不能宣称未登记形状一律硬失败。

裁决：不得合并
