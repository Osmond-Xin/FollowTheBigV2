总判：这份简报还不能进注册表，最大问题不是选 B/C/D，而是版本血缘、前视门禁、资源上限和异常形状都没有可执行判据。

【致命】

1. 事件流版本内容寻址不完整  
证据：“事件流版本 = 注册表版本 + 提取参数集 + 原始层数据清单 的内容寻址。”  
攻击路径：同一注册表、同一参数、同一“原始层数据清单”，换 extractor 代码、依赖版本、交易日历、时区、排序/去重规则、枚举空值归一化规则，都能产出不同事件流，但版本号不变，无法复现也无法追责。  
修正：事件流版本必须绑定 `registry_hash`、`param_hash`、`raw_manifest_hash`、`extractor_git_sha`、`container_image_digest`、`lockfile_hash`、`calendar_version`、`timezone`、`schema_hash`、`normalization_policy_hash`、`sort_dedup_policy_hash`、`output_manifest_hash`。缺任一项不得发布。

2. 前视口径只“声明”，没有机器门禁  
证据：“当日自身（事后，日内前视，适合 T+1 信号但必须声明）”；“注册表必须把口径写成参数，因子层不得混用。”  
攻击路径：把“当日自身 p90”事件流喂给盘中秒级因子，因子层看到的分位实际来自收盘后，回测收益被污染；因为只是文字声明，消费端可以绕过。  
修正：注册表字段增加 `availability_time`、`reference_window_end`、`lookahead_class: PIT | EOD | CROSS_SECTION_EOD`。因子消费接口必须传入 `decision_time`，门禁规则为 `event.availability_time <= decision_time`，否则硬失败并记录审计日志。

3. “事件不含判断”无法机械验证  
证据：“分位候选 + 全量度量”；“松分位”；“切割规则本身也有参数（N、k、m）”。  
攻击路径：把判断阈值改名成“松分位”“最小持续时长”“连续递交 k 次”写入提取器，就绕过“判断只在因子层”的门禁；两个月后注册表会堆满事实上的 alpha 判断。  
修正：给注册表加 `parameter_role` 枚举：`structural_partition | sampling_resolution | candidate_recall_gate | decision_threshold`。门禁判据：任何直接决定事件是否存在、且调紧会单调减少候选数量的参数，必须标记为 `candidate_recall_gate`，并要求登记召回覆盖率实测；`decision_threshold` 禁止进入提取器。

【严重】

1. 资源耗尽没有上限和失败语义  
证据：“宽的代价是体积”；“段太多时体积不可控”；“17 亿行 × K 列，K = 20 时 zstd 后估 30–40 GB，内置 SSD 只剩 148 GB”。  
攻击路径：把分位放宽、K 增大、段切割参数调小，输出爆炸；17 小时任务跑到末尾磁盘写满，留下半成品，被下游当完整事件流消费。  
修正：注册表必须包含 `max_rows_per_symbol_day`、`max_bytes_per_trading_day`、`max_total_bytes`、`spill_policy`。提取输出采用两阶段提交：写入临时目录，生成 `output_manifest` 和完整性校验后原子发布；超过预算硬失败，不发布版本。

2. 日界事件与缺口只有不变量，没有生成规则  
证据：“每 (标的, 交易日) ≥ 1 条日界事件；安静 ≠ 缺口。”；“日界事件与缺口在各备选里怎么产生。”  
攻击路径：停牌、半日市、原始数据断流、空表、重复开盘帧都可能被误写成“安静日”；因子层无法区分无异常和数据缺失。  
修正：定义系统事件接口：`DAY_OPEN`、`DAY_CLOSE`、`TRADING_HALT`、`NO_RAW_DATA`、`RAW_GAP`、`HEARTBEAT_ONLY`。每个 `(symbol, trading_day)` 必须有 `coverage_status`，判据绑定交易日历和原始流覆盖率，低于阈值不得标记为安静。

3. 已知脏数据形状没有归一化契约  
证据：“开盘重复帧（09:30 / 13:00 两帧）、停牌心跳、6 位时间两天、枚举空值 ' ' / '' / null。”  
攻击路径：6 位时间跨日解析错位，重复帧双计，空字符串和 null 分桶不同，停牌心跳制造伪连续段，直接污染 uq、hqa、ac、冰山重复递交等事件。  
修正：RawStore 到事件提取之间必须有 `canonical_tick_schema`：时间字段必须解析成带交易日的 `event_ts`；枚举空值统一成 typed null；重复帧规则明确 `keep_first | keep_last | aggregate | mark_duplicate`；停牌心跳必须带 `is_heartbeat` 并默认排除出连续性判据。

4. 并发与增量重跑语义缺失  
证据：“提取一次约 17 小时”；“几个月跑一次”。  
攻击路径：长任务中途 RawStore 追加、修正或压缩文件，前半段读的是旧数据，后半段读的是新数据；同一版本内混入两个 raw snapshot。  
修正：提取启动前生成不可变 `raw_snapshot_id`，绑定每个文件的 path、size、mtime、checksum、row_count。读取时二次校验；任何文件变化立即失败。

【建议】

1. 依赖与供应链没有门禁  
证据：简报只提“内容寻址”，未提 extractor 依赖、运行镜像、压缩库、解析库。  
攻击路径：zstd、parquet/arrow、pandas/numpy 版本变更导致压缩、排序、浮点分位插值不同；同一数据重跑不一致。  
修正：提取器必须用锁定镜像运行；版本 manifest 记录 `image_digest` 和 `dependency_lock_hash`；CI 加一组 golden raw fixtures，要求输出 hash 稳定。

2. 浮点与分位定义未固定  
证据：“本股当日 p90”；“松分位（如 p95）”。  
攻击路径：不同库的 quantile 插值、NaN 处理、空样本处理不同；边界值刚好等于分位时事件是否进入不一致。  
修正：注册表字段固定 `quantile_method`、`nan_policy`、`empty_sample_policy`、`tie_policy`、`comparison_operator`。例如 `method=nearest_lower`、`empty=NO_EVENT_WITH_COVERAGE_FLAG`、`operator=>`。

3. 两个月后的退化路径很清楚：注册表会变成硬编码策略仓库  
证据：“第一批种子事件（假墙 / 冰山 / 隐藏深度 / 成交量时钟）”；“V1 的 0.5 是硬编码字面量”。  
攻击路径：为了追求召回和体积，团队会不断把因子判断前移到提取器，用“候选”“结构参数”包装阈值，最终 17 小时重跑层承载策略逻辑。  
修正：每条注册表条目必须通过 `judgment_lint`：检查名称、参数、说明是否含方向性判断词；检查参数是否决定 alpha 通过/失败；新增条目必须给出“因子层还能调紧哪些字段”的消费接口。

裁决：不得合并
