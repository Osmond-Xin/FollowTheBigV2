# 门禁清单（实测验证版）

> 过程文档。实现为 `pyproject.toml` / `setup.cfg` / `tools/` / `.github/workflows/` 后归档。

## 0. 最重要的一条实测发现

**import-linter 无法实现「不得跨模块 import 私有符号」。** 它是**模块粒度**的；对
`from qr.util.math import _internal_thing` 实测退出码 **0（放行）**。ruff 的 `PLC2701` 只对**第三方**包
生效，对项目内 import 任何配置下都不触发；pylint 的 `private_import` 扩展同样豁免第一方。

**⇒ 这条约束没有现成工具，必须自带约 25 行 AST 检查。** 用它扫 V1 的 `src/`，**当场命中 3 处**：

```
src/followthebig/features/factor_primitives.py:17  private name `_i64` from `followthebig.data.preserve_schema`
src/followthebig/research/sss_event_family.py:30   private name `_i64` from `followthebig.data.preserve_schema`
src/followthebig/research/sss_event_family.py:30   private name `_hhmmssmmm_to_ms` from `followthebig.data.preserve_schema`
```

即：V1 唯一的深模块被**三处**跨模块引用私有符号捅穿，比此前发现的一处更严重。

## 1. 门禁清单（按性价比排序）

| # | 门 | 工具 | 跑在哪 | 防住 | **防不住** |
|---|---|---|---|---|---|
| 1 | 结构复杂度 | ruff 0.15+ | CI + 本地 | 分支爆炸、参数膨胀、嵌套过深、私有属性访问 | 语义错误、数据正确性、跨函数复杂度（拆函数即绕过）|
| 2 | 分层/依赖方向 | import-linter 2.14 | CI | 核心层反向依赖 IO、循环依赖、禁用包泄漏 | 符号粒度、动态 import |
| 3 | **私有符号跨模块 import** | **自带 AST 脚本** | CI + 本地 | **深模块被捅穿** | `getattr`、`importlib` |
| 4 | 增量覆盖率 | diff-cover | CI（仅纯逻辑核）| 新代码裸奔 | 无断言测试；IO 半完全不适用 |
| 5 | 金标准回归 | 自建 + pytest | 本地（IO 半唯一有效门）| 数值漂移、口径变更、前视偏差 | 全新代码路径 |
| 6 | 契约/血缘校验 | 自建 | CI（小样本）| schema 漂移、列语义错配、PIT 违规 | 值域外的业务错误 |
| 7 | 死代码/依赖 | vulture / deptry | CI | 幽灵代码、缺失依赖 | — |
| 8 | 变异测试 | mutmut / crapkit mutate | 本地 nightly，仅核心 | 「跑了但没断言」 | 慢 |
| ❌ | Maintainability Index | — | — | 实测 V1 的 51 个文件里 50 个 A 级，**永不触发** | 一切 |

## 2. 关键配置要点

**ruff**：`preview = true`（`PLC2701` 需要）。
**⚠️ 最常见误配：`max-complexity` 若不显式设置，`C901` 不报错也不警告，直接静默失效。**

```toml
[tool.ruff.lint]
select = ["C901","PLR0911","PLR0912","PLR0913","PLR0915","PLR0916","PLR1702",
          "SLF001","PLC2701","ERA001","TID252"]
[tool.ruff.lint.mccabe]
max-complexity = 10
[tool.ruff.lint.pylint]
max-branches = 12; max-statements = 50; max-args = 6; max-returns = 6
max-bool-expr = 5; max-nested-blocks = 4
```
IO 半用 `per-file-ignores` 豁免规模类规则，但**保留 `SLF001` / `PLC2701` / `ERA001`**。

**import-linter**（`setup.cfg`）：必须加 `include_external_packages = True`，否则禁外部包会直接报错退出。
契约类型用 `forbidden`（纯逻辑核禁 import IO 与 duckdb/requests/os/pathlib，`allow_indirect_imports = False`）
+ `layers`（分层方向）+ `independence`（同级子包互不依赖）。它最有价值的输出是**间接链路**：

```
followthebig.features is not allowed to import duckdb:
-   followthebig.features.x -> followthebig.data.loader (l.2)
    followthebig.data.loader -> duckdb (l.1)
```

**私有 import 检查脚本**（纯 stdlib，实测 4/4 命中、0 误报）：
遍历 AST，对 `Import` / `ImportFrom` 判断被引名或模块路径中是否含私有成分（`_x`，dunder 除外），
并检查引用方是否在该私有符号的**属主包**内。相对 import（`node.level > 0`）视为同包，放行。
配套 ruff `SLF001` 拦 `obj._private` 属性访问——一个管 import，一个管访问。

| 写法 | 结果 |
|---|---|
| `from qr.util.math import _internal` / `... as ok` | ❌ 拦（别名不逃逸）|
| `from qr.util._secret import thing` / `import qr.util._secret` | ❌ 拦 |
| `from qr.core._helpers import _local`（同包）/ `from . import _sibling` | ✅ 放行 |
| `from typing import __all__`（dunder）| ✅ 放行 |

## 3. CI 跑不了 TB 数据：收据机制（这一条解决 Q14）

CI 硬拒的都只需源码 + fixture（秒级）：ruff / 分层契约 / 私有 import / 契约登记完整性 /
小样本金标准 / 增量覆盖率（仅纯逻辑核，`--fail-under=90`）。

必须留本地：全量 TB 重建、真实金标日对账、回测全跑、变异测试。

**让本地那部分绕不过 = 收据 + CI 校验**：

```python
# tools/emit_receipt.py —— 本地重活跑完后写收据，提交进仓库
receipt = {"commit": git_head(),
           "tree_sha": git_tree_sha("src"),      # 只对 src/ 的树哈希，改文档不失效
           "ran_at": time.time(),
           "golden_days": GOLDEN_DAYS_SHA,
           "backtest_sha": sha256(backtest_output)}
receipt["sig"] = hmac.new(SECRET, canonical_json(receipt).encode(), "sha256").hexdigest()

# tools/verify_receipt.py —— CI 跑，不需要任何数据
assert hmac.compare_digest(r["sig"], resign(r)),        "收据签名无效"
assert r["tree_sha"] == git_tree_sha("src"),            "src/ 变了但重活收据是旧的"
assert time.time() - r["ran_at"] < 7*86400,             "收据超过 7 天"
```

**效果**：改了 `src/` 却没跑本地重活 → tree_sha 不匹配 → CI 拒绝，且 CI 无需碰 TB 数据。
绕过 pre-commit 无用，因为强制点在 CI。

## 4. IO 半的三个替代门（覆盖率在这里无意义）

- **金标准回归**：对 1 个交易日的小样本跑完整管道，比对冻结的输出 sha256。
  **关键：`regen_golden.py` 必须强制要求 `--reason` 并写入 ledger**，否则「重新生成金标准」变成一键绕过。
- **契约测试**：`Contract(columns, not_null, ranges, unique, asof_rule="date <= as_of")`；
  CI 用 fixture 小样本跑；配一条 `test_every_live_output_has_a_contract`（有 live 产物未登记契约即失败）。
- **血缘 / PIT 校验**：`test_no_lookahead_in_feature_graph`（每个特征的输入时间戳必须 ≤ 自身）、
  `test_every_live_column_is_in_semantics_registry`。

## 5. 若保留 CRAP：只用 crapkit，且只用 ratchet 模式

| | crapkit 0.4.11 | crap4py 0.1.1 |
|---|---|---|
| 无覆盖数据时 | **按 cov=0 计（正确）** | **按 100% 覆盖计（漏洞）** |
| 文件不在报告里 | 三种 flag 区分，均计 0 | **直接跳过门禁** |
| baseline/ratchet | **有** | 无 |
| CC 引擎 | lizard（维护中）| 自写 AST |
| 发布数 / 文档 | 14 / handbook+changelog | 1 / 无 |

配置要点：`[[scope]]` 是**单数**；`target` 默认是 6，要显式设回 30；IO 半用 `coverage_optional = true`。
命令序：`inventory` → `coverage` → **`ratchet seed`（冻 baseline）** → `verify`。
**绝不要一上来就开绝对阈值。**

**⚠️ 不同 CC 引擎口径不同**：实测同一函数 radon=56、ruff/mccabe=19。硬门禁必须先确认锚在哪个数上。

上线前必验 5 点：无覆盖数据的函数是否真按 cov=0 计 / `coverage.py >= 7.13.1`（否则函数区间错位）/
lizard 与预期 CC 是否一致 / `coverage_optional` 的 io scope 确实不因缺覆盖率失败 / ratchet marks 已提交且被读取。

降级序：crapkit 只留 `inventory`+`worklist`（报表用）→ xenon（radon 系，`radon` 本身永远 exit 0，
只能当数据源）→ 只留 ruff `C901` + `PLR09xx`（零新增依赖）。

## 6. 落地顺序

```
1. ruff 配置（IO 半 per-file-ignores 豁免规模规则）
2. check_private_imports.py 进 tools/
3. setup.cfg 分层契约（先 report 模式，再开 exit 1）
4. .github/workflows/gate.yml + 收据机制  ← 这一步才让本地重活绕不过
5. 纯逻辑核接 diff-cover --fail-under=90
6. （可选）crapkit：先 inventory/worklist 观察，再 ratchet seed，最后才 verify
```

**未实测**：金标准 / 契约 / 血缘 / 收据四段是设计骨架，非跑通代码，依赖管道形态。
