总判：这份方案门禁方向、信任边界、血缘绑定都不够硬，最危险的是它会很快演化成“生成器和模型替人裁决”。

【致命】

1. 证据：`design-log 顶层文件数 ≤ 30 即红`、`docs/ 总词数 ≤ 5 万即红`  
攻击路径：阈值方向写反，正常小仓库会立刻红；团队会第一时间关掉这两条门禁，随后文档膨胀和日志堆积重新失控。  
修正：判据改为 `design-log 顶层文件数 > 30 fails`、`docs/ 总词数 > 50000 fails`，并在 CI 测试里放边界用例：`30 pass / 31 fail`、`50000 pass / 50001 fail`。

2. 证据：`CI 重新生成后与仓库 HTML 逐字节 diff，非空即红`、`生成器 tools/render_docs.py`  
攻击路径：只要手改生成器，就能让任意 HTML 输出变成“合法生成结果”；逐字节 diff 只证明生成器自洽，不证明来源可信。  
修正：生成器必须输出 provenance block：源文件路径、源 commit hash、输入内容 hash、生成器 hash；CI 校验 HTML 中的 provenance 与当前 `ledger/`、`CONTEXT.md`、模块 `__init__` 实际 hash 一致。生成器变更必须触发专门 reviewer 或 CODEOWNERS。

3. 证据：`docs/STATE.md = 唯一的「现在在哪、卡在哪、下一步」页，唯一裁决`、`STATE.md 草案 ... 以 PR 提交，人合并`  
攻击路径：MiniMax 从日志中读到未裁决事实、旧事实或提示注入，把它写成 STATE.md；人审 PR 容易只看文本流畅性，合并后未裁决内容变成“唯一裁决”。  
修正：STATE.md 不允许自由事实句，必须是结构化条目：`decision_id | status | source_ref | source_hash | decided_by | decided_at`。CI 要拒绝没有来源 hash、没有裁决状态、引用 design-log 但未落账本/代码/活文档的条目。

4. 证据：`账本 append-only：已存在条目的 id / code / days 只能增不能删改（与预注册同一纪律，git diff 门禁）`  
攻击路径：用 rename、重排 TOML、squash/rebase、改基准分支、拆文件、改 `structural` 字段、滥用新 id 替代旧 id，都能绕过“只看 git diff”的 append-only。  
修正：用语义校验，不用文本 diff。CI 从 `origin/main` 读取上一版账本，按稳定主键 `id` 比较 JSON-normalized AST；禁止删除 id，禁止改 `code/kind/stream/evidence/created_at`，`days` 只允许集合并集；废弃只能通过 `superseded_by` 指向已存在 id，且原条目保留。

【严重】

1. 证据：`仓库出现 scripts/ bin/ notebooks/ 目录即红`、`tools/ 是唯一放可执行入口的目录`  
攻击路径：可执行入口可以藏在 `src/*/__main__.py`、`Makefile`、`pyproject.toml [project.scripts]`、GitHub Actions inline bash、`docs/*.ipynb`、`scratchpad` 子目录、带 shebang 的任意 `.py`。目录名门禁挡不住入口泛化。  
修正：CI 扫描全仓：shebang、可执行 bit、`if __name__ == "__main__"`、`argparse/click/typer`、`project.scripts`、workflow `run:`。除 `tools/manifest.toml` 登记入口外全部 fail。

2. 证据：`scratchpad 探针允许存在但不入库；跑第二次即必须工具化`  
攻击路径：“跑第二次”不可观测；探针可在本地反复跑，最后只提交结果。两个月后会退化成“不可复现结论 + 干净仓库”。  
修正：任何进入账本/数据表/design-log 的数字必须带 `receipt_id`，receipt 包含命令、工具版本、输入 hash、输出 hash、运行时间。没有 receipt 的事实不得落地。

3. 证据：`每个 tools/*.py 至少被一条测试引用`  
攻击路径：测试里 `import tools.foo` 就满足“引用”，但不执行 CLI、不覆盖参数、不验证输出；工具实际坏掉仍过门禁。  
修正：判据改为每个工具必须有 smoke test 调用公开入口，例如 `python -m tools.foo --fixture ... --out ...`，断言 exit code、输出 schema、关键字段、幂等二次运行。

4. 证据：`tools/ 单文件 ≤ 300 行`、`单文件 > 400 行由 crapkit ratchet 拦`  
攻击路径：逻辑拆成多个 299 行文件或塞进 `src` 私有 helper，复杂度不降；行数门禁会驱动横向扩散。  
修正：增加复杂度和依赖判据：入口文件只允许参数解析、IO 编排、调用 `src` 公开 API；工具目录禁止新增非入口 helper，公共逻辑必须在 `src`，并由 import-linter 验证依赖方向。

5. 证据：`只 import src 的公开接口（私有 import 门禁已有）`、`跨模块只能从包顶层 import`  
攻击路径：Python 私有接口只是命名约定；可通过 `importlib`、相对路径、修改 `sys.path`、动态 getattr 绕过。  
修正：CI 用 AST 禁止 `importlib.import_module("src...")`、`sys.path` 修改、从 `src.*._*` 导入、跨包深路径导入；运行时可选加 `pytest` import smoke，确保工具只依赖 `__all__` 暴露名。

6. 证据：`scan_shapes.py（全语料形状扫描 → TSV，可续跑）`、`ingest_days.py（... 幂等、逐日日志）`  
攻击路径：没有定义 checkpoint、锁、部分输出原子性。并发 CI 或本地重复跑会产生半写 TSV、重复日志、跳过坏文件后仍给成功状态。  
修正：接口定义必须包括 `--input-root --output --state --lock-file --fail-on-skipped`；输出先写临时文件再原子 rename；checkpoint 绑定输入文件 path、size、mtime、content hash；跳过文件计入非零 exit 或显式 receipt。

7. 证据：`非规范文件名跳过、磁盘余量下限、幂等`  
攻击路径：跳过非规范文件名可能悄悄丢数据；磁盘余量下限未定义单位和判据；幂等未定义“重复运行输出 hash 相同”。  
修正：跳过必须生成 `skipped.jsonl` 并使 CI fail，除非 skip code 已登记；磁盘下限使用绝对字节和百分比双阈值；幂等判据为相同输入 hash 下输出 manifest hash 完全一致。

8. 证据：`code 集合 ⊆ 代码枚举`  
攻击路径：只检查账本 code 被代码枚举覆盖，不检查代码枚举是否都有账本解释；代码里可新增未登记枚举绕过登记纪律。  
修正：除非显式 `legacy_allowed`，判据应为 `ledger code set == DefectCode set`；新增枚举必须同 PR 新增账本条目和测试。

【建议】

1. 证据：`用 MiniMax（CI 已有 key）读新日志`  
攻击路径：CI key 变成供应链单点；日志内容可携带提示注入，诱导模型输出错误归档移动。  
修正：模型输入只给纯文本抽取视图，剥离代码块和指令性文本；输出只允许 JSON schema；归档移动由确定性程序根据 `landed_refs` 判定，模型不得决定移动。

2. 证据：`README 只允许链接活文档`  
攻击路径：README 可变成“链接农场”，事实迁移到链接标题、锚文本或外链，门禁形式通过。  
修正：README 只允许固定模板和相对链接白名单；禁止外链事实标题；CI 对 README AST 做结构校验。

3. 证据：`docs/archive/YYYY-MM/`  
攻击路径：归档文件可继续被引用为当前事实，形成“死文档复活”；两个月后新旧事实混用。  
修正：活文档引用 archive 必须带 `historical` 标记；STATE.md 禁止以 archive 作为当前裁决来源。

4. 证据：`每条：id · code · kind ... evidence ... read_layer_action`  
攻击路径：缺少 `created_at`、`source_hash`、`observed_by_tool`、`schema_version`，同一 evidence 可被重写解释，复现链断。  
修正：账本条目增加必填字段：`schema_version`、`created_at_utc`、`source_artifact_hash`、`observed_by_tool`、`tool_version_hash`、`receipt_id`。

5. 证据：`docs/ 总词数 ≤ 5 万`  
攻击路径：词数门禁会诱导把长事实塞进图片、HTML 属性、压缩 JSON、外部链接。  
修正：同时限制仓库文档字节数、HTML text content、图片数量/大小、外链数量；外部事实必须有本地 receipt 摘要。

裁决：不得合并
