## 〇、等你裁的一件事：冰山切得太宽

`RefillAfterFill` 实测 **218.92 条/(标的·日)**，坍缩 268。
**三关全不过**：超单条上界 50、超整张表预算 100（它一条就超一倍）、坍缩不到下界 1000。
逐日 151–287，不是边缘情况。

数据在说的话：**每片量中位 = 100 股 = 一手**，而且**在每一个可见档位桶、每一个轮数桶里都是 100**。
一手的委托被吃掉、又来一笔一手的——连续竞价里每秒都在发生，
它不是「切片下单」，因为**一手是不能再切的**。55% 的候选只完成一轮，中位跨度 6.9 秒。

**假墙那一刀（十档内可见）拿到这里不管用**（我只量了，没改定义）：
只砍掉 52.5%（→ 104.00，仍超预算），而且**没有分开两类东西**——
十档内外的每片量中位都是 100、轮数中位都是 1，假墙那次两边差 3–10 倍。
可见性对假墙有效是因为「看不见的墙吓不到人」，那条结构的意义依赖被看见；
**冰山不依赖，藏起来才是它的意义**。同一把刀切不同结构，不该指望一样的效果。

四条路，都没实测，我不替你选（详见 `design-log/2026-09-03-冰山密度回归.md` 第五节）：

| | 做法 | 论证 | 风险 |
|---|---|---|---|
| **A** | 每片量不得是**最小交易单位（一手）** | 一手是交易所定的最小委托单位，与「十档是交易所定的发布范围」同构：**一手不能再切，所以一手的重复挂单不是切片的证据** | 形式对，但落在「量」这一维，容易滑成阈值 |
| B | 要求补单补回**同一个档位** | 存在性不是幅度 | 没量过，可能砍不动 |
| C | 要求本组期间该档位**没有别人的委托进出** | 存在性 | 会把真冰山也砍掉 |
| D | 承认它不是稀有结构，改 `event_class` | —— | 一天几十万条，预算重算 |

⚠️ **「轮数 ≥ 3」不是路。** 条目自己写着「一轮即成立，≥ 3 才是判断，归因子层」；
把 k 从 10 改成 3 正是 V1 §C 的错误（`REP_MIN=10` 是错代理，96% 的触发来自它），
本条目的 `v1_audit` 就是为这件事写的。

**合计准入现在过不了**（3.68 + 32.68 + 218.92 = 255.28，预算 100），所以还进不了全量提取。

## 一、上个 session 末尾裁的两件事（已落地）

### 1. 隐藏深度没通过准入 → **动上界**（动的是它的出处）

`FillExceedsDisplayed` 实测 **32.68 条/(标的·日)** 撞上了当时的上界 30。
**这是准入机制第一次真的拦下一条条目**，它拦对了。

裁决是动上界。落地时动的不是数字，是把这个数第一次**推出来**——
原来的「10–30」写在一句项目背景里，没有推导过程（红队方法论致命 1 已判过它）：

```
事件层常驻预算 8 GB ÷ 每行约 25 字节 ≈ 3.44 亿行
÷ (约 3000 主板标的 × 1122 个交易日) ≈ 102 条/(标的·日)   ← 整张表合计
```

⇒ `REGISTRY_ROW_BUDGET = 100`（合计），单条上界 50 = 预算的一半，只防「一条吃掉半个预算」。
**两个输入都是估算并如实标注**：8 GB 数据表已注明未实测，25 字节/行也没实测过——
所以 100 是一个**预算分配决定，不是一个测量结果**。

同时把真正的约束移到了合计上（`admit_registry()`），且**未实测的条目让它拒绝**：

| 条目 | 实测 | |
|---|---:|---|
| 假墙 | 3.68 | ✅ |
| 隐藏深度 | 32.68 | ✅ |
| 冰山 | 未测 | ⛔ 合计准入因此拒绝 |
| **已测合计** | **36.36** | 剩给冰山 63.64 |

⚠️ **这次改动没有解决「隐藏深度在小档位上退化成噪声」。**
候选的展示量中位 800 股（全部帧×档位是 16,400 股）这个事实没变，只是它不再撞成本闸。
成本闸问的是「装不装得下」，而「这批候选里有多少真是暗单」是**结构问题**。
**别因为准入过了就当它解决了**，见 `design-log/2026-09-03-隐藏深度密度回归.md` 第三节末。

### 2. 对照裁决强度不够 → **改词汇表的定义**

原定义只写了对**假设**的对照裁决（要求 agent 不知道项目历史），把注册表条目套进去
会得出「三方红队不算对照」这种错判。现在 CONTEXT.md「对照裁决」条分两类写：

- **对假设 —— 要求盲**：不知道项目历史，不知道 V1 结论。裁决的是「这个结论成不成立」。
- **对注册表条目 —— 要求异构，不要求盲**：独立 agent · 独立上下文 · 独立判据，
  但允许知道项目历史。理由：判断一条切割规则是不是过滤、会不会在集合竞价爆量、
  排序键靠不靠得住，**必须懂业务上下文才审得动**——把 CONTEXT 藏起来只会换来
  一份看不懂对象的评审。

两类都不叫「盲验」。第一批四条挂的三方红队按第二类成立。

### 隐藏深度的候选生成器 + 密度回归收成一个入口

`core.book.frames`：帧间比对（展示量 → 成交 → 新增委托 → 幸存量），8 条契约测试。
`io.events` 收成一个入口 `probe(store, ledger, kind, days, ...)`，
候选表怎么生成由 `_BUILDERS` 按 kind 取——加一条新事件是加一个生成器，不是抄一遍文件。
工具 `tools/probe_walls.py` → `tools/probe_density.py`（`--kind` 选条目）。

**红队那第三个角色被量出来了**：不加「两帧之间无新增委托」，
111.7 万 → 13.9 万，**砍掉 87.5%**。也就是说八成八的「隐藏深度」其实是三秒里价格穿过该档
之后被新挂单重新撑住。红队这条不是推测，是真的。

## 五、坑（在上一份的基础上补充）

- **跑实测的时候不许碰工作区。** 我犯了一次：第一趟 21 天实测跑到一半时改了 CONTEXT.md
  与 seeds.py 的注释，收据 `source_dirty = true`，按规矩不算证据，只能删掉重跑。
  一趟 21 天要 11–12 分钟，等得起，别边跑边改。
- **「查不到 = 没有」在代码里比在纸上难认。** 这个 session 撞了两次，两次都是同一形态：
  ① `probe` 把 `res.gaps` 整个丢掉，于是「没有快照可比」与「档位不在十档内」都变成 `level = null`；
  ② 零候选的实测本来会通过准入（坍缩比是无穷大）。两处都已改成硬失败。
- **适用时段不许下推到读取层。** 日内型提取器的盘口深度必须从开盘累积，
  把窗下推给 `ReadRequest` 会裁掉集合竞价里挂下的委托，它们的撤单就找不到档位——
  实测表现是 `unlinked_cancels` 从 0.041% 跳到 1.31%。**窗约束的是产出，不是读取。**
- **词汇门禁还在飘，未修。** 这个 session 两种失败模式各撞一次：
  ① 同内容一次报 4 处冲突、重跑通过；②「判定输出不是合法 JSON」。**重跑即过**，
  但这是硬门禁，CI 可能红在上次绿过的 commit 上。
  修法：判定输出加 schema 校验 + 重试；「判定不可用」与「判定为冲突」分不同退出码。
- **红队的数字要验。** agy 估假墙 500–1500 条/(标的·日)，codex 估 100–1000，实测 43 / 3.68。
  它们的**方向**这次全对（三条要改的都真该改），**量级**全错。
- **我们自己的数字也要验，而且要说清楚量的是哪一边。** 上一版记的「上交所关联率 57%」
  数字没错，错在它是**混了主被动的聚合**，而冰山要的是**被动方**那一边（99.9%）。
  由此得出的「冰山在上交所不可靠」被推翻。**一个比率必须说清楚分子分母各是什么**——
  否则它会回答一个你没问的问题，而你不会发现。
- **一把好用的刀不会到处好用。** 可见性把假墙的两类形态完全分开（差 3–10 倍），
  拿到冰山上只砍掉一半、且两边没有差别。因为假墙的意义依赖被看见，冰山的意义是藏起来。
  **搬经验之前先量一量**。
