## 一、等你裁的两件事（**开工前先看这里**）

### 1. 隐藏深度没通过准入，怎么办

`FillExceedsDisplayed` 实测 **32.68 条/(标的·日)，超过上界 30**（坍缩比 1,793 过关）。
逐日 26.1–39.6，不是某天爆量，是整体就在上界附近。

数据在说的话：**候选的展示量中位只有 800 股**，而全部帧×档位是 16,400 股。
这批「隐藏深度」绝大多数发生在**八手的小档位**上——档位越小越容易被一笔单吃穿，
「成交 ≥ 展示量」几乎自动成立。结构本身没错（幸存确实是隐藏的证据），
但**它在小档位上退化成了噪声**。

规矩说这时**回到设计，不是把上界调成能过**。三条路，我没替你选：

| | 做法 | 代价 |
|---|---|---|
| A | **接受它不是稀有结构**，`event_class` 改成尺子 | 事件流一天约十万条，成本口径要重算 |
| B | **再加一个结构角色**（必须是结构不是幅度）。想得到的：该档位随后连续 N 帧持续幸存；或两帧之间被吃穿不止一次 | 两个都还没实测，得再跑一轮 |
| C | **动上界** | 按红队方法论严重 4，得先把「10–30」本身写成一条预注册的假设。**最像捷径，也最危险** |

详见 `design-log/2026-09-03-隐藏深度密度回归.md` 第三节。

### 2. 对照裁决的强度不够

四条种子挂的三方红队满足独立 agent / 独立上下文 / 独立判据，
**但它们的简报内联了 CONTEXT.md**（无头模式下不许读文件），所以它们**知道项目历史**，
不满足词汇表「对照裁决」对假设那一处的盲验要求。

我把它如实记进了 CONTEXT.md「对照裁决」条的注，并标明这是**较弱**的一份对照。
要拿强对照，得另外安排一次**不带 CONTEXT** 的独立评审。要不要做、什么时候做，你定。

### 假墙走通了整条路，并且被数据改了定义

**注册表声明结构 → `core.book` 出候选 → probe 出分布 → 数据来定义结构。**

21 个交易日（语料里三流齐全的全部日子）× 200 只随机主板标的 = 4200 标的·日，
读入 2.46 亿行，切出 133 万个档位生命周期。收据 `4c4e199a…5028`。

| 切法 | 条/(标的·日) | |
|---|---:|---|
| 不切 | 43 | 八成与「墙」无关 |
| **按可见性切** | **3.68** | ✅ 坍缩 15,926 倍，准入通过 |
| 按「必须到过最优价」切 | 约 1.6 | ❌ **数据否定**，98% 的结构被扔掉 |

十档外占段数 79.9%，中位 **5 笔**委托堆起 **5,400 股**；十档内是几十笔堆起两万到六万股。
**两类形态完全不同，不是程度差别。** 一句话：**看不见的墙吓不到人。**

外推全语料约 **1,200 万条**。详见 `design-log/2026-09-03-假墙可见性回归.md`。

### 隐藏深度的候选生成器 + 密度回归收成一个入口

`core.book.frames`：帧间比对（展示量 → 成交 → 新增委托 → 幸存量），8 条契约测试。
`io.events` 收成一个入口 `probe(store, ledger, kind, days, ...)`，
候选表怎么生成由 `_BUILDERS` 按 kind 取——加一条新事件是加一个生成器，不是抄一遍文件。
工具 `tools/probe_walls.py` → `tools/probe_density.py`（`--kind` 选条目）。

**红队那第三个角色被量出来了**：不加「两帧之间无新增委托」，
111.7 万 → 13.9 万，**砍掉 87.5%**。也就是说八成八的「隐藏深度」其实是三秒里价格穿过该档
之后被新挂单重新撑住。红队这条不是推测，是真的。

## 五、坑（在上一份的基础上补充）

- **跑实测的时候不许碰工作区。** 我犯了一次：第一趟 21 天实测跑到一半时改了 CONTEXT.md
  与 seeds.py 的注释，收据 `source_dirty = true`，按规矩不算证据，只能删掉重跑。
  一趟 21 天要 11–12 分钟，等得起，别边跑边改。
- **「查不到 = 没有」在代码里比在纸上难认。** 这个 session 撞了两次，两次都是同一形态：
  ① `probe` 把 `res.gaps` 整个丢掉，于是「没有快照可比」与「档位不在十档内」都变成 `level = null`；
  ② 零候选的实测本来会通过准入（坍缩比是无穷大）。两处都已改成硬失败。
- **适用时段不许下推到读取层。** 日内型提取器的盘口深度必须从开盘累积，
  把窗下推给 `ReadRequest` 会裁掉集合竞价里挂下的委托，它们的撤单就找不到档位——
  实测表现是 `unlinked_cancels` 从 0.041% 跳到 1.31%。**窗约束的是产出，不是读取。**
- **词汇门禁还在飘，未修。** 这个 session 两种失败模式各撞一次：
  ① 同内容一次报 4 处冲突、重跑通过；②「判定输出不是合法 JSON」。**重跑即过**，
  但这是硬门禁，CI 可能红在上次绿过的 commit 上。
  修法：判定输出加 schema 校验 + 重试；「判定不可用」与「判定为冲突」分不同退出码。
- **红队的数字要验。** agy 估假墙 500–1500 条/(标的·日)，codex 估 100–1000，实测 43 / 3.68。
  它们的**方向**这次全对（三条要改的都真该改），**量级**全错。
