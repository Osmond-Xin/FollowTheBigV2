总判：这份设计能挡住一批显眼入口，但关键门禁、收据血缘和批量摄取语义都有可绕过口，按当前简报假设会失败。

【致命】

1. 证据：`workflow_refs` 只扫 `".github/workflows").glob("*.yml")`，且只用正则找 `tools/…\.(py|sh)`；简报却称覆盖 `workflow 引用` 与 `pyproject [project.scripts]`。  
攻击路径：新增 `.github/workflows/backdoor.yaml`，`run: python -m ftbv2.evil` 或 `python src/ftbv2/...py`；或在 `pyproject.toml [project.scripts]` 暴露 console script。入口门禁完全发现不了，CI/本地命令面被扩展。  
修正：解析 `.yml` 与 `.yaml`；用 YAML parser 读取 `jobs.*.steps.*.run`，提取 `python -m`、`python path.py`、`bash path.sh`、裸执行路径；解析 `pyproject.toml [project.scripts]`，把目标模块/函数纳入入口集合。判据：发现集合必须包含 workflow 和 project scripts 暴露的所有可执行入口。

2. 证据：gate 限制只有 `re.search(r"^\s*from ftbv2|^\s*import ftbv2", text, re.M)`。  
攻击路径：在 gate 中写 `import importlib; importlib.import_module("ftbv2...")`、`__import__("ftbv2")`、`subprocess.run(["python","-c","import ftbv2..."])`，或 shell gate 调 Python 调业务代码。`gate 不得 import ftbv2` 被绕过，被审 PR 仍可给自己当裁判。  
修正：对 Python gate 用 AST 禁止任何动态 import 到 `ftbv2`，禁止 `subprocess/os.system/runpy` 执行业务模块；对 shell gate 做 allowlist，只允许固定命令和固定工具路径。更稳的是 gate 运行在隔离环境，`PYTHONPATH` 不含被审 `src`，并用 origin/main 版本 gate 复核。

3. 证据：收据只绑定 `"tool": str(tool), "tool_sha256": sha256_file(tool)`，`inputs` 多处是路径而非内容，如 `audit_preserve`：`inputs = {"a": str(args.a), "b": str(args.b)}`；`bench_read`：`{"root": str(args.root), "ledger": ledger.sha256}`。  
攻击路径：同一路径数据被替换后复跑，receipt id 可因为 payload 相近而看似同一实验族，但无法证明输入内容；`audit` / `bench` 的数字不能复现，只能复现命令外壳。  
修正：收据接口必须绑定 `cwd`、git commit/tree hash、工具 hash、所有被调用 `src/ftbv2` 代码 tree hash、Python/依赖 lock hash、输入文件或目录 Merkle hash。判据：任何报告数字的 receipt 都必须有 `input_digest`，路径字段只能作为 locator，不能作为 identity。

4. 证据：`write_receipt` 使用前 16 位：`.lineage/receipts/<sha256 前 16 位>.json`，且 `if not path.exists(): path.write_text(...)`，已存在不校验。  
攻击路径：预置同名 receipt 文件，后续写入被静默跳过；或未来规模上来后 64-bit 截断碰撞风险成为账本污染点。  
修正：receipt id 至少全 32 或 64 hex；若文件已存在，必须读取并校验 canonical body 完全一致，否则硬失败。判据：`existing_canonical_sha256 == new_canonical_sha256`。

【严重】

1. 证据：adapter/gate 二分只看 manifest 的 `kind`；`gate` 无行数上限，且只禁 Python 文本里的直接 `ftbv2` import。  
攻击路径：把厚逻辑登记成 `gate`，规避 `adapter ≤ 120 行` 和“判据下沉 src”；或者把 adapter 拆成 shell gate 调用复杂脚本。两个月后 `tools/` 会重新长出判据孤岛。  
修正：manifest 增加 `allowed_imports` / `allowed_commands`；gate 必须是固定 allowlist 类型；所有 `tools/**/*.sh` 同样做静态检查。判据：gate 只能编排已登记 gate/adapter，不能含业务判据或任意解释器调用。

2. 证据：smoke 判据是 `Path(path).name in smoke.read_text(...)`。  
攻击路径：测试里写一行注释 `# ingest_days.py` 即通过；工具可以不可执行、参数坏、主路径坏。  
修正：smoke manifest 改成结构化：`smoke_command` 或 pytest marker；门禁执行 `pytest -k smoke --collect-only` 并检查测试中实际 `subprocess.run([...path...])`。判据：每个工具至少一次真实进程调用，断言 exit code 和关键输出。

3. 证据：`ingest_days` 对重复 day 没有显式判据，receipt outputs 用 `{o.day.isoformat(): ...}`。  
攻击路径：传入两个不同路径但同名 day 的 archive，后者覆盖前者输出 key；若 ingest 幂等或覆盖策略有缺陷，账本只剩最后一个 day 映射，无法审计重复输入。  
修正：入口处按 `day` 去重，重复 day 硬失败；receipt outputs key 改为 `archive_digest + day`。判据：`len(days) == len(set(days))`。

4. 证据：`_low_disk(path)` 会 `path.mkdir(parents=True, exist_ok=True)`。  
攻击路径：调用者传错 `--root` 或 `--scratch`，检查函数会创建目录，把路径错误伪装成可用路径；也可能在不该写的位置制造目录。  
修正：磁盘检查不得创建目标根；scratch parent 可要求已存在且 writable。判据：`root.exists() and root.is_dir()`，否则硬失败。

5. 证据：`audit_preserve.compare_preserve` 只有在 `rows / row_groups / schema_equal` 全等时才计算 `cells_differ`；否则只返回元信息，工具 `return 0`。  
攻击路径：制造 schema 或 row group 差异，比较不进入逐格 diff，CI 仍绿；消费方若只看退出码会误判通过。  
修正：`audit_preserve compare` 在任一 stream `not identical_modulo_null` 时非零退出；payload 增加 `failed: true` 和差异类型。判据：比较失败必须让门禁失败。

6. 证据：`scan_shapes` 的续跑跳过逻辑按 day 级：`if not any((day, s) in done for s in streams)`。  
攻击路径：输出 TSV 里已有某天一个 stream，就跳过整天三流，导致缺失流永远不补；观测覆盖退化但 receipt 仍写 `n_days`。  
修正：按 `(day, stream)` 粒度过滤，而不是按 day。判据：输出覆盖矩阵必须等于 `days × streams`，缺任何格子非零退出。

7. 证据：0 字节 CSV 契约只返回 `tuple(empty)`，`StreamReceipt(..., n_symbols, ...)` 不含 empty 明细；简报称 `IngestReceipt.empty_files`。  
攻击路径：某标的某流空文件被允许跳过，但 stream-level receipt 哈希没有绑定空文件列表；后续无法证明“没摄入”是因为空文件还是漏扫。  
修正：`StreamReceipt` 或顶层 `IngestReceipt` 必须绑定 `(stream, symbol, path, sha256=e3b0..., size=0)`。判据：`empty_files` 进入 canonical receipt hash。

【建议】

1. 证据：`read_floor` 用 `time.time()` 并 `round(..., 2)`。  
攻击路径：系统时间调整导致负值或抖动；四舍五入让小样本基准不可复现。  
修正：改 `time.perf_counter()`；收据记录机器信息、CPU、磁盘、冷/热缓存标记；原始秒数不 round，展示层再 round。

2. 证据：`preserve_days` 用 `p.stem.split("=")[1]`。  
攻击路径：非规范文件名、额外 `=`、坏日期会让审计工具直接异常退出，不能产出可审计失败。  
修正：复用 `parquet_relpath`/日期 parser，坏文件进入 `invalid_files` 并非零退出。

3. 证据：`workflow_refs` 读文件未用 `errors="replace"`，其他处部分使用。  
攻击路径：工作流中放非法 UTF-8，入口门禁自身崩溃，形成拒绝服务。  
修正：所有仓库文本扫描统一 `encoding="utf-8", errors="replace"`，并把 decode 异常作为违规而不是崩溃。

4. 证据：`symbol_mismatches` 对 `streams` 默认取交集：`common = set.intersection(*sets.values())`。  
攻击路径：某流完全丢失大量标的时，只报告每流相对交集的 only-in，缺少“应有全集”与严重度，容易被当作普通单边差。  
修正：输出 `per_stream_counts`、`union_size`、`missing_from`；超过阈值非零退出。

5. 证据：`_load_stream` 用 `data = path.read_bytes()`。  
攻击路径：单个异常大 CSV 会把内存打爆，批量摄取失败级联。  
修正：先 stat size，设置单文件和单 stream 上限；大文件用流式哈希和流式解析。判据：超过配置上限硬失败并记录 archive/path。

裁决：不得合并
