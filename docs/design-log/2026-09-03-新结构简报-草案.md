# 红队对象：事件注册表第一批四条结构（FollowTheBigV2，注册表 0.2.0）

## 背景：这一版是被退回重写的

上一版四条种子里，`QuoteThenWithdraw` 的切割规则是「一笔委托被挂出后被整笔撤销」。
用户判定：**每一笔撤单都成一条事件，信息密度太低，这不叫设计，这叫把数据挪到另一张表。**

诊断：把**过滤**（挑出满足某属性的单条原始记录，坍缩比 1:1，不降维）当成了**提取**
（找出多条原始记录之间的结构关系，把它们坍缩成一条）。

本次红队要验证的就是：**重写后的四条，是不是真的变成了提取。**

## 项目约束（裁决依据，不可动摇）

- 数据：A 股 Level-2 三流（orders 逐笔委托 / trades 逐笔成交 / xinqing 十档快照），
  1122 个交易日、约 3000 只主板标的、2.585 TB。全量提取一次约 15 小时，
  外置机械盘 4 IOPS，读取下界 16.9 小时。
- **事件不含判断**：提取器只回答「这里有一个这样的结构」，不回答「够不够大、算不算反常、是不是庄」。
  分位、排名、通过/不通过，一概不进事件流。判断全在因子层（秒级重跑）。
- **边界由结构触发，不由时间触发**（用户裁定，原话：庄家不掐表，是子弹打光了或者量到了）。
  不得写「隔了 T 久没动静就结段」这类规则。
- **目标密度**：事件层要把 5300 万行/天坍缩成「几万条/天」（全部标的合计），
  即约 10–30 条 / (标的·日)。信号稀少是设计目标。
- 提取参数只能是拓扑量（时间上界、笔数边、价位连续性边、离最优价的离散刻度边），
  且必须满足三条：① 维度切分（不含任何关于「该量在样本中的排名/分位/偏差」的参数）；
  ② 单调同伦（参数单调变化只让段更粗或更细，不换成另一种事件）；
  ③ 不可调出空集。
- 事件三型：区间（起止之间那东西确实存在着）/ 组（一批离散记录被圈成整体，起止只是头尾）/
  时刻（无跨度）。
- 回看范围四档：段内 / 日内 / 跨日（写得出 lookback_days）/ 周期（写不出一个数，
  且不产出事件行、只产日级参考层的列）。

## 待审对象一：四条结构的切割规则

### 1. LevelBuildThenVanish（别名：假墙）· 区间 · 日内 · orders + trades

跨行结构关系（三个角色）：
- 建墙的本方委托 · 拆墙的本方撤单 · 该档位存续期间的成交
- 不变量：同一 (标的, side, price) 上，一批委托把该档位从无堆到有，
  另一批撤单把它清回零并使该档位从盘口消失，
  **且第三个角色在整个存续期间为空集（该档位一笔没成交）**。

开段：某 (side, price) 档位在十档可见范围内从无到有被本方委托建立。
结段：该档位深度回到零并从盘口消失。

几何度量：side · price · peak_vol · n_orders（几笔堆起来）· n_cancels（几笔拆掉）·
build_ms · life_ms · teardown_ms · ticks_from_touch_at_peak。无提取参数。

### 2. RefillAfterFill（别名：冰山）· 组 · 日内 · orders + trades

跨行结构关系（三个角色）：
- 被成交耗尽的本方委托 · 耗尽它的成交 · 同价同量的补单
- 不变量：三者按时序咬合并至少重复一轮：委托 → 被成交吃完 → 同 (price, vol) 的新委托出现。
  **补单必须发生在成交之后。**

开段：某 (side, price) 上一笔委托被成交耗尽后，同 (price, vol) 的新委托出现（第一次完成「成交 → 补单」）。
「重复」的词义下限是 2 笔委托，不是阈值。
结段：出现价或量与本组不同的本方委托，或该价位被穿过。

几何度量：side · price · slice_vol · n_refills · total_filled · span_ms。无提取参数。

### 3. FillExceedsDisplayed（别名：隐藏深度）· 时刻 · 日内 · xinqing + trades

跨行结构关系（三个角色）：
- 前一帧快照在该档的展示量 · 两帧之间在该档的成交 · **后一帧快照上该档仍然存在**
- 不变量：成交量 ≥ 前一帧的展示量，**而该档位在后一帧仍然活着**。
  档位在被吃掉自身全部展示量之后还在，只能是因为它背后有没显示出来的量——幸存本身就是隐藏的证据。

（上一版写的是「成交量 ≥ 展示量，≥1 倍即记，属存在性」。审计判定 1 是个幅度、
只是被起了个「存在性」的名字，故改为以「幸存」为核心。）

几何度量：side · price · displayed_vol · executed_vol · surviving_vol。无提取参数。

### 4. VolClockBar（别名：成交量时钟）· 区间 · 跨日（lookback_days=20，读 daily_ref.volume）· trades

开段：上一根 bar 结束的那一笔成交之后的第一笔成交。
结段：本 bar 累计成交量首次跨越刻度 tick_volume。
刻度：tick_volume = daily_ref.volume 的 20 日均值 ÷ bars_per_day，**bars_per_day = 48**。
日均值取自 T−1 及以前，绝不含当日自身。

（上一版把刻度写成一句描述「daily_ref.volume 的 lookback_days 日均值」——
照它跑一天只有一根 bar，而 28 个契约测试全绿。）

几何度量：bar_index · volume · vwap · n_trades。

## 待审对象二：新增的两道结构性防线

```python

class Relation:
    roles: tuple[str, ...]      # 少于 2 个即构造失败：单行过滤只说得出一个角色
    invariant: str              # 角色之间必须成立的关系（署名字段，机器只查非空）

class Density:
    rows_per_symbol_day: float  # 必须 > 0
    collapse_ratio: float       # 必须 > 1，否则「这条提取器没有降维」
    receipt: str                # 必须非空：入库数字一律带血缘
```
