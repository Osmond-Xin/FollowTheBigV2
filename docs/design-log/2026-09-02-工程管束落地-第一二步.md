## 第一步：账本生命周期 + 语义 append-only（PR #8，已合并）

- 账本条目：`kind / status(pending|active|rejected|superseded) / superseded_by / created_at / evidence + evidence_sha256 / decision_ref + decision_sha256 / read_layer_action / note`。
  证据快照 `ledger/evidence/<id>.md` 与裁决文件 `<id>-decision.md` 分开、写一次不改、哈希绑定；读取层只看 active；补丁码来自账本 action，
  处理器集合按 AST 从 `store.HANDLED_PATCHES` 读；代码 `DefectCode` = active ∪ pending 的 code 集合。
- 门禁 `tools/check_ledger.py`：**自包含**（不 import ftbv2，被审 PR 不能给自己当裁判），CI 另用 origin/main 那一版再跑一遍；
  按 id 做结构化比较：禁删、不可变字段、作用域不可缩窄、days 只许并集、状态转移集合、替代链（允许 ≥ 2 层，终点须 live，无环）、
  新增条目只能 pending；观测批次哈希绑定且只许追加；基线 = merge-base(HEAD, origin/main)，工作区脏时为 HEAD，CI push 事件为 HEAD^，绝不自比较。
- 红队五轮（codex 每轮、opencode / agy 后两轮）：采纳 30 余条。第二轮起 opencode / agy 空输出的根因是脚本把提示词放在仓库外临时目录（plan agent 拒读）
  与 agy 无头模式任何 read_file 都自动拒且整体不输出，已修（提示词放 `.redteam/`，agy 内联 CONTEXT.md 并禁读文件）。

## 第二步：入口门禁 + 工具 + 收据 + 0 字节 CSV（PR #9）

- `tools/check_entrypoints.py`（自包含）：全仓 AST 扫 `__main__` / argparse·click·typer / shebang / 可执行位 / `*.sh` / workflow 引用，

  每个入口有真正调用它的烟雾测试（`tests/tools/test_tools_smoke.py`）。

## 明确接受的残余风险（红队命中但本阶段不修，写在这里比假装修了诚实）

1. **同一 job 注入 MINIMAX_API_KEY 运行被审 PR 的代码**（codex，两轮）：单人仓库，fork PR 默认拿不到 secret；PR 全由仓库主发起。等有第二个提交者再拆受信 workflow。
2. **门禁实现自身无 ratchet**（opencode / codex）：序列 PR 可逐步弱化 `check_ledger.py`；CODEOWNERS 在单人仓库不可用（作者不能审自己的 PR）。基线版复核挡的是「同一 PR 改坏裁判」，挡不住「多 PR 蚕食」。
3. **观测批次只记 code 不记 (stream, days) 明细**（codex）：账本 days 与观测覆盖尚未逐日绑定；`tools/scan_shapes.py` 的产物结构化后再补。
4. **引导 PR（#8）自己带 checker**：main 尚无实现时基线复核被跳过——只发生一次，已过去。
5. **V1 manifest 反查批次的 scanner 是 external 且哈希为零**：基线里既有的批次不可改；规则只对新批次生效；跨流标的差今后由 `tools/audit_preserve.py mismatch` 产出。
6. **adapter 行数上限可被 minify / 拆文件绕过；shell gate 无命令白名单**（opencode / codex）：现阶段全部 tools 由仓库主写并 review，等有第二个提交者再加 AST 体积与 shell allowlist。
7. **收据的输入摘要对 TB 级输入只取文件级 Merkle**：内容哈希 1 GB/文件级别可接受；目录级输入（root）仍以路径 + 文件集合哈希表示。

第一步 5 轮红队 + 4 次加固约 4 小时；第二步约 2 小时。门禁新增两道（账本、入口），CI 时长 +40 s。
