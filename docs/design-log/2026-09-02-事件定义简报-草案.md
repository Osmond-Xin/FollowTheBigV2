# 事件注册表与事件提取：事件到底是什么（设计简报，待三方红队）

> 用户的起点模型：「事件就是一个算式，或者说一个阈值——某个计算量大于某个值，事件就发生了」。用户自己觉得太松散，要求深化。
> 本简报把这个模型摆在 A，并给出三个更结构化的备选，请红队按方法论 / 架构 / 工程三面攻击，目标是收敛到一个能进事件注册表的定义形态。
> 术语按词汇表：事件不含判断；因子含判断且是状态机；提取参数是第三类参数；事件流版本；日界事件；缺口。

## 0. 约束（来自三份活文档，不可谈判）

1. **事件不含判断**：提取器只回答「统计上反常」，不回答「是不是庄」。判断留在因子层（秒级重跑）。
2. **提取一次约 17 小时**（RawStore 全字段读三流下界 16.9 h，2026-09-02 实测），几个月跑一次 ⇒ 写进提取器的决定被锁死在最难重跑的位置 ⇒ **宽而中性**。
3. 事件流不变量：按 (标的, 时间) 有序；每 (标的, 交易日) ≥ 1 条日界事件；安静 ≠ 缺口。
4. 提取参数（分位点、窗长、最小持续时长）属于事件注册表，进证据指纹，假设不得改；判断阈值只属于预注册。
5. 事件流版本 = 注册表版本 + 提取参数集 + 原始层数据清单 的内容寻址。
6. 三个必测数字未定：事件流体积、全量提取耗时（下界 16.9 h）、「宽而中性」的宽度。
7. 已知形状：开盘重复帧（09:30 / 13:00 两帧）、停牌心跳、6 位时间两天、枚举空值 ' ' / '' / null。

## 1. 原料：V1 里被算完就丢掉的东西

V1 每 30 秒窗算 `uq`（十档失衡均值）、`mpc`（中间价漂移 tick）、`hqa`（报单笔数）、`ac`（撤单股数），然后用「本股当日 p90」做 hi_hqa / hi_ac、
`|uq| > 0.5` 做 extreme_uq，三相位共现（Build-Up → Cancel → Sweep）判定 `is_spoof_seq / is_spoof_sweep`，**在内存里 count / sum 掉**，只有日聚合落库。
事件本身从未持久化。冰山（同 (price, vol) 递交 ≥ 10 次）、隐藏深度（rest ≥ 2×disp 的快照时点）、成交量时钟 bar 同理。

## 2. 四个备选定义

### A · 阈值触发（用户起点模型）
事件 = `f(窗口内的行) > θ` 为真的时刻。注册表条目 = 算式 + θ。
- 优点：直觉、可解释、一条注册表条目就是一行公式。
- 问题：θ 是判断，写进提取器就锁进 17 小时；改一次 θ 重跑一次；「宽而中性」被违反；θ 从哪来（V1 的 0.5 是硬编码字面量）没有答案；
  θ 对不同标的 / 不同市况不可比。

### B · 分位候选 + 全量度量（宽而中性的直接实现）
事件 = 某统计量落在**该标的自身分布**的松分位（如 p95）之外的**窗口**，但事件记录**不含通过 / 不通过**，只含度量：值、分位、持续窗数、前后窗的伴随量。
注册表条目 = 统计量定义 + 参照分布（哪天、哪个标的、多长回看）+ 松分位 + 伴随量清单。真正的阈值在因子层。
- 优点：提取只做一次「宽筛」，因子层任意收紧；度量齐全可复用；分位对标的自适应。
- 问题：参照分布若是「当日自身」= 日内前视（p90 要到收盘才知道）；候选量取决于分位松紧，仍是一个锁死的参数；「宽」的代价是体积。

### C · 切割段（segmentation）
事件 = 一段**时间区间**，由切割规则把逐笔 / 快照坍缩成段：例如「十档失衡符号持续 ≥ N 窗」「同 (price, vol) 连续递交 ≥ k 次」「主动成交连续吃穿 ≥ m 档」。
段记录：起止时间、长度、峰值、积分、段内与段后 K 窗的伴随量。注册表条目 = 切割规则（纯结构，不含幅度阈值）+ 段度量清单。
- 优点：切割规则是结构判据（持续、连续、单调），不是幅度阈值，最接近「反常」的语义；段天然有起止，因子状态机好消费；
  V1 三相位可以由因子在段序列上重建。
- 问题：切割规则本身也有参数（N、k、m）；段的定义比阈值难解释；段太多时体积不可控；「不含幅度阈值」能否做到要逐条验证。

### D · 窗口帧（没有事件，只有统计量）
不定义事件。提取器每 30 秒（或按成交量时钟）对每个标的落一行 K 个统计量（uq、mpc、hqa、ac、吃穿档、撤单距离分位、同价位重复次数……），全量落盘。
事件与因子全部在纯核上从帧计算，秒级重跑。注册表条目 = 统计量定义 + 窗长。
- 优点：把「记哪些字段」之外的一切决定都移出 17 小时位置；A / B / C 都能在帧上事后定义；三个数字只剩一个（帧表体积）。
- 问题：体积——3128 标的 × 480 窗 × 1122 天 ≈ 17 亿行 × K 列，K = 20 时 zstd 后估 30–40 GB，内置 SSD 只剩 148 GB；
  窗内的逐笔结构（如冰山的逐笔递交序列）被窗聚合抹掉，某些事件在帧上不可恢复；30 秒窗本身是一个锁死的参数。

### 组合
- **B + D**：帧全量落盘（粗粒度） + 对少数逐笔级现象（冰山递交序列、撤单前离最优价距离）做 B 式候选。
- **C + D**：帧 + 段；段的切割在帧上做（秒级，不锁死），只有逐笔级段（冰山）在提取器里切。

## 3. 参照分布的前视问题（所有备选共有）

「本股当日 p90」在盘中不可知。三种口径：当日自身（事后，日内前视，适合 T+1 信号但必须声明）；前 N 日滚动（PIT，冷启动缺口）；
全市场当日横截面（同样事后）。注册表必须把口径写成参数，因子层不得混用。
